# DramaIP v2.0.0 发布与回滚 Runbook

## 触发条件

出现 P0/P1 数据损坏、授权绕过、支付重复扣款、云审片越权、更新链路失效或签名异常时，立即停止 rollout。不要删除 v2 创建的数据库表、资产版本、Retake 候选、影响记录、订单快照或审片审计记录。

## 立即止血

1. 在平台入口停止分发 v2.0.0 更新清单，保留已发布文件和 SHA-256 供审计。
2. 关闭受影响的服务入口或 Provider 配置；云审片、智能路由和外部 Provider 可独立停止新任务。
3. 对支付问题停止新结账，但保留 webhook 幂等处理和订单查询；不得手工覆盖权益快照。
4. 对云审片安全问题撤销受影响分享，停止签发新媒体 URL，并保留最小审计记录。

## 桌面端回滚

- 数据库迁移只向前增加。回退应用二进制时使用升级前自动数据库备份验证旧版可读性，不对当前数据库执行降级 DDL。
- 用户项目包 v1–v12 仍可导入；v13 项目应保留原包，不能伪装成旧版本。需要旧客户端继续生产时，使用 v2 导出的标准媒体或受支持的旧格式副本。
- 已采用资产和历史候选不可删除。回滚只撤销新 UI/入口或停止新任务，避免破坏成本和血缘审计。

## 平台回滚

1. 回滚 Web/BFF/服务镜像到向前兼容的上一版本，数据库扩展保留。
2. Billing 保留历史 plan、订单、订阅和 `entitlements_snapshot`；旧套餐映射继续按已批准迁移规则执行。
3. Review 服务停止发布时仍应允许授权删除和到期清理；若完全隔离服务，运行对象与元数据对账后再恢复清理任务。
4. 恢复前执行权限、幂等、配额、对象校验和备份恢复 smoke。

## 恢复与复盘

修复候选必须重新生成并绑定当前 commit 的 Provider、剪辑器、安装、支付、云审片安全和备份恢复证据。再次运行全量 CI、跨版本升级测试、发布元数据生成与 `pnpm release:gate`；只有输出 `RESULT: GA READY` 才能恢复 GA rollout。
