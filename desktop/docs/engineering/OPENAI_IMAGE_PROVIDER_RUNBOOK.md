# OpenAI Image Provider Runbook（LM5-10，本地链路已完成，外部沙箱待授权）

定位范围：图片是 [产品定位](../../../docs/product/POSITIONING.md) 中可替换的生产出口，不是小说/剧本创作的前置依赖。本文保留该适配阶段的合同与沙箱边界；定位更新不构成新的外部 Provider 验收，配置、凭据和发布状态应以当前代码及工程架构复核。

Desktop 已提供图片生成设置、Keychain 凭据引用、可取消/重试的本地图片任务、谱系与成本未知态、
本地 PNG/JPEG/WebP 归档和静帧候选。它不读取环境变量，默认关闭生产开关，也不会自行创建网络请求。
因此本地链路可验收，但在账户所有者授权真实沙箱前，仍不能作为“外部生产可用”或发布 Gate 通过证据。

## 已验证的本地合同

- 使用 `POST https://api.openai.com/v1/images/generations`、`gpt-image-2`、`b64_json` 输出归档语义。
- 只有同时存在 API Key 和 `featureEnabled: true` 时适配器才允许提交。
- 文本生图路径拒绝 `file:` 参考图；参考图编辑必须使用独立、审查过的 edits 上传流程，不能偷偷上传本地素材。
- Key 只保存为 SQLite 中的 Keychain 引用；renderer 只收到 `masked:v1:*`，设置与 E2E 均验证不会返回明文。
- 任务先写入本地长任务、谱系和费用条目，再发起同步请求；成功的 `b64_json` 先归档为项目媒体，之后才创建新的静帧候选，绝不覆盖已采用候选。
- API 返回的令牌使用量只进入无凭据的谱系快照；没有可审计账单时费用继续显示“未知”，不伪造金额。
- 用户取消只停止本地等待和后续归档；同步 Images API 没有在本产品中验证的远端取消操作，费用状态保持“未知”。失败任务可从任务中心新建重试谱系。

## 授权沙箱步骤（尚未执行）

1. 账户所有者在“图片生成设置”中主动录入专用 API Key，确认系统 Keychain 可用，并仅为隔离测试配置勾选“可产生费用”。Key 不得写入 SQLite、默认参数、日志、环境文件或命令行。
2. 使用无敏感信息、已授权的角色描述和场景描述，分别提交一张角色图与一张场景图；确认本地归档文件、候选、长任务、模型/参数/usage 谱系以及成本“未知”均可追溯。
3. 从任务中心取消一次仍在等待的请求、重试一次受控失败任务；确认不会覆盖已采用候选，并记录同步请求远端费用仍未知的提示。
4. 记录测试日期、模型、账户区域/组织验证状态、限流/权限结果、账单实际费用和数据保留声明；这些证据由账户所有者保存，不写入项目正文、截图 fixture 或仓库。
5. 测试结束立即关闭该配置的生产开关。无 Key、开关关闭、组织未验证、权限/余额失败均必须保持不可提交；人工导入授权素材仍是完整离线回退路径。

官方依据：[OpenAI Image generation guide](https://developers.openai.com/api/docs/guides/image-generation) 当前将
`gpt-image-2`列为最新 GPT Image 模型，推荐单次文本生图使用 Image API 的
`/v1/images/generations`，并以 `b64_json` 归档。GPT Image 使用前可能要求组织验证；图片端点的数据保留、
区域和图片输入审查规则必须在每次正式上线前按当前官方文档复核。
