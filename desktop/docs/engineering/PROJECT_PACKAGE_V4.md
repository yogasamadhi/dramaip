# Desktop `dramaip-project-package` schema v5（兼容 v1–v4）

项目包服务 [产品定位](../../../docs/product/POSITIONING.md) 下的独立小说与改编创作，是用户确认后的内容交换边界，不是默认云同步。包中不必包含改编、分镜或媒体结果；零章节简报与小说成果不会因为缺少视频被视为不完整项目。

当前 Desktop 完整 JSON 项目包生成 schema v5，导入接受 v1–v5。所有导入都先 Preview，Commit 后才创建项目和资源，并使用幂等键防止重试造成重复数据。本文描述 Desktop；Platform 是独立产品，不由本地实现推定其客户端已支持 v5，也不新增跨产品依赖。文件名保留以兼容既有文档链接。

## v5：版本化内容与允许导出的谱系

v5 章节和资源保留实际原 ID／版本；`lineage` 只携带经严格公开契约校验的允许元数据，不能包含模型指令、候选全文、来源正文、私人引文／解释、原动作键、凭据或本地绝对路径。包的作者正文和允许交换资源是内容区，不是谱系元数据或默认外发遥测；本协议不把任意自由资源 payload 认证为已经通过同样的敏感字段过滤。

完整 JSON 的 `lineage` 区分：

- Automation 原工作流／运行／快照身份、冻结引用、原范围与纳入／排除元数据；不补最新输入，不认证模型理解或原记录历史真实性。
- Workspace 原保存作者意图版本的身份与内容／来源指纹，不含意图正文或当前头推断。
- Production 原正式成果、普通保存稿件／稳定块身份及明确镜头关联，不附原值、私人关联理由或原文引句。
- Knowledge 原保存声明、人工解释、状态转换及独立摘要的允许身份／来源，候选、失效和历史不自动升级为正式事实。
- Creative Quality 原模型／人工／逐字规则记录、位置和引文哈希；人工决定不含私有 note，不把分数、风险接受或报告采用当质量保证。

这些侧车有明确 recorded-only 范围，不是所有 owner 的全状态历史。缺 owner 显示 unavailable；损坏、重复、跨项目、额外私有字段或不能完整结束的分页拒绝导出，不返回部分记录或原诊断。独立稿件格式不因不序列化的这些 owner 侧车失败而要求完成媒体或质量报告。

v5 导入只把允许谱系存为 `importedLineageArchives` 的不受信外部只读声明，并校验原导入声明指纹。重新导出保留 A→B→C 的原外部声明，不把它们激活为本项目工作流、采用头、作者意图或授权；旧 v1–v4 缺失谱系保持缺失，不生成 v5 历史凭证。指纹核对不证明许可或外部声明真实。

## 当前导出入口与格式边界

| 入口／格式                              | 实际内容与谱系范围                                                                                                                                                                                                                       |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Workspace `json`                        | v5 完整内容交换项目包；原已保存章节／资源版本、完整只读 owner 谱系侧车和已有外部导入声明                                                                                                                                                 |
| Workspace `submission-json`、`delivery` | 兼容的 v5 工程 JSON：全部已保存章节，后者仅保留指定交付类资源；保留原工作流和外部导入声明，不收集完整 JSON 专属的四类 owner 侧车；不是正式投稿交付回执                                                                                   |
| Workspace `markdown`、`automation`      | 作者章正文和选用资源的 Markdown 资料；不序列化 `lineage` 或外部归档，不伪造谱系已附带；`automation` 为既有兼容 API                                                                                                                       |
| Workspace `script`、`storyboard`        | 章正文加实际 scripts／shots 资源的 Markdown 资料，不是 Fountain／FDX，也不等于完整项目谱系包                                                                                                                                             |
| Workspace `submission-markdown`         | 全部章正文的兼容稿件 Markdown，无资源 JSON 附录或谱系侧车；没有明确范围时不截取前十章                                                                                                                                                    |
| Delivery 稿件 `markdown`／`json`        | 用户明确确认的实际所选章节／版本、目录、权利 Gate、完整文件校验和真实 Host 保存回执；只含稿件及必要清单，不隐式收集项目候选或媒体                                                                                                        |
| Delivery 内部试制 ZIP                   | 实际采用大纲／剧本／分镜的结构化文件、`source-context.json`、`lineage.json` 和校验清单；`includeWorkflowLineage=true` 才附精确三阶段 `workflow-lineage.json`，未选择或旧包不自动升级。人工确认不是新模型输入，原回执缺失明确 unavailable |

普通桌面的“导出投稿包文档／数据”按钮走 Delivery 的明确范围／权利／回执流程，而不是旧 Workspace 投稿格式。一般内容导出是用户选择后的本地交换，不等于云上传、授权核验、文学质量认证或发行就绪。所有格式与候选状态保持独立，不因导出自动采用或修改正文。

本轮实际八种 Workspace API 的隔离 headless 探针覆盖12章、一个未采用手工意图、原段落事件的私人时间标注和五级普通生产行，逐格式核实际章节版本、正文、资源选择、侧车是否应序列化、外项目／私人声明排除与原记录不变；不冒充模型工作流、SQLite 重启或 ZIP 验证。后者分别由永久 Runtime／纯文件回归验证，原终态及范围见根 PLAN22.169。允许导出谱系按原父项已验收，完整 M4 的其余原条件仍继续收口，不认证任意自由资源 payload、语义质量或授权。

## 既有 v4 内容能力

v4 在既有简报、卷季、章节、灵感卡片和 automation 资源之外，允许 `creativeIntelligence`：

- 用户选择的抽象语料卡；
- 项目因果节点和边；
- 观众认知状态；
- 脱敏后的来源谱系。

零章节创作简报是合法包。导入前可以修改项目名和模式。网页正文、完整灵感对话、长期记忆、个人创意指纹、IP 孪生缓存、账号信息和凭据永不进入项目包。

公共条目只复制创作机制和必要的来源标识；`quoted_from` 的短引用最多 500 个 Unicode 字符，并继续标记为需要人工权利复核。IP 孪生是可重建投影，不随包传输。

2026-10-06 谱系输出保护：Knowledge 的 `exportPackageAssets` 在既有事务内核对因果来源、观众主体和 provenance 两端的必要标识；绝对本地路径、盘符路径、UNC、家目录与 `file://` 不作为可导出身份。发现时通用 JSON 工程包返回不包含该值的 409，原持久记录不改写，也不暗中生成替代身份。输出只为 `quoted_from` 保留短引用，其余关系不复制额外 `quoteExcerpt`；不透明身份、版本及实际关系保持。永久纯测试和实际 Runtime 导出／拒绝／原记录保持回归已通过，不证明所有旧元数据接口都已脱敏，也不代替人工权利复核或完整 M4 验收。

2026-09-30 导出增量：既有 Workspace `submission-json` 与 `delivery` 导出仍使用兼容包结构，未选择范围时包含全部已保存章节，不再静默截取前十章；`submission-markdown` 是题名、梗概与正文，不追加资源 JSON。schema 版本、导入协议和所有权不变。这不等于已实现 Delivery 的版本化稿件清单、范围/权利 Gate 或 Host 保存成功结果投影。
