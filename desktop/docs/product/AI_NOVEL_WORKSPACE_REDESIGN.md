# AI 小说创作工作台：定位纠偏与改进方案

方案日期：2026-09-05。下文保留整改前核查与设计依据；2026-09-06 的实现与验收范围见 [AI 核心流程执行记录](./AI_CREATION_IMPLEMENTATION_2026-09-06.md)。

> 当前口径（2026-09-30）：小说创作是重要的上游核心之一、可独立完成的一等能力，能够形成章节、完整稿件和投稿成果；不只是改编输入，也不是所有项目的必经入口。当前定位以 [产品定位](../../../docs/product/POSITIONING.md) 为准；本文其余部分保留 2026-09-05 的小说领域方案，不把整改前问题视为今日仍未修复。

本方案是全产品 AI 定位下的小说领域方案。全局入口、其他项目模式、改编、制作、审核与交付的核查和执行边界见 [Desktop 全产品 AI 核心定位审计](./AI_PRODUCT_ORIENTATION_AUDIT.md)。

本方案沿用统一交互原则：小说正文由 AI 生成，用户负责创作方向、提出要求、审阅和采用。前一版“默认专注手动写作、AI 为可选辅助”的设计假设不再适用于小说工作区。

当前验收应覆盖“本章 → 采用 → 事实记忆 → 下一章 → 稿件导出”的独立闭环。文风、视角、类型与表达目标服从作者意图，不默认要求短剧化、每章反转或媒体可生成；改编检查只有在用户选择改编目标时参与。真实模型文学质量仍需独立评价，不能从界面或模拟工作流通过推定。

## 1. 现状与问题

### 1.1 章节目录覆盖了章节标题

`packages/app/src/features/novel/NovelChapterWorkspace.tsx` 将目录按钮绝对定位在工作区的 `left-3 top-3`，章节标题则位于子编辑器的普通布局中。按钮没有占据布局空间，也没有给标题留位，因此会覆盖标题；这与原生窗口按钮无关。

目录的开闭又绑定到 `focus/context/ai` 布局模式。选择章节、切换模式会改变目录可见性，目录不能作为独立导航稳定使用。搜索快捷键只聚焦输入框，没有先确保隐藏的目录打开。

改进：目录入口进入章节上下文栏的正常布局，使用图标、明确标签与展开状态；宽屏目录进入左侧统一导航，窄屏用抽屉。切换章节保留当前目录布局；关闭抽屉后将焦点归还触发按钮。搜索快捷键先打开目录，再聚焦搜索。

### 1.2 默认布局与产品定位相反

同一文件的布局回退值为 `mode: "focus"`，界面以“专注写作 / 写作与设定 / AI 协作”组织功能，并默认隐藏 AI 操作。正文格式工具、打字机滚动、保存按钮占据显著位置，本章生成入口却在另一个布局中。

首页与项目概览仍有“手动写作不需要配置 AI”“直接开始手动写作”等文案；这些入口需要随产品主线统一调整。

改进：取消三种写作布局作为主功能选择。进入章节即展示 AI 创作工作台，正文默认承担候选稿或定稿的阅读和审阅。用户通过指令、选择方案和选段修订来控制正文。字号、行距和正文宽度归入阅读设置；常驻格式工具栏和打字机模式退出主要流程。

### 1.3 质量相关能力分散

现有能力包括项目设定、人物卡、全书及章节大纲、卷规划、章节生成、改写、润色、章节记忆、人物状态、事件、伏笔、一致性检查、诊断与修订预览。相关入口分散在章节要点、故事圣经、长篇工具和 AI 面板。

当前生成完成处理突出候选稿及字数差异；用户缺少一个把本章目标、实际引用、检查问题、修订和采用串起来的主流程。任务目录中存在某项能力，不能作为该能力已自动参与每次章节生成的证据。

### 1.4 需要优先验证的生成接线缺口

以下是当前代码路径的静态核查发现，尚未通过真实模型输出验证影响范围：

- 章节界面的 `ensureNovelConversation` 创建会话时携带项目，未携带章节；`startRun` 在发送消息时携带 `chapterId`、`chapterBaseVersion` 与 `target.wordGoal`。`plugins/agents/src/sessions/routes.ts` 的发送路径构造上下文和运行记录时读取的是会话上的 `chapter_id`，未见在该路径消费请求中的章节与字数目标。需要用 Runtime 测试验证最终模型请求中的目标对象、版本及约束。
- `plugins/agents/src/context/store.ts` 默认组装项目、当前章节、选区、故事圣经投影，以及人物、大纲、故事弧三类写作资源。该组装路径没有显式加入前章正文、章节记忆、人物状态、故事事件和伏笔资源；不能仅凭其他页面维护了这些资料，就宣称每次生成已自动读取它们。
- 自动上下文选择主要按来源种类优先级、字段路径和预算决定纳入项。需要补充与当前章节有关的时间范围、人物、情节和伏笔筛选，明确已发生事实与未来规划的区别。
- 章节 UI 依赖任务、候选稿及旧事件名称推进状态；会话发送路径完成时记录的是会话消息与运行事件。需要逐项核对从本章生成到候选创建、事件更新、预览和采用的完整链路，避免将“对话回复完成”等同于“已产生可采用的章节”。

这些问题应先于多模型评审、批量生成等增强功能处理。

## 2. 新的主流程

创意与定位 → AI 规划全书与卷纲 → 本章任务书 → 组装并校验上下文 → AI 生成 → 检查与局部修订 → 审阅采用 → 更新连续性资料 → 推进下一章。

用户可以只提供一句创意，由 AI 提出人物、设定和大纲候选；不要求先手工填写大量表单。真正需要用户决定的是作品方向、主要人物关系、关键剧情取舍和是否采用结果。

正常章节一键执行“生成并检查”。阶段进度透明展示；仅在方向不清、关键资料冲突、执行失败、预算边界或需要采用时暂停。内部多阶段执行不要求用户逐阶段点击。

## 3. 1800 × 1000 的界面组织

| 区域 | 内容与行为                                                                                                                                                |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 顶部 | 一条紧凑项目上下文栏与一条章节操作栏。显示卷、章节、当前状态和一个主要动作。项目说明横幅收为可展开说明。                                                  |
| 左侧 | 默认约 224 px，统一容纳项目导航与卷章目录；进入小说工作区时优先展开目录。支持搜索、定位当前章、待处理筛选、分页及排序。避免再叠加一条独立 260 px 章节栏。 |
| 中间 | 使用剩余宽度展示本章任务书、生成中的内容、候选正文或定稿。正文以阅读为默认交互，选段后给 AI 下达修改指令。                                                |
| 右侧 | 默认约 440 px、可调整，常驻当前章节的 AI 操作。以“本章目标 / 引用资料 / 检查与修订”组织内容；指令输入与主要动作固定在底部。                               |

窄屏将右侧操作区和目录按需放入抽屉，但“生成 / 审阅 / 修订”的主要动作仍留在章节栏。消息、正文、目录各自滚动，滚动边界不传递给整个页面。

全局助手与章节助手共享结果呈现与明确的对象上下文；章节工作区优先显示当前章助手，避免同时占据两条右栏。切换章节时不静默重绑已有对话。

## 4. 中间区域按工作状态变化

| 当前状态           | 中间区域                                     | 首要动作                   |
| ------------------ | -------------------------------------------- | -------------------------- |
| 尚未规划           | 由 AI 提出的本章任务书与缺少的关键决策       | 生成本章方案               |
| 已有规划、没有正文 | 剧情推进、出场人物、结尾目标、约束及准备情况 | 生成并检查本章             |
| 正在执行           | 真实阶段与生成内容；已采用稿可随时查看       | 停止生成                   |
| 候选已完成         | 候选正文、目标完成情况、检查问题             | 审阅采用，或先处理阻塞问题 |
| 需要修改           | 问题定位、原文证据、可执行的修订建议         | 修订所选问题               |
| 已采用             | 定稿、连续性资料更新状态、下一章建议         | 生成下一章                 |
| 上游修改           | 列出影响本章的事实与失效引用                 | 重新检查本章               |

这些是工作区派生状态，不替换原任务执行状态枚举。“已采用”“待审阅”“资料需更新”继续与执行状态分开。

## 5. AI 怎样生成更好的小说

### 5.1 用本章任务书表达目标

将现有章节要点提升为生成前的主要输入：本章承担的剧情推进、人物目标与变化、场景与事件顺序、叙事视角、情绪节奏、必须保留的事实、不能提前泄露的信息、待埋设或回收的伏笔，以及字数范围。

任务书默认由 AI 根据全书和卷纲提出，用户以修改要求和选择方案确认。钩子、爽点、反转等是按题材启用的策略，不强制每章使用同一公式。

### 5.2 保证实际上下文正确

每次执行应冻结并关联可追踪的输入：

1. 当前项目、卷、章节与采用版本；
2. 本章任务书和作品风格约束；
3. 前章结尾及适量的邻近已采用正文；
4. 更早章节的有效摘要与事件记忆；
5. 当前出场人物的状态、关系与认知范围；
6. 与本章有关的设定、待回收伏笔和剧情规划；
7. 用户本轮指令、锁定内容及选区。

资料应按相关性及预算选择。未来大纲属于计划，不是人物已经知道或故事已经发生的事实；未采用候选不能污染正式连续性资料。界面展示本轮真实纳入及遗漏的资料摘要，不能只展示固定的“已读取全部上下文”文案。

### 5.3 将检查和修订接在生成之后

- 规则检查：目标对象、版本、必需约束、字数范围、明显重复与格式完整性。
- 连续性检查：人物状态、时序、地点、能力、称谓、认知范围及已确定的设定。
- 叙事审阅：本章是否推进剧情，动机和冲突是否成立，节奏与对白是否符合预期。
- 表达审阅：解释过多、套话、重复句式、人物声音相似等有正文证据的问题。

每个问题需提供位置、证据、影响与建议动作。默认进行范围有限的局部修订，保留用户锁定内容；重写整章属于明确选择。修订后重新检查关联约束，限制自动修订轮数与预算，避免无限改稿。

AI 审阅是参考意见。不会将单一综合分、模型自评或“达到目标字数”作为作品质量合格的证明。

### 5.4 采用后形成连续写作记忆

正文采用后自动提出章节摘要、事件、人物状态和伏笔变更，并关联正式正文版本。客观提取可在用户已启用的自动策略下保存为可追踪派生资料；涉及新增设定、主角能力或剧情方向的变更保留待确认状态。

下一章的生成使用已采用事实及其有效记忆。资料更新失败或尚未完成时应明确提示，并依据正文补取必要上下文或暂停依赖步骤；不能假装已完成同步。

## 6. 持续生成与质量验收

先把单章流程打通，再提供有范围、字数与成本上限的连续生成。依赖前章情节的正文按顺序推进；候选未经采用时，后续探索属于明确的候选分支，不能混入正式故事事实。

第一阶段以一章为默认审阅单元。批量生成要能暂停、从有效检查点恢复，并在关键冲突、连续失败或预算边界停下；不把多模型同时生成作为默认方案。

质量评估使用固定小说样例、相同模型及约束，对旧流程与新流程做匿名对比，记录：

- 首次候选采用比例，以及采用前的修订轮数；
- 人物、设定和情节连续性问题及其证据；
- 用户为得到可采用正文需要补充的指令量；
- 每个已采用章节的生成耗时与实际成本；
- 长篇推进后，关键事实和伏笔是否仍被正确承接。

首先覆盖首章、续章、人物密集章、跨卷章节、上游正文修改和失败恢复；待流程稳定后，再逐步增加长篇范围。性能和质量目标以测量结果为依据，不预先承诺提升比例。

## 7. 执行优先级与验收

| 优先级 | 工作                                                                               | 验收重点                                                                            |
| ------ | ---------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| P0     | 修复章节目录重叠及焦点；核对当前章节、目标字数、上下文、候选创建和事件到达路径     | 目录不遮标题；模型请求绑定正确章与版本；回复完成能到达真实待采用结果                |
| P1     | 替换手动写作主线；精简顶部；默认展开章节 AI 区；中间按状态呈现；统一首页和概览文案 | 从项目进入即可理解下一次 AI 操作；不用切换“AI 协作”布局；无正文时不会只看到空白纸页 |
| P2     | 本章任务书、相关上下文、生成后检查、问题定位与局部修订、采用后记忆更新             | 从一句创意或已有大纲得到一章可采用正文，并能根据该章衔接下一章                      |
| P3     | 有边界的连续生成、题材策略、长期质量评估                                           | 批量执行不串章、不污染正式事实，失败后从明确边界恢复                                |

本方案仅适用于 `desktop/`，复用现有插件、引擎、Host 凭据、Preview/Commit、版本及恢复机制。新增运行输入与持久字段由所属插件管理并同步契约和生成客户端；编排由 Runtime 负责。旧布局偏好需要版本化迁移，保留章节位置、对话、草稿、候选和已采用正文，不继续自动恢复旧的手动写作默认模式。
