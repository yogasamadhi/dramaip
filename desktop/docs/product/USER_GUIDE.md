# 尽意 DramaIP Desktop v3 使用指南

尽意 DramaIP 当前是面向 AI 短剧与漫剧的本地优先 AI 编剧与 IP 改编工作台。小说创作是重要的上游核心之一、可独立完成的一等能力，分集改编和剧本开发是转化核心；作者意图、叙事质量、连续性、版本与来源贯穿两路，分镜与媒体用于试制和交付。完整口径见[产品定位](../../../docs/product/POSITIONING.md)。

先按自己的成果目标选择路径：只写小说时完成规划、本章生成/修订、审阅采用、连续性记忆、下一章和稿件导出；需要改编时再进入分集与剧本；已有剧本可跳过小说写作，进入连续性、制作检查和分镜交付。小说不必生成分镜或视频，也不默认要求增强爽点、反转或短剧感。

“导入小说或大纲 → 独立改编诊断 → 整季分集方案 → 首集剧本 → 首集分镜试制包”是 [优化执行计划](../../../docs/PLAN.md) 的目标流程，不表示这些新对象和统一入口已全部上线。下文介绍现有工作区与操作，不能用计划替代当前操作说明。

小说项目工作区保留“设定、人物、大纲、章节、故事圣经”等主要入口。输入一句故事想法即可智能补全项目设定；人物卡、全书大纲、章节大纲和卷/单元规划都有独立中文页面，采用智能结果前可以逐项核对。已有剧本入口直接打开剧本检查，不要求先创建小说。

章节页集中处理本章创作与审阅。左侧章节树支持搜索、卷/单元分组、拖拽排序、批量选择和记忆/质检状态；中间是 Tiptap 正文编辑器，可调字号、行距、正文宽度和打字机滚动。顶部显示自动保存、实时字数、字数目标、章节要点、版本记录和“智能写作”按钮。

章节右侧的“AI 创作”集中提供创作按钮。空白章节点击“生成并检查本章正文”即可开始；已有正文可以直接点击续写、改写、润色、扩写，或增强冲突、爽点、钩子、反转、悬念、短剧感和作者风格。“续写下一章”会先创建下一章，再承接上一章生成正文。补充要求可以留空，目标字数、引擎和模型收在“创作设置”中。“对话”用于聊天、讨论和会话管理，聊天草稿不会带入创作按钮。窄窗口通过“智能写作”打开右侧抽屉。

生成前会自动保存当前草稿，流式正文只用于预览。空白章节和已有正文均等待明确审阅采用，不因字数达标自动写入正式正文。可以查看段落级差异，使用行内、左右对照、最终结果编辑、逐段采用或全部采用；不满意时继续提出修订要求或放弃候选。目标字数用于指导与检查，不代表文学质量。

自动保存使用整数版本检查；编辑器版本过旧时会提示冲突，不会覆盖较新的内容。应用异常退出后会提示恢复本地草稿；每次采用智能修改前还会自动创建内容检查点，可从“版本记录”恢复。

“更多创作工具”提供章节记忆、人物状态、时间线、伏笔、一致性、创作分析和编剧室。每个工具都使用正式中文表单，智能报告需要点击“保存到项目”才会进入后续写作上下文。小说导入、自动拆章、项目包、版本记录和运行历史也集中在这里，不挤占日常写作页面。

当前桌面壳使用 48px 顶部上下文栏与可折叠左侧导航。顶部显示当前项目和工作区，可切换项目、搜索、选择外观或打开智能助手；左侧区分全局入口与当前项目入口，并标出当前页面。“项目库”是总入口，“数据洞察”与任务、设置等同属全局入口；进入项目后左侧固定为“概览／故事／改编／制作／审核交付”五项，其中“故事”直接进入长期创作工作区，“创作分析”从故事页的“创作分析工具”打开，顶部显示为“故事 / 创作分析”。顶部“AI 助手”按钮打开智能助手，打开后同一位置变为关闭按钮。窄窗口通过导航抽屉访问同一组入口。外观菜单和设置页都可选择跟随系统、浅色或深色，偏好只保存在本机；制作与审核交付工作台会随这一选择同步切换，不再在浅色模式中强制显示整块深色页面。

“项目”首页支持按标题和类型创建项目、创建示例项目以及导入项目包；其他入口按内容域提供现有工作区。所有资料都由本地 HTTP Server 保存。选择本地文件时，Renderer 只会获得短期 capability token，不会获得可提交给业务接口的绝对路径。

当前界面保留多个工作区和按需打开的智能助手抽屉；项目页已提供驾驶舱与单一推荐下一步，助手默认按当前页面提供简洁动作。它们是可恢复的生产入口，不会替代人工审核或自动把建议写入正式内容。

## M5评测与用户研究记录

维护者可在`desktop/`使用离线命令快速准备统一研究记录；它不是应用里的自动评测按钮，也不会调用模型、招募用户或上传正文：

```bash
bun scripts/run-node.mjs scripts/product-evaluation.mjs study-template
bun scripts/run-node.mjs scripts/product-evaluation.mjs user-template novel
bun scripts/run-node.mjs scripts/product-evaluation.mjs user-template adaptation
bun scripts/run-node.mjs scripts/product-evaluation.mjs user-template script
bun scripts/run-node.mjs scripts/product-evaluation.mjs study-check /absolute/path/to/local-study.json
```

使用锁定Node24.18.0运行。模板只向stdout输出，保存为本机记录后再填写；用户任务表加入统一记录的`sessions`，修改不透明参与者标签及真实角色，不填写姓名、正文、Prompt、路径或凭据。开始前取得研究同意，按原设备／版本／模型／素材预算条件记录实际任务，小说终点是连续两章与稿件，改编是诊断至内部包，直写不补小说／诊断；不要求视频。失败、放弃、辅助、未知测量、来源修改与重启恢复不能省略为成功。

协议初始draft，建议阈值不是批准。真实执行前确认并冻结协议，先用`study-check`取得该完整协议的`protocolDigest`；模型执行后才填写新evaluation v2记录的`execution.startedAt`／`finishedAt`（实际ISO UTC）、原`receiptDigest`和当时的`protocolDigest`，不从耗时或当前默认配置补造。模型早于冻结、原协议不匹配或证据缺失时不列为评测已就绪；修改阈值后不能把旧运行自动重绑为新标准。旧evaluation v1仍可读，但没有执行时间，不升级成预注册证据。

`study-check`按路径和固定配置列观察、检查6–8位角色配额与终点，并列六项M5缺证据。它只校验供给记录，时间与摘要也不是认证的时间戳或真实预注册证明；不能证明真实模型、用户身份、研究同意、账单、公开许可、已生效套餐或设备发布。即使全部供给字段齐备，M5／质量／发布仍是not-established。第22.204节当时34项离线测试；当前52项与新增完整语料缺口见根PLAN22.207。

## M5全篇语料与版本冻结

默认十份情境输入只有47–100个Unicode字符，`targetScale`是目标规模，不是实际中／长篇。现在即使旧情境记录全部评议完成，`study-check`也保留`FULL_SOURCE_CORPUS_INCOMPLETE`，不把片段评测当成全篇输入齐备。

完整作品应使用新的本机catalog v2文件，不覆盖仓库`cases.json`或旧记录。顶层保持`sourcePolicy`与`cases`，改为`schemaVersion: 2`／`status: internal-corpus`；每例保留原十个字段，另加`sourceCorpus`：

- `extent`：`complete-work`、`selected-excerpts`或`scenario`，由实际范围决定。
- `sourceScale`：`short`／`medium`／`long`／`not-established`。这是来源分类，不从目标标签推断；非未知分类须提供人工核对记录的`classificationDigest`，未知保持null。
- `characters`：实际`source`的Unicode字符数，含空白；`contentDigest`：该完整字符串UTF-8字节的SHA256。数值／摘要不符会拒绝。
- `units`：按原顺序的`{id, startOffset, endOffset}`，偏移采用UTF-16；全篇声明须从0至正文末端无漏覆盖，不允许重叠、重复ID或切开Unicode代理对。章节数量／偏移覆盖不能独立证明这确实是完整作品。

本机只读命令可统一加前缀，例如：

```bash
bun scripts/run-node.mjs scripts/product-evaluation.mjs --catalog /absolute/path/to/new-catalog.json catalog
bun scripts/run-node.mjs scripts/product-evaluation.mjs --catalog /absolute/path/to/new-catalog.json study-template
bun scripts/run-node.mjs scripts/product-evaluation.mjs --catalog /absolute/path/to/new-catalog.json study-check /absolute/path/to/new-study.json
```

`validate`／`summarize`／`compare`也使用同一前缀。新目录上限16MiB、每例正文最多200万UTF-16单位；评测／研究记录仍上限1MiB。本机来源文件允许正文，但研究记录继续只保存摘要／标签，不复制正文到结果或自动上传。命令只读且不打印来源、任务、作者意图或本机路径。

新套件须另建未运行模板、核对实际完整中／长篇作品与使用权，并在真实执行前重新确认冻结；短篇创意任务仍可使用简报，不被强制先有小说母稿。旧suite／input记录不能重绑。新目录的`protocolDigest`同时绑定完整suiteDigest和协议，不能沿用旧协议摘要；请从该目录的`study-check`读取实际值。人工分类摘要与全篇声明只是供给记录，工具不认证作者、文件真实性、文学长度标准、许可或质量；重复生成的测试填充文本不算真实中／长篇。当前未提供新真实全篇语料，M5不因接入能力而完成。

## M5调优前后结果比较

准备两份来自同一固定目录／原输入的evaluation v1或v2文件（不是整个study文件），在`desktop/`使用锁定Node24.18.0执行：

```bash
bun scripts/run-node.mjs scripts/product-evaluation.mjs compare /absolute/path/to/baseline-record.json /absolute/path/to/result-record.json
```

命令只读文件并向stdout输出，不调用模型、修改记录或自动采用调优方案。每个样例前后各一条完成记录才配对；失败、缺失、多候选与未运行保持原状态，不挑最优结果。新执行的相同输出在独立有序回执声明齐备时保留零变化，缺原执行证据不能把复制结果当新观察。两路与原前后模型配置分别列组，采用只比较已决定配对，修订／耗时不补未知；人工等级和连续性检查须同一声明盲评者，换评议者或unknown不算质量变化。

费用只对同币种、未共用结算摘要的声明逐项计算精确差值；缺账单、跨币种和共用摘要标不可比，不换汇、不汇总节省。输出包含前后原记录／summary及comparisonDigest，可供填入调优记录后人工核对；没有自动retain／revert。协议变化、时间未知／重叠或回执复用仍显示，不认证实验可比性、账单或因果效果。真实模型／用户原证据与人工决策仍需另外验收，M5／质量／发布保持not-established；22.205当时相关评测44项，当前52项见根PLAN22.207。

## M5评测附件原字节核对

在`desktop/`用锁定Node24.18.0执行：

```bash
bun scripts/run-node.mjs scripts/product-evaluation.mjs verify-evidence /absolute/path/to/evaluation.json /absolute/path/to/receipts
```

新全篇目录可在命令前加同一`--catalog /absolute/path/to/new-catalog.json`前缀。只读取指定评测记录引用的`<sha256>.receipt`文件，按原始文件字节核对候选、模型配置、执行、协议、用量、结算和人工评议的摘要；不枚举其他文件，不解析或输出附件内容，不修改记录或附件，不调用模型／网络。请提供与原声明对应的原始字节；规范化JSON摘要不会自动转换成文件摘要，不能通过改摘要或替换内容消除不符。

单文件上限32MiB、声明附件总量256MiB；符号链接、目录和超限文件不当有效附件，读取期间可检测的文件／目录变更拒绝。exit0仅表示所有已引用文件在各自读取时摘要匹配，exit2表示缺失／不完整或无附件，非法记录／目录等exit1。同一个摘要被多处引用仍是一个文件，不证明独立运行或独立收费；本次核对不是原子目录快照，也不认证模型来源、输入与运行绑定、授权、账单、真人同意或语义质量。M5／质量／发布仍为not-established。相关58项测试见根PLAN22.214。

## M5候选包只读检查

维护者在`desktop/`使用锁定Node24.18.0运行：

```bash
bun run release:inspect
bun run test:release-candidate
```

`release:inspect`默认只读`apps/desktop/dist`，可直接用`bun scripts/run-node.mjs scripts/check-release-candidate.mjs --artifacts /absolute/path/to/candidate-directory`检查另一目录。只核当前版本更新清单的安装文件size／SHA512与全字节SHA256；旧更新清单另列，调试文件不混入。旁置mac解包应用另行比较自有Runtime／Main／Renderer编译文件并只读查看签名，不能由此证明安装文件与旁置app相同或源码构建来源。

命令只输出JSON，不保存或上传，不安装、启动、更新、公证或签名。exit0是检查完成，不是发布通过，`releaseReady`始终false；三平台安装／升级／恢复保留not-run。当前实际旧alpha文件摘要有效，但旁置解包构建与本地不同且只是ad-hoc签名。真实检查与后续发布条件见[发布检查](../release/RELEASE.md#当前本地准备证据2026-10-07非发布通过)和根PLAN22.200，不能拿旧同版号包替代当前版本验收。

### 发布元数据生成

PLAN22.201修复了旧生成器把整个dist当本版的行为。`bun run release:metadata`不是只读命令：它在所有输入与最低20唯一依赖组件检查通过后，仅向新的metadata目录写四份文件。只选择当前版本安装文件、更新清单和存在的对应blockmap，不收历史包／解包app／debug，也不删除它们；已有输出目录明确拒绝，不覆盖。真实操作须先完成自己的package与发布验收，按需要指定DRAMAIP_RELEASE_ARTIFACT_DIR／DRAMAIP_RELEASE_METADATA_DIR为明确的新候选／新输出目录。

新增`bun run test:release-metadata`在临时惰性fixture验证生成、拒绝与并发保护，不安装或发行。release-inventory.json保留所选字节与三份文档摘要及releaseReady=false；SBOM只定位本Desktop已安装依赖，不证明打包依赖完整、许可、签名、公证或设备验收，不能用命令成功替代发布批准。

## 正式成果驾驶舱

首页“继续当前项目”和“项目工具 → 项目驾驶舱”使用同一正式成果证据。小说保持章节采用、当前连续性记忆与稿件保存三个 Gate，不要求改编或媒体。新小说改编项目默认六 Gate：来源与作者意图、改编诊断、独立改编策略、整季分集方案、首集剧本、首集分镜试制包；采用诊断后推荐单独比较策略，下游绑定其正式版本。已有真实旧季纲的兼容链仍保留五 Gate，旧诊断内方向不冒充独立策略。已有剧本和创意直写保持四 Gate，不补造小说、诊断或季纲。

直写首集按当前真实分集目录的实际顺序选择，不用生产树返回顺序或旧首集；原稿记录与实际 AST 文档版本分别核对。大纲、剧本、分镜和内部包须继承同一来源、意图、分集及目标时长。唯一主动作返回当前阶段、真实候选运行或内部包 ID；当前意图和来源变化后，旧成果与回执仍可查看，但不再代表当前完成。目录与完整采用历史读取冲突时显示未核验，不任选版本；直写没有媒体制作百分比。

改编 Gate 核对当前明确采用头、版本、实际范围及完整上下游引用。首集按当前已采用季纲的 `orderIndex` 选择稳定分集 ID，人工重排后不会继续推荐旧首集。候选不是正式成果，唯一推荐下一步返回实际候选或当前阶段；历史失败、旧生产目录、剧本/镜头计数不替代采用。失效显示历史版本及已知原因，先回到最早未就绪的上游核对，不改写历史内容。

分镜已采用后可直接核验内部试制包，不要求生成静帧、声音或视频。只有当前正式版本链、明确权利声明、无已知导出阻断、Host 字节数与摘要匹配的保存回执才显示“内部包已保存”；预览、取消、失败、缺回执和旧来源都不是当前交付。摘要/范围覆盖、内部保存和用户权利声明均不表示语义质量、完整授权证明、费用或发行核验通过。读取失败或采用头冲突显示未核验；系统不会任选旧记录显示完成。限定工程证据与剩余范围见执行计划第 22.22–22.24 节。

从待确认、驾驶舱或历史链接返回诊断、策略、季纲和质量报告时，显示指定对象及原运行；同页已有缓存或上一次人工选择不会替代它。对象 ID 与工作流相互冲突、未知或归属不符时明确报错，不显示最新候选代替。只有工作流链接时只取该运行产生的结果，未生成结果不会当作最新历史。另行确认新来源才开启新基准；历史选择与人工重排保存都更新具体对象链接，正式采用仍须明确确认。

已采用或已放弃高层摘要的精确返回是只读版本复核，不显示另一份摘要的生成工作台；要另做摘要，请点击“返回分层摘要工作台（另行确认来源）”。待采用摘要继续通过原工作流审阅，查看不自动生成、采用或扩大原冻结范围。实际费用和权利未知不补零，也不因已采用或保存成功自动表示核验通过。

侧栏进入改编、制作和审核时沿用本项目的实际对象位置；打开项目工具不会清空这个选择。正式单集使用其实际分集／剧本记录进入资源页，叙事稳定分集键与实际生产记录不混用。页面先核对完整父级，指定对象找不到、跨项目或引用冲突时保留错误，不替换成最近项目或第一集。普通资源页以当前对象摘要为主，多级选择器在“切换项目或制作对象（高级）”中展开；切换分集会清除旧分集的子级。浏览不启动模型、不采用内容，也不自动确认费用或权利。

通过明确章节链接打开小说时，页面核对实际项目与章节归属。章节缺失、属于其他项目、参数重复／为空，或路径项目与参数冲突时，不显示上次正文或自动打开首章；请从错误页明确返回项目库再选。切换项目时等待核对，迟到的旧读取不会改换当前正文。未指定章节的普通目录仍可恢复上次本章；本机未保存草稿不因错误链接被清空，小说稿件可独立完成，无需进入短剧改编或媒体制作。

## 从首页开始项目

首页先询问“你现在手中有什么素材？”，再确认“写小说”或“开发剧本”。生产简报中的平台、集数、画幅等字段服务改编目标，不是衡量小说成果的标准。目标确认的位置和已选目标会随草稿恢复；文件预览与权利确认须重新进行，草稿不会自动恢复授权。其他创作模式在“其他创作模板”中。

首页的三个入口都会保存一份可编辑的生产简报：创建路径、内容形态、目标受众与平台、单集时长、计划集数、画幅和视觉方向。它们不会要求先选择智能引擎、任务、模型或服务商。

- **导入小说或大纲**：在创建项目之前先选择文件，核对预览和使用权，再创建并导入。选择写小说时保留已有章节与末章位置，不追加空的第一章，不要求建立改编；取消预览不会创建项目或写入内容。选择改编目标后，可以采用正式作者意图并进入独立改编诊断；整季方案及后续完整转化链路仍按执行计划实施。
- **从创意开始**：选择小说或剧本目标，保存故事构思和简报。小说以规划和章节为主线；选择剧本目标直接进入“从创意到分集剧本”，只建立分集目录与空剧本草稿，不创建小说母稿、人物占位或假季纲。补充本集目标后点击“生成并检查本集剧本”，审阅采用后才成为正式正文；未配置模型时仍可保存与恢复项目及要求。
- **导入已有剧本**：可粘贴剧本文本，明确确认使用权后直接保存为首集生产域剧本。选择“开发剧本 · 单季短剧”时，也可在创建前预览 Fountain／FDX 或结构化剧本 JSON，核对完整内容、格式损失和两项声明后创建；JSON 保留文件中的全部分集与实际场景资料，不缩成首集。导入后打开实际原稿检查，不创建小说母稿、章节或人物占位资料。粘贴按 Fountain 识别剧本块，非标准排版须人工核对；原文保留。其他目标的旧导入协议与小说入口保持独立，不把本次持久初始化覆盖范围扩大到它们。

生产简报会随项目包导出和导入。旧项目没有这份简报时仍可打开和再次导出，不会被自动补写或修改。

已有剧本页会带入项目、分集和剧本，父级选择器收在“切换项目或分集（高级）”中；无需再选择一次父级即可开始规则审查或切换到场景。规则报告不能证明文学质量或必然可制作。再次打开零章节的剧本项目会恢复真实剧本；旧项目的小说章节和旧路由不删除。初始化失败时保留项目和已写入资料，重试只补缺失对象；与已保存版本不同的粘贴草稿不会自动覆盖。

原创剧本同样恢复真实分集和本集创作要求。原始剧本工作区仍可从空稿复用既有稳定块候选/修订工作流，冻结已经明确采用的正式作者意图版本；该兼容稿件不自动升级为新正式单集成果。需要正式大纲、标准剧本、分镜与内部交付时，可另行进入下方“已有剧本与创意直写的独立正式单集链”。目录、空稿或规则报告存在，都不代表这些成果已经完成。

## 人物、大纲与故事设定的独立规划

小说的“人物”“大纲 → 全书大纲／章节大纲／卷与单元”，以及“创作分析”的故事与视觉设定，先显示“本轮规划来源确认”。规划不要求先有正文，不创建空章，也不会附加旧记忆或旧规划。还没有正文时，页面自动按“不使用正文”确认；已有正文时，预选全部有正文的章节（12 章以内同时预选完整原文作为表达），但仍须点击“确认本轮规划范围与表达”后才会使用。

明确选择“不使用正文”时，只依据项目简报与正式作者意图规划；也可以选择局部章节，或当前全部非空正文目录。范围确认不等于表达确认：对所选章节另选完整原文、精确已采用章节摘要、实际原文段落，或来源仍有效的高层冻结范围摘要。每章须被实际表达覆盖，高层摘要的全部原覆盖须处于范围内；空章不是已读，摘要／片段不是全文阅读或文学质量通过。

更改范围会清空本轮表达选择。点击“确认本轮规划范围与表达”后，才可“生成并检查”；确认本身不运行模型、不采用，也不是隐私或预算批准。生成前重新核对实际来源、当前版本和完整首次提示预算，禁止外发、来源缺失或超预算时，不新增上下文记录、任务或模型调用，不静默裁剪或替换为最新摘要。目录读取失败时不能启动新规划，原运行仍可按自己的冻结输入查看或处理。

候选只在明确“采用”后成为正式资料，不修改小说正文。运行中的“引用资料”列出实际覆盖、未纳入数量、逐章表达、高层原冻结身份与预算估算；usage／费用未报告时为未知。失败重试与待确认精确返回保持原请求、来源快照和当时的作者意图，不因编辑区新勾选或重启换源；正文、简报、意图或所选高层采用头变化后，旧候选不能换源采用。局部范围不会因未选目录增长而扩大，完整目录变化须重新确认。已采用派生规划再次引用仍继承原文和中间记录的禁止外发策略。

未启动的范围／表达选择不承诺重启恢复，也不会自动恢复确认；已创建运行的冻结证据独立保留。“旧方案与生成记录”仍是兼容入口，不把历史运行补写成此独立来源协议。当前验收终态与完整认知／因果、其他操作、语义质量的剩余范围见执行计划第 22.67 节。

## 人工认知与因果声明（限定规则推演）

“创作分析 → 认知与因果声明”按实际项目保存手工节点、关系和观众／人物的认知声明。页内表单不打开系统弹窗；人工确认默认不勾选，未确认节点仅为候选，不进入声明快照。确认关系的两端须已人工确认；非“未知”的认知状态须填证据说明。人工 confirmed 和证据说明只记录你的判断，不证明小说原文位置、因果语义、文学质量或授权。

先点击“明确创建新声明快照”，核对冻结节点、关系和认知，再明确勾选理解声明边界，才能基于这个原快照创建规则推演。两次动作独立；不自动读取正文、调用模型、采用或改写故事。当前检查是图规则和假设中的节点标题命中，没有语义结论、模型概率或质量通过保证，也不属于完整认知索引。

新快照的“原冻结规则定位”显示实际声明范围、待复核问题、建议及原 node／edge／cognition ID 与版本；展开“查看原冻结记录与版本”可读本快照的作者说明，不换最新。起点导致／使之可能的终点按起点→终点，起点依赖终点按终点→起点；揭示只揭示终点，不证明揭示时点。循环可能是有意闭环，认知回退可能有失忆等解释，未建揭示关系也不证明原文泄露；只需人工核对，不自动评定解释是否充分、改稿或采用。无提示仅表示本规则集未发现结构线索，不是质量通过。旧快照无新版定位时保留历史文本，不在读取时升级；要用新规则须核对后另行明确创建快照。实际范围与验收见 PLAN 第 22.73 节。

原快照和推演的返回链接保留项目、快照和推演 ID，后台重启后只读恢复原记录，不新建或换用最新结果；审阅勾选不恢复。新声明使旧快照失效时，原图和原推演仍作为历史保留，但不能据旧快照创建新推演。外项目、错配 ID 或读取失败会拒绝使用；每次进入重查，错误优先于旧缓存，不把失败当作“零节点”或“无风险”。未提交表单和假设不承诺跨项目／重启恢复。

通用 AI 上下文默认不外发人工图。只有在上下文预览显式选择时，才可纳入当前人工确认的手工节点／关系，标为非原文核验；候选和任意伪造章节来源不加入。单个节点／关系的禁止发送策略仍可阻断整图 always 选择。

“从实际原文或精确采用资料创建声明”可明确选择小说来源或直接剧本来源。小说路径先选择一个实际章节及其段落／精确采用资料，填写作者的声明解释，再“仅保存正式来源候选”。不默认选段落、不生成模型结果，也不直接写入正文或因果图。资料的原文引文能定位，仍不代表模型解释正确。

直接剧本路径不要求小说：在“声明来源类型”选择“直接剧本已保存块”，明确选择实际剧本和有文字的原块，再填写作者解释。只读取已保存的文档，不使用可能初始化文档的编辑器读取；缺文档、重复块 ID、损坏内容或来源回执无法核对时拒绝，不重解析或替换来源。目录每页二十项，可显式翻页；所有块默认不选中，未选块不会混入候选。审阅保留实际 script／document ID、两种版本、原块 ID／顺序／类型和完整所选文字。若原块保存了位置标注则原样显示，否则明确缺失；标注不证明编辑后仍对应原文件行号。

候选审阅显示原章节或剧本／文档版本、冻结来源、原文引文，以及实际字符范围或保存块身份／顺序；采用资料另显示资料与原采用运行 ID。核对来源和审阅解释是两项独立勾选，之后才能“明确采用该原声明”。采用只创建一个独立声明节点，新快照仍须另行创建；该节点是你的来源绑定解释，不是语义已证明的事实。原声明链接保存 projectId／storyDeclarationId，重启只读恢复原 ID，审阅勾选不恢复。放弃仅限未处理候选；页内最近二十项历史不自动选最新，更早项仍可用原链接恢复。

原正文或采用资料变化后保留旧证据并显示 stale，不自动改绑。旧候选不能采用，失效节点及相关关系／认知不进入新快照；原快照保留但不能继续创建新推演。读取失败时不使用旧缓存；可点击“重读实际来源与原声明”。请求丢失响应后，保持同一页、同一输入重试会使用原请求键，不重复创建；离开后未提交表单不承诺恢复。

这类来源声明同样默认不外发。显式选择其上下文项只发送作者声明及来源身份／位置，不隐式发送引文、完整原文或原资料解释；原章节、所选段落、中间资料和节点的禁止策略仍可阻断。直接剧本声明还保留实际记录、文档、所选块和真实采用回执中的上游禁发依赖；复制 sourceWorkflowId 不算采用证据。这里的 current 只表示本声明精确选择仍可核对，不证明改编剧本的上游语义仍正确；来源绑定不能视为整个认知索引或语义质量已经完成。

“给关系或认知单独绑定实际来源”另建关系／认知候选，不会为了引用原文先创建一个多余节点。明确选择小说段落／精确采用资料或已保存剧本块，再选择实际已确认节点与原版本，填写作者解释，并区分“作者认为来源明示”和“作者推断”。关系连接两个不同节点，置信值只是作者估计，不是校准概率；认知主体可以是实际角色节点或明确观众组，故事顺序也是作者声明，不自动换算成章节或时间位置。所有原文和节点均不默认选中。

保存只建立候选，不入正式图。审阅同时保留实际原文锚点和节点版本；核对来源与审阅解释／不确定性后，才能明确采用一个独立关系或认知记录。原 projectId／storyAssertionId 可重启只读恢复，审阅勾选不恢复，历史按二十项分页且不自动选最新。关系本身的原文变化时，即使两端节点没变，旧关系也退出新快照，原声明与原快照历史保留；来源不可读时拒绝采用、新快照和新外发，不复用旧缓存。

相同起点／关系类型／终点或同一认知主体／对象／故事顺序已有实际记录时，新写入或候选采用会明确冲突，不覆盖原记录或擅自选新状态；正式来源候选仍未处理，可按原 ID 审阅或明确放弃。当前不承诺自动合并、替换或撤回已采用声明，不能把重复创建当作修改原记录。

全局“待确认”已纳入这些来源节点、关系和认知候选；无需先运行模型，也可按项目筛选。来源仍当前的未处理候选在“待确认”，原来源变化或无法核对的候选在“需要处理”；已采用的实际声明来源失效也在这里复核，当前已采用及已放弃的声明保留在历史中，不反复要求采用。点击“返回对应对象”打开原项目、原声明 ID，不用最新候选替代；原文与解释仍须分别审阅，重启不恢复勾选。列表只显示名称、版本与来源提示数量，不展开冻结正文或原错误详情，打开列表不会写入故事、调用模型或采用声明。

列表会读取全部实际分页，某个来源后页失败、归属或分页身份无法核对时，该来源整组不显示为已读全；其他完整读取的领域可显示，但分类计数为“未核全”。项目读取失败时隐藏旧缓存中的对象入口，仍保留当前链接项目，不回退为全部项目或“没有待处理项”；点击“刷新状态”重新核对。这里的来源状态是本地身份核对，不是文学质量或作者解释已被证明。当前工程和后台验证范围见 PLAN 第 22.74 节。

这类关系／认知同样默认不外发；显式引用只发送作者解释与来源身份／hash／位置，不发送冻结引文或端点正文，并继承自己原文、源节点原文／中间资料、节点及实际关系／认知的禁止路径。不能通过显式包含手工图绕过来源关系的禁发。失败后同页同输入重试保留原动作键，明确成功后再次创建属于新动作；离开后的未提交表单不承诺恢复。工程范围和实际验收见 PLAN 第 22.72 节，不能以作者审阅或规则推演证明文学／改编质量。

已独立采用的来源节点、关系和认知现在可以在原记录的“来源声明撤回与替换”中明确处理。`adopted` 和原绑定版本保留历史采用事实，当前是否生效以生命周期的“生效／已撤回／已替换”为准；不会把撤回写成放弃候选或删除旧证据。填写理由并另行勾选已核对原记录退役影响，才可撤回；即使旧来源目前不可读，也要核对实际原图记录和版本，不能覆盖已改动记录。

替换前须先独立保存一个同项目、同类型的新来源候选。在原已采用记录处输入这个候选的精确 ID，点击“读取并审阅此新候选”，逐项核对新原文位置、节点版本与作者解释，再分别勾选新来源、新解释及旧记录退役影响，明确“替换并独立采用”。不默认挑最近候选，不复用其它已占用关系／认知位置。新候选、原记录退役、理由和回执一次提交；失败不会只完成其中一半。新实际 ID 与原 ID 不同，已有关系／认知、旧快照和原稿不自动重连或改写；需要另行审阅其它受影响声明。已替换的原记录不能再次换源，可以通过精确按钮打开所指定的新记录；新记录也有自己的生命周期。

后台重启可恢复原采用、撤回／替换历史与指定新记录，不恢复新审阅勾选或未提交表单。读取失败隐藏新候选旧缓存；同页同输入失败重试保留原请求键，若实际已提交也可重读原 ID 核对结果。回执重放只读原结果并投影当前生命周期，不能重新激活旧内容。退役记录退出当前图／新快照和外发上下文，不解绑降级成手工事实；新来源仍默认禁止外发并完整继承自己的来源／节点／采用回执禁止链。全局待确认不再把已撤回／已替换的旧绑定当成当前失效正式来源反复展示；新候选或新生效声明仍单独核对。工程和后台验收以 PLAN 第 22.75 节实际终态为准，不是文学质量或发行验证。

## 正式作者意图

系列长篇和单季项目的“项目工具 → 作者意图”可单独保存作品主题、情绪承诺、目标受众、必须保留、允许改变、必须避免、结局约束及叙事声音与风格。结局可暂不决定，各类约束每条单独一行；小说不被要求短剧化或加入机械反转。

“带入旧项目字段（待确认）”只原样带入受众、情感核心和风格，不把旧自由文本标题解析成主题，也不会自动采用。填写后点击“保存意图候选并预览差异”，在八字段对照中核对当前正式版本与指定候选，再明确“确认采用此作者意图”。取消确认只关闭窗口；候选仍待确认。可从当前正式版本创建新候选，不原地编辑或覆盖历史版本。

项目设定或当前采用头在候选保存后变化时，旧候选显示来源过期并进入待确认中心的“需要处理”，不能直接采用；可以核对后建立新候选，或明确放弃旧候选。浏览核对不改历史状态，实际采用冲突才记录冲突。放弃不会改作者原稿或删除已采用意图，新的明确采用也不会自动改写章节、剧本或触发生成。

保存后的候选、当前采用版本和历史可在重启后恢复；待确认的“返回对应对象”打开指定版本，不用最新候选替代，也不显示其他项目的意图正文。作者手工填写、旧字段整理和 AI 意图建议保持不同来源；独立诊断、季纲及单集操作引用的是明确采用的正式版本，而不是任何待确认建议。

“AI 辅助提出作者意图”先读取本项目可用来源。可以不选条目，仅用已保存简报，也可以明确选择完整章节或已有剧本；未选前文不会自动发送，不声明已读全书。已有剧本读取实际保存的原文或 Fountain／FDX 稳定块，文档尚未存在时不自动创建。核对列表后点击“确认 AI 意图来源”，再填写要求并点击“生成并检查作者意图建议”才运行模型；确认来源本身不发送模型，也不是采用。

生成经结构与模型检查，必要时至多一次受控修订／复检，完整八字段候选保存后点击“比较并确认此 AI 意图候选”，核对与当前正式版本的差异、实际来源及运行身份，再单独“确认采用此作者意图”或放弃。模型推测不代表作者真实思想，结构检查不证明语义质量；来源不完整、隐私禁止或完整提示超预算时在任务／快照分配与模型调用前拒绝，不裁剪或补原文。原稿、其他项目和已采用历史保持不变，通用创作提交不能代替这次确认。

已创建 AI 工作流的指定链接与待确认返回保留原项目版本、当时的正式意图头、所选来源版本／摘要和原快照。失败重试、继续检查或重启不会自动改用最新材料；原稿、项目简报或当前正式意图改变时旧候选不能覆盖，需要重新明确确认来源后创建新运行。来源重新读取只是更新可选列表，不重绑旧工作流；未开始的来源勾选不承诺重启恢复，手工八字段草稿按下文独立保存。实际 usage／费用仍以真实运行和结算回执为准，未知不是零。

八字段编辑区现在按项目保存本机 UI 草稿，部分输入和换行也保留。当前本机应用数据和存储正常时，离开工作台或重启后恢复原输入、项目版本及原采用基准；不自动换成最新来源，不创建候选或调用模型，也不恢复任何采用／权利同意。项目或正式意图后来变化会提示来源已变化，须明确“刷新来源与状态”并重新核对。损坏／未知格式草稿不自动删除或覆盖；存储失败／已发现其他窗口改动如实提示，当前内存输入仍保留，但不能声称已保存。这只是本机编辑恢复，不是跨设备同步、数据库版本或跨进程事务锁。

“清空本地编辑草稿”须单独确认，只删除此项目的本机编辑记录；取消不清空，其他项目、已保存候选、正式意图、章节和剧本不变。草稿保存在当前应用的本机数据中，不应把清空应用数据或更换 profile 当成可恢复保证。正式候选仍需点击“保存意图候选并预览差异”，正式意图仍需另行明确采用。

旧兼容 `episode`／剧本修订／审片复检／镜头提示操作不再默认取前三章。空章节选择仅依据本轮冻结的项目简报与生产对象，不证明已读原著；明确选择的章节最多 100 项，缺失、跨项目、重复及超限选择拒绝，不截成前几项。明确章节被隐私或预算排除时，在启动前拒绝，不补其他章或外发被禁止内容；重试原失败工作流保留其原快照，不偷偷重绑新章。需要新正式诊断／整季／单集结果时，继续使用相应独立工作台，而非将兼容合并包冒称新流程完成。

新的小说人物/大纲/故事弧、章节创作、既有剧本创作、独立诊断、季纲与其单集大纲/剧本会读取或继承正式意图，冻结八字段和采用版本。创作面板“引用资料”显示“作者意图 · vN（冻结版本）”；检查、局部修订、复检及重启重试不会偷偷换成新意图。未采用的意图候选不进入模型。意图是创作约束，不是已经发生的故事事实；已采用章节与事实记忆仍须核对。独立诊断及其下游须先有明确采用的正式意图；小说和既有剧本创作仍允许明确记录“尚无正式意图”。

创作开始时没有正式意图也会明确记录。此后首次采用或替换意图，相关旧候选在采用时会冲突，原正文不变；请按新版本开启新的创作，重试旧运行仍使用旧冻结资料。已经采用的正文和历史不会自动重写。历史候选没有意图绑定时，只有项目仍无正式意图才保留原兼容采用路径，不能事后补成“已经使用新意图”。

如果上下文策略禁止发送 `/author-intents/current`，或正式意图无法完整纳入上下文预算，创作会在引擎调用前报错；不会覆盖隐私策略，也不会静默忽略正式约束。可以核对策略、精简下一版意图后明确采用，再开启新创作。通用 Agent 对话、事实记忆提取等其他操作不因本次接入而被视为已使用正式意图。

## 独立改编策略

已采用来源有效的诊断后，可以进入“项目工具 → 独立策略”。点击“确认独立策略来源”只核对当时的诊断版本及策略头，不调用模型；再点击“生成并检查独立改编策略”才运行。完整继承诊断已经明确阅读的表达和正式意图，不另选原著、不补未读章节。生成和检查后比较 2–3 个保留／合并／删减／重排／重构动作不同的选项；没有默认勾选，制作风险和未知费用不等于报价，结构检查不证明文学质量。

选定一个后点击“采用此独立策略”，再确认采用；取消不改变正式方向，也不自动生成季纲。可明确放弃指定候选；历史版本、原稿和当前其他成果仍保留。待确认及历史链接精确恢复本次运行和候选，重启或失败重试不换成最新来源。生成期间原著／意图／诊断变更、另一候选先采用或已处理原运行，会阻止旧候选覆盖；请重新确认后创建新版本，不修改已采用选项。

独立策略采用后，整季方案须明确确认其 ID／版本／选项，后续大纲、标准剧本、分镜和内部 ZIP 沿用同一引用。旧诊断内的选项仍用于明确选择的兼容季纲，不冒称独立策略；不能在新策略失效时偷偷退回旧选项。独立小说、已有剧本和创意直写不被强制走此流程；未启动前的来源确认不承诺重启恢复，已创建运行会恢复原请求。当前验证见根 PLAN 第 22.55–22.56 节。

### 旧 episode 的显式兼容入口

改编工作区先提供“正式进度与推荐下一步”和“独立单集开发”。原先一次生成剧本／场景／分镜的 episode 工作台收在“打开旧 episode 兼容路径”，默认折叠；个人小剧场与旧试制计划也明确标识兼容，展开不调用模型。旧候选和回执没有删除或自动迁移，仍须明确采用，不能当作新的独立大纲／标准剧本／分镜正式结果。

旧任务／待确认显示兼容标签并返回原工作流；指定 workflowId 的深链接按原目标与快照恢复，不被较新候选替换。项目归属错误、项目不存在或尚未核验时保留原链接并明确提示，不自动换成最近项目；请核对正确链接，不据替代对象继续采用。

## 改编诊断与策略比较

单季短剧或系列长篇项目的“项目工具 → 改编诊断”提供独立诊断工作台。先核对并采用正式作者意图，再选择实际提供给模型的非空章节，设置短剧/漫剧、目标集数和单集秒数，确认来源使用与改编权利声明，点击“确认本轮来源与版本”。声明不等于系统已核验授权证明。

默认是所选章节的局部诊断，不会暗取前三章或假定读过全书。全书诊断须明确选择全部非空章节；“选择全部非空章节”只是选择动作，仍须确认。保存的范围固定章节版本、目录指纹、正式意图和此前采用的诊断头。更改选项不会自动重绑旧范围，生成新候选前须再次确认；已确认范围可重启恢复，但未确认的勾选编辑不保证恢复。

默认使用所选章节完整原文。也可以开启“诊断使用明确混合表达”，展开“诊断实际表达”，按确认范围另行选择完整原文、当前精确采用的章节摘要、实际原文段落或来源仍有效的已采用高层摘要。范围与表达分别确认，不自动勾选原文、不借用小说续写或质量报告的选择。高层摘要必须完整处于确认范围，不能裁切部分摘要；目录增长后只能使用仍有效的原冻结范围，不扩展到新章。

点击“生成并检查改编诊断”后，系统经过生成、检查和必要的一轮受控修订/复检，形成独立候选。候选分别显示确认范围和逐章实际表达、未覆盖章节、主题、情绪承诺、主线、人物弧、关系和带逐字引文的问题证据。摘要引文只核对实际摘要，段落引文只核对所选片段；同时标明真实来源 ID/版本/字段位置，不能引用未提供原文或元数据。完整表达与引用声明不证明模型理解原著、文学质量或商业效果。

缺少完整所选表达、隐私排除或完整首轮提示（含要求、格式及引用）超硬预算时，生成前无写入预检阻断：不新增上下文预览／快照、任务或运行，不调用模型，不补正文或裁剪摘要。高层摘要和派生诊断继承完整原章节、中间记录及祖先的禁止外发限制，最上层 always 不能绕过。读取本地索引不会自动改变本轮输入；更改来源须重新明确确认。

新主流程点击“采用诊断，下一步独立策略”，明确确认后只采用叙事证据和结论，不先选择旧策略，不自动写入原稿或下游。随后在独立策略工作台比较并采用一个正式方案。诊断内原有 2–3 个建议保留在“旧诊断内策略（兼容路径）”；只有明确展开、选择一个并点击“采用选定策略与诊断”才沿旧路径采用，不创建独立策略版本。没有默认选择，已采用诊断不能追加或原地更换旧选项。

所选章节、正式意图或竞争采用头变化会使旧候选失效；全书诊断还核对新增/移除的非空章节。局部诊断不因未选章节正文变化而失效，但不会据此扩大其覆盖。读取来源状态不改历史状态或时间；实际采用发生冲突时才记录冲突。可以明确放弃待确认或冲突候选，已采用诊断和作者新稿保留。待确认中心将过期候选列入“需要处理”，返回指定诊断与工作流，不跳到最新候选。

候选、当前采用头、唯一策略、冻结来源和历史可在重启后恢复；重试旧失败运行仍使用旧快照，只有新运行才能绑定新版本。制作费用在诊断中仅为风险判断，不是报价；受控接口未提供 usage 时也不能计算真实 token 或费用。独立诊断采用不等于整季方案或试制包已经完成；只写小说或从已有剧本开始的项目不被强制经过此阶段。

## 整季分集方案与人工顺序版本

新小说改编项目采用独立策略后，从驾驶舱推荐或“项目工具 → 整季方案”进入；只有采用诊断而无有效独立策略时不能确认生成基准。明确选择旧诊断内策略的项目另保留“兼容：从诊断内策略继续整季方案”入口。确认本轮来源有效的诊断、实际正式策略版本及当前季纲头；继承原正式意图、章节与实际表达、集数和时长，局部不扩大为全书，混合表达不补整章原文。改变范围、表达、意图或目标须建立并采用新诊断；只改变独立策略须另行生成并明确采用新策略版本，然后重新确认季纲基准，不静默改绑旧运行。

生成并检查后，候选显示主题、主冲突、情绪承诺、每集推进、人物关系变化、伏笔、预计场景/角色数与制作风险；混合季纲另列继承的逐章实际表达和高层原冻结身份。覆盖来自每集实际章节 ID/版本引用，仅代表方案引用的原章节身份，不证明摘要所覆盖的全文已读；范围内未使用章节必须明确说明删减，范围外章节不计为已覆盖。全部实际表达、采用诊断/策略或意图被隐私策略/预算排除，或完整首轮提示超硬预算时，无写入预检在上下文记录、任务与模型调用前阻断。结构通过和模型审阅不证明文学质量、商业效果或实际制作费用。

可以上移/下移完整分集顺序，点击“保存重排为新候选”并确认，生成独立新版本；旧内容、稳定分集标识和来源保持。未保存顺序只是界面草稿，不保证重启恢复。保存后仍须“采用这个整季方案”并明确确认；旧版本保留，重排不调用模型、不自动改剧本或生成媒体。当前正式方案也能创建新的人工顺序候选，不能原地改变采用版本。

模型候选与人工重排候选各自出现在待确认中心，并返回指定季纲 ID/workflow。来源、诊断、意图或当前季纲改变后，旧候选进入“需要处理”，不能采用或重排，但可以明确放弃；只读核对不改变历史内容和状态。已保存候选、当前正式头、来源快照与幂等回执重启恢复，失败重试沿用旧冻结基准，新运行才读取新头。已采用季纲不等于首集剧本、分镜包或授权证明已经完成；小说独立写作与已有剧本入口不被要求经过该流程。

## 从正式季纲开发单集大纲与标准剧本

小说诊断改编路径可以从当前采用季纲的“继续单集大纲与标准剧本”，或“项目工具 → 单集开发”进入。分集目录按实际采用顺序显示；人工重排后默认首集使用重排后的稳定标识，不按旧序号另造一集。

先准备已批准 Story Bible。当前新链路仅把 Knowledge 的设定工作流经作者明确“采用”后写入的 `story-bible` 记录视为已批准设定；历史通用设定、导入整理和待确认变更不自动算正式批准。工作台缺少批准设定时提供 Story Bible 候选创作与审阅，不自动采用。这个边界不代表其他入口必须改编小说。

选择本集与“单集大纲”，点击“确认本轮单集基准”，再生成并检查。候选显示 logline、目标/冲突/转折/集尾、按序场景目标、人物、动作节拍、因果、预计时长和实际章节映射版本。所有本集映射章节须有场景对应，场景和节拍标识唯一、预计时长合计匹配季纲；映射不证明全文已读。点击“采用”后仍须明确确认，才成为独立大纲版本；这一步不创建剧本、场景、分镜或媒体对象。

单集开发的“单集实际表达确认”分别显示本集映射章节数与实际输入范围。选择“继承正式季纲的表达”会完整继承季纲已确认的原文／章节摘要／段落／高层原冻结范围，可能包含其他分集上下文；不裁掉跨集摘要的一部分或改成整章原文。也可明确改为“本集独立重选实际表达”，从原正式季纲范围选真实原文、精确采用摘要或实际段落，须覆盖本集全部映射；高层摘要仍按完整范围选择，未选章节不自动补入。改选后须重新确认基准，读取失败隐藏旧选择并禁启动。正式大纲采用后，标准剧本与分镜精确继承该大纲的模式／原选择，不再换源；正式历史显示“实际冻结输入表达”，不能把章节映射当成模型只收到这些章节。限定工程验收见 PLAN 第 22.79 节，不证明语义无影响或发行通过。

本路径不把章节记忆或高层摘要视为已批准 Story Bible／视觉资产依据。完整源与中间记录的禁止策略、任何所选表达缺失或完整首轮预算超限，都在新增上下文、任务与模型调用前拒绝。历史未使用混合表达的季纲仍保留原本集完整原文路径；旧确认不会自动升级或重绑新版季纲，须明确重新确认。第 22.30 节记录本增量及验证范围，完整语义质量与 M4 仍未完成。

大纲正式采用后切换“标准剧本”，重新确认当前大纲与剧本基准，再生成并检查。候选提供完整 Fountain、稳定 UUID 剧本块及大纲场景到连续块组的完整映射；结构检查拒绝正文与块不一致、重复块、重叠/遗漏映射及无动作/对白的场景。明确采用后 Production 写入实际 `scripts` 与原生 `screenplay_documents`，可从“打开实际剧本与导出”继续现有编辑/导出。每次新采用创建独立剧本，不覆盖旧稿或顺带生成 scenes/shots/媒体。

来源、诊断/唯一策略、季纲、意图、已批准 Story Bible 集合、大纲头或当前剧本编辑版本变化，会阻止旧候选采用。正式历史只读显示失效原因，不自动修改历史内容；直接编辑剧本也会使旧正式快照不再代表当前正文。要生成下一版，按实际正文版本重新确认基准；作者旧稿和旧稳定块仍保留。已批准设定新增也属于集合变化，不会静默追加到旧快照。

已确认基准、工作流/候选、正式结果、采用头与稳定块可重启恢复；失败重试沿用旧冻结季纲/意图/Story Bible/实际表达，只有新运行读取新头。待确认精确返回实际分集与工作流，恢复原运行基准，不自动换到最新候选；旧候选仍可查看或放弃，不因来源失效而自动删除。正式引用被 privacy `never`、摘要策略或预算裁剪时，模型/新任务调用前阻断，不绕过策略把正文嵌入 Prompt。

### 从正式剧本生成单集分镜包

标准剧本明确采用且来源有效后，在同一工作台切换“分镜包”，重新确认当前大纲、正式剧本、实际 AST 编辑版本与已有分镜头。生成候选提供逐场镜头、稳定剧本块映射、视觉资产需求、构图/机位/运动、时长、声音、正负 Prompt、对白字幕、成本风险和外部依赖。展开来源可核对稳定块；字幕只能引用正式对白，风险是模型建议，不是价格报价。

结构检查要求场景顺序及完整块组与正式剧本一致，镜头覆盖所有块、不能跨场，镜头时长合计匹配正式场景。资产须引用实际已批准 Story Bible；字幕逐字对应真实对白块，时码在对应镜头内。模型检查和受控修订沿用同一冻结来源；结构通过不等于叙事、权利或专业制作验收。

候选阶段不写入场景或镜头。点击“采用”并再次“明确采用”后才建立实际 `scenes / shots`，并保留正式分镜快照、来源、采用版本和恢复记录。可用“打开实际场景与分镜”进入既有编辑工具；这一步不生成静帧、声音或视频，不授权费用，也不自动锁定视觉资产。每次新采用追加独立场景/镜头，不覆盖旧分镜或人工修改。

当前剧本换头、AST 编辑、上游来源或批准设定变化会阻止旧分镜候选采用；已采用场景/镜头被编辑或删除后，旧快照显示失效但保持历史内容。候选生成后对上一版分镜的人工修改也会阻止旧采用，新运行才能绑定新基准。重启恢复与失败重试保持原冻结内容，不能把新剧本静默追加到旧运行。

上文来源规则适用于小说诊断改编路径；原创与已有剧本可通过下一节独立进入正式单集，不被要求制造小说或诊断。其余素材格式的完整入口验收、段落级谱系与语义质量门仍待完成。正式分镜方案本身不等于已交付，内部试制包须另经下方预览和实际保存。结构检查和受控接口不证明文学质量、真实费用、制作可行性或 GA；来源目录的细粒度影响尚未完成，季纲全局失效可能影响整条当前小说改编单集链。

### 确认实际人工修订为新的正式剧本

在“单集开发”的当前正式标准剧本中，打开“审阅与确认人工修订”。这里读取实际稳定块文档，可以修改标题或各块文字，保留块 ID／类型／顺序；“保存实际人工正文”只保存实际文档，不正式采用、不改旧正式快照或现有分镜。未保存编辑不保证重启恢复，请先明确保存。其他编辑入口改变结构时，不自动猜测新的场景关系。

保存后核对完整实际正文及连续场景映射，再点击“预览实际人工修订正式版本”。仅原场景标题 ID 和顺序均可核全时复用映射；新增／删减标题等未知结构须先重新审阅大纲与映射，不自动绑定。预览冻结实际文档／脚本记录版本、正文、标题、场景映射和原正式来源；不调用模型、不创建生成工作流。作者意图、故事来源、批准设定或大纲已失效时，不能仅重新确认正文来解除来源门。

逐项确认已审阅全部冻结正文、场景映射以及仍遵循原作者意图与来源，才可再次明确采用。采用追加标为人工确认的正式快照，复用同一实际剧本／文档而不改实际正文；旧正式版本、旧分镜和旧交付包保留并按真实来源显示失效。语义正确性是作者声明，未获独立验证；此动作不重做分镜或生成媒体。

预览及采用／撤回回执持久化，可在本集人工确认历史恢复；“待确认”通过无正文摘要返回指定预览，不换最新候选，重启不继承三个勾选。正文再次变化、竞争正式头变化或上游失效均阻止旧预览采用，仍可明确撤回预览，已保存实际正文不被撤回。人工正式剧本可以进入整包分镜开发，也可在下节的固定结构范围内明确选择局部重做；不会在确认剧本时自动重做。

新内部包的 `source-context.json`／`creation-records.json` 分开人工确认与模型生成：保留实际确认回执，继承依据明确标为原确认基础，不声称是本次新模型输入；没有伪造工作流、运行或模型费用，不推定其他历史运行费用为零。逐次工程和后台证据见 PLAN 第 22.34 节。

### 明确选中镜头的局部重做

在“项目工具 → 单集开发 → 分镜包”中，已有正式分镜会显示“明确选择局部重做镜头”。逐一勾选要替换的镜头，再“确认本轮单集基准”；该动作只保存实际镜头身份、版本和正式来源，不调用模型或生成媒体。不选镜头仍走原有整包生成，不会自动猜选范围。

若实际剧本已修改，先在标准剧本中明确确认新的人工正式版本。局部重做只接受原版本到当前同一实际剧本的完整人工确认链；场景映射／稳定来源块不变，所有机械关联受影响镜头都须选中。来源、作者意图、批准设定、实际记录或结构未核全时会被阻止，不自动换源、重建镜头或覆盖作者新稿。

明确生成后，审阅“选中镜头局部候选”的动作、构图、机位、运镜、声音、正负提示、字幕与局部风险；模型只输出选中镜头 patch，不生成一整包再忽略其他部分。当前范围固定镜头顺序、时长、来源块和既有资产；全局视觉方向／资产／外部依赖以及未选镜头原样继承。结构、时长或资产改动须整包复核，未选镜头不等于语义安全承诺。

“采用”后仍有单独确认对话框。提交再次核对冻结来源／采用头／真实记录版本，在本机合并检查完整块覆盖和实际对白；选中镜头及其场景汇总原地升级版本，未选镜头和未选场景的身份、正文、版本保留。旧正式分镜快照不重建；旧试制包继续读原冻结字节，仍须按当前正式链重新预览与保存。

Media owner 只标记关联旧静帧／视频／音频素材、包含受影响镜头或素材的旧音轨及动态分镜待复核，保留文件与历史记录，不删除、不取消付费任务或自动再次调用服务商。失效候选不能直接重新采用，也不能成为新视频／动态分镜的有效素材。生成中的媒体绑定实际镜头版本，完成时版本变化的结果保留待复核；历史未绑定版本不补造证明。动态分镜／渲染的整集指纹门仍保守保留，不宣称已实现所有轨道的语义局部更新。完整原故事表达影响、任意结构重做及真实模型质量／费用验收仍未完成；逐次证据见 PLAN 第 22.35 节。

### 生成等待期间改动镜头

图片与绑定镜头的语音生成，在请求发出时记录实际镜头版本；视频异步任务将该版本持久保存，重启后的查询与本地归档仍使用原版本，不偷换成当前稿。等待服务商返回或归档期间修改镜头，晚到的素材会保留，并在记录中标记失效／待复核，不能直接采用旧静帧或视频。以新版本明确发起的新请求可以形成新的候选，不会由旧任务自动再生成；来源复核入口见下节，逐轨来源和归档视频完整审阅仍须继续。

视频预检回执只确认镜头、服务商、已采用静帧、锁定资产和生成参数，不把回执哈希自身当成输入。添加该回执不会误判为来源变化；真正改镜头、提示词或费用确认仍须重新预检。重复同一提交键或重启查询不应重复提交服务商任务或归档；历史任务缺少实际版本绑定时保留待复核，不补造“当前有效”证明。受控异步 Runtime／迁移证据见 PLAN 第 22.36 节，不代表已验证真实服务商质量、真实视频文件探测或费用。

### 音轨来源版本与明确时间线装配

“制作 → 音频”另存草案时，系统固定每个片段的真实镜头、素材、音色及其样本／人物版本，并检查实际项目／分集归属。界面显示逐片段来源版本；采用会再次核对当前真实来源，旧版本或跨项目不能靠改元数据通过。历史音轨没有实际冻结证明时显示未核验，不在升级或读取时补造；保留旧轨并明确新建当前版本。

“来源版本一致”只是机械核对，不等于已试听、音色授权、字幕语义或成片质量通过。手工文本轨可以保存与采用，但不冒充可播放音频；已采用轨后来源变仍保留历史采用状态，并显示过期／原因，不算当前有效版本。

“时间线与输出 → 审查自动编排”只列出当前有效采用轨，并显示被排除的旧轨。试听和核对来源／字幕后明确选择轨，再采用编排；只选中的对白／旁白产生字幕。预览后源变或时间线版本改变会拒绝旧确认，须重新审查；重复同次确认不重复写入。人工移动、裁切、音量和锁定片段保留，旧装配音频／字幕有固定来源；来源过期或历史片段缺失证明时，导出／渲染拒绝，不自动换最新音轨或删除人工片段。新音轨修订见下一节；人工时间线换源／移除须另行明确审查，不能用版本核对或新草稿采用代替它。

### 人工音轨修订预览、确认与另行采用

在“制作 → 音频 → 本分集音轨版本”打开指定轨的“审查并修订此音轨”。原轨可以是当前轨，也可以是需重新核对来源的旧轨；编辑基准保持打开时的真实版本，不静默换最新版本。编辑候选的名称、类型、逐片段文本、镜头 ID、实际音频素材／音色、起点与时长，可新增片段或从候选移除旧片段。候选至少保留一个片段；删除只影响候选，不删除原轨、原素材或时间线。

“冻结音轨修订预览”固定完整原轨与候选、新旧片段唯一映射、明确删除／新增清单及候选当下真实来源版本。预览阶段没有新音轨，也不调用模型。左右比较实际文本、引用和时间；安全内嵌音频只有仍与冻结素材版本一致时才显示播放器，旧版本文件不可读时明确提示，不用当前内容顶替旧音频。没有素材的片段只是文本草稿，不表示生成、试听或质量通过。没有可用播放器不等于已审阅；请另行审阅实际文件，否则保留或放弃预览。

分别勾选实际内容／差异、片段映射、作者意图／权利限制三项声明，再“确认修订并生成新草稿”。确认保存声明和时间，创建一个有独立 ID、来源证明和原轨映射的新草稿；不会自动采用、改旧轨或改时间线。原轨版本、候选实际来源或另一份确认头改变，会拒绝旧预览；旧预览可明确放弃。修订历史只读打开不产生确认；重启继续同一冻结预览，但勾选项必须重新确认。修订及当前确认头的新草稿已并入全局待确认中心，精确入口见下文。

在版本列表中单独“采用此音轨”才确立新的替换采用头。旧轨保持原片段／版本／历史采用状态并显示替换轨 ID，不再作为当前有效轨；旧竞争草稿不能覆盖后来确认的候选。已装配的人工音频／字幕仍引用原轨，来源门可能继续阻止导出。请在下述入口明确审查并换源／移除，不要把“采用新轨”理解为时间线已经完成更新。完整归档音频／视频、声音权利／费用与正式 Media Gate 仍按 PLAN 推进。

### 人工时间线片段换源与明确移除

在“制作 → 时间线与输出 → 审查人工片段来源”打开实际音轨引用清单。每个音频／字幕片段默认“保留，不处理”；音频和字幕分别选择，分割后片段也分别处理。替换列表只接受本分集当前有效、已采用的实际片段，并沿不可编辑的修订映射逐级对应旧来源；不按名称／文本猜对应关系。新增而无旧映射的片段、不同项目／分集或类型、过期／未核验轨都不能替代。新源不能容纳原源偏移＋时长时无候选，不会自动裁短；可以明确裁切后重新审查，或移除不再使用的旧引用。

明确换源保留时间线片段 ID、轨道、起点、时长、源偏移、名称、音量、淡入淡出／降音和锁定状态，标记为人工编辑以保护后续装配。字幕默认保留原文本，只有单独选择“明确使用新源文本”才改用新文本／名称。音频新素材须实际版本一致，只能接入受限 opaque mediaRef；不能接入时显示未关联，不沿用旧媒体引用。明确移除必须填写理由，只移除选中的时间线引用，不删除 Media 原轨／素材或磁盘文件。

“冻结人工换源差异预览”保存完整原／后时间线、逐项人工参数、原来源与新轨实际文本／来源版本／修订回执链及移除理由，尚不改时间线。核对所有实际内容、人工／锁定／分割参数以及作者意图／字幕／权利限制，重新勾选三项声明后“确认所选人工片段换源／移除”。来源或 Timeline 已变化会拒绝旧确认，不自动换新基准；可以明确放弃或清空未确认选择再核对。缺可读音频只能看到文本及来源快照，不能当作已试听；请另行核对实际文件，否则保留或放弃。

历史可恢复同一预览，重启／选择不同预览／状态或来源变化不恢复勾选声明。确认同事务保存声明时间、时间线、撤销栈、回执和身份事件；同次重放不重复编辑。撤销恢复原片段与引用，回执仍是历史，不把过期原轨重新证明为当前；来源门仍会阻止旧导出／渲染，重做恢复换源后的引用。待确认预览已并入全局待确认中心，不证明试听、声音授权、费用或正式 Media Gate 完成。

### 实际媒体加载与播放

来源复核、音轨修订／时间线换源的新旧片段对照，以及资产中心提供“加载实际媒体”。资产中心先点“打开本地预览”核对真实记录版本，再明确加载文件；展示用“资产版本”标签不是文件版本。音轨只读取其冻结的实际素材版本，旧版本不能以当前文件替代；没有素材的纯文本片段仍不代表已生成音频。

支持安全内嵌的 PNG／JPEG／WebP／GIF、常见音频和 MP4／WebM，以及本项目持久 Media 归档记录授权的同类文件；实际浏览器能否解码以加载结果为准，不承诺所有编码。归档元数据不等于已读取文件。每次加载沿 SDK → Runtime → Host 核对实际项目、版本、文件大小及完整 SHA-256，成功读完后才展示 Blob 原生控件。当前单文件最多 128 MiB，需要等待完整读取；更大或不支持的文件请另行审阅，不提供前几字节冒充全文件的预览。

图像解码和音视频可播放状态分别显示；文件缺失／变化、版本过期、取消或浏览器无法解码都会明确失败，不显示其他项目、最新素材或外部链接来替代。点击“停止并释放媒体”、切换对象或离开页面会取消读取并释放 Blob。重启后仍需明确重新加载，不依赖上一会话的文件映射、不自动播放或恢复勾选声明。已载入的是当次冻结的字节副本；归档元数据轮询不是持续磁盘重哈希，需再加载核对当前文件。

播放器不会确认、采用、重生成或调用模型，也不会勾选任何审阅声明。逐片段试听是原文件试听，不是时间线偏移／音量／字幕的同步成片预览；仍须人工核对内容、作者意图、声音／人物授权和费用。限定验证、失败记录及完整命令终态见根 PLAN 第 22.42 节，正式 Media Gate 仍未完成。

资产中心已打开的记录版本变化后，可以在同一张卡片点击“重新核对本地记录”。开始核对即释放旧文件，成功后显示当前实际版本，仍需另点“加载实际媒体”；失败、错误身份或项目切换后的晚到结果不会恢复旧播放器。该只读操作不自动把旧播放器改为最新字节，不采用、确认或修改记录。音轨对照必须保留旧冻结版本，不能通过资产中心核对来替换旧来源。

### 时间线实际同步预览

在“制作 → 多轨时间线”明确点击“加载实际同步预览”。系统先核对实际项目、时间线版本、手工链接的冻结素材版本或已装配音轨的原始来源，再完整读取全部所需文件并解码，核对源偏移与裁切是否超过真实文件时长。准备成功后才启用“播放”。没有实际文件的示例仍可定位、编辑、撤销与导出受控引用，但不能用空时钟冒充媒体播放。

同一预览时钟控制原生视频／音频、静帧和字幕；按项目帧率解释开始、时长、分割后的源偏移，播放到片段边界时等待下一实际片段启动。暂停或拖动播放头会暂停全部声音和画面，明确再播放时从新位置继续。轨道静音／独奏控制声音，视频静音不停止画面；Web Audio 的增益节点应用片段音量、淡入淡出及对白／旁白期间的配乐 ducking，不把大于 1 的音量悄悄夹成 1。“静音预览”只影响本次试听，不修改轨道或作者记录。

加载后、每次开始播放前和定时轮询都会核对 owner 来源元数据。缺失、历史没有冻结版本、错误项目／类型、来源过期、解码／设备失败、原生播放拒绝或超时都会停止并释放预览，不使用最新文件替代；重新载入才重新核对完整文件字节。历史手工链接须明确重新链接，已装配音轨须经逐片段换源确认，不能用手工链接绕过修订谱系。

当前单文件最多 128 MiB，本次预览合计 256 MiB、最多 16 个不同文件／64 个片段；不支持重叠视频合成，超限会明确拒绝整个预览。设备播放并非逐帧精确的正式渲染，预览不会生成成片、自动确认质量／权利／费用或取得授权。完整 Media Gate、较大文件、重叠合成及真实内容质量仍按根 PLAN 推进；本项实施及逐次证据见第 22.43 节。

### 创作启动与真实中断

“生成本章”“续写下一章”等明确操作启动后，引擎健康核对和会话建立可能仍在等待。工作流已保存本次运行身份不代表引擎记录已经完成写入；直接启动和后台推进现在共用同一工作流的防重入控制，等待中的合法启动不会被另一轮推进误判为“引擎提交在保存前中断”。这不是忽略真正的失败，也不使用假候选或自动重发来掩盖中断。

真实引擎失败、缺失持久运行或重启中断仍明确保留在任务中；已创建的续章目标、原候选和冻结来源保留，重放原请求不会再建另一章。需要恢复时从对应任务检查错误并明确重试，不自动换模型、改变来源或采用候选；生成完成后仍须审阅采用，旧正文不因这次并发修复被覆盖。实际延迟回归、首次失败与完整验收见根 PLAN 第 22.46 节。

### 实验混音渲染的当前边界

时间线同步预览与 NLE 文件交付都不会自动生成 MP4。独立的本地实验渲染处理非重叠 MP4 视频片段，使用固定 1080×1920／25 fps／48 kHz 双声道配置。新混音策略已接通视频内嵌声音与对白、旁白、配乐、音效的精确归档，按保存的音量、淡入／淡出和降配乐控制合成 AAC。轨道静音／独奏排除声音但不删除视频画面，片段间视频空隙为黑色；无实际可听来源时才生成已知静音，不把坏源、短源或解码失败改成静音成功。字幕必须明确选择不烧录，或在已验证签名字体能力可用时选择原字体烧录完整原字幕；SRT 仍独立导出，不自动烧录。

音量与淡入／淡出按原控制值相乘；重叠对白／旁白期间，配乐只按保存的降配乐系数降低一次，零音量但仍活跃的对白／旁白也保留该语义。音源须实际探流并完整解码覆盖冻结区间，只支持能明确核验的 mono／stereo 流；格式、流选择或时钟不确定时拒绝，不猜声道或选第一条流。最终混音峰值超过 1 明确失败为 AUDIO_MIX_PEAK_EXCEEDED，不自动归一化、削波或调整作者音量。AAC 是有损编码，不声称逐样本等同预览、专业母带或完整 Media Gate 通过。

当前新任务还完整解码每个唯一视频源，按原有理时钟逐帧检查并核对所有裁切区间，不以格式总时长、平均帧率或声明帧数替代。最终成片须实际是唯一 H.264 yuv420p 视频与 AAC 48 kHz 双声道，视频每帧都能解码、尺寸和字节数符合配置、从零开始严格为 25 fps、完整帧数与时间线一致，AAC 另做完整解码；全部通过才归档。视频解码或帧证明失败为 VIDEO_FRAME_PROOF_INVALID，不能靠丢坏帧、补帧或重置时钟变成成功。当前明确预算为单视频源最多 24 小时、宽高各不超过 8192 且像素数不超过 16777216，单次完整解码／成片最多 100 万帧；这些是拒绝边界，不是已完成上限压力测试。历史成功回执不自动升级为当前逐帧核验或当前文件完好的证明。

实验渲染必须使用已核验签名的本地 sidecar；新混音能力另须实际核验过滤器、采样时钟／增益、AAC／x264 编码器和原视频时钟的全帧解码能力，不能仅以“工具存在”或旧静音能力通过预检。创建前冻结实际时间线版本和 Media owner 的唯一有效存档；只有元数据预检通过不表示文件已经校验。任务执行时完整读取并核对所有参与来源的字节，使用任务私有副本，源文件变化、缺失或历史无证明明确失败，不改用最新素材。输出记录保留原冻结时间线谱系，重试须仍是同一来源与输出策略；取消和重启中断不自动恢复任务或发布旧结果。旧静音任务保留原语义，不能借原键或重试换成混音，需要重新预检并创建独立新任务。

在“制作 → 成片渲染”的“本地实验混音渲染”面板，先核对实际项目和分集，再点击“核对实际来源与渲染能力”读取当前能力。字幕输出策略初始为“尚未选择”，不是默许不烧录；必须明确选择“明确不烧录字幕”，或选择“烧录原字幕与指定字体”并另行选原字体。字体目录不自动选第一项；目录没有可核验能力时烧录选项不可用，不搜索或替换系统字体。选择后重新核对实际来源；只有完整策略／原字体及现有时间线、来源、本地能力预检通过，并另行勾选本次声明，才能创建。换策略或字体会清掉预检和同意，重载不恢复勾选。打开面板和“重新核对渲染历史”只读全部实际 SQL 分页，不创建时间线；没有既有时间线时，请到“多轨时间线”明确编辑和保存。

烧录使用未 muted 的原字幕完整文字和原整数半开帧区间，不受音频 solo 排除；原字体以 ID、packVersion 和完整 SHA 固定。字体许可／来源仅为签名声明，不是合法授权核验。固定字号、边距与安全区，缺字、重叠、不可见、超区、字体或原来源变化会明确失败，不缩字、折行、截断、换字体或静默变成不烧录；复杂语言排版及实际观感需另行审阅。预检只是元数据核对，任务还会核完整私有字节及实际绘制、源与成片解码，不能把预检当作成片成功。

历史必须明确选择指定任务，不默认选最新。已知活动任务读取实际状态；离开页面只取消读取，不取消持久任务。取消须明确点击对应任务的取消按钮；失败／已取消／中断任务只有仍符合原时间线版本、来源指纹、字幕策略／原字体及渲染器／sidecar版本，重新预检与确认后才能明确重试。选择不烧录不能重试原烧录任务，原字体不可用也不能替换成同名或更新字体；改变输出策略需独立新预检／新任务。历史没有字幕证明不会被补成新选择。

请求已发出但回复未知时，本机保留原项目／分集／时间线、原键和严格输入，不保存正文、媒体字节或同意声明。刷新或重启先只读查找原请求回执，不重发、不另建任务。未查到时可继续“查找原请求回执”，或明确选择“重发原键与原输入”；重发前仍先查回执，只复用原绑定，不能用新预检悄悄替换。损坏或错项目的本地绑定会阻止创建／恢复，不能据此当作没有请求。项目／分集切换取消旧读取，不显示另一个作用域的恢复内容。

成功任务保存实际 Media 输出记录的项目、ID 与冻结 version，通过“加载实际媒体”完整核对文件后才播放；不自动加载、自动播放或勾选审阅。“停止并释放媒体”释放 Blob 和读取资源。输出记录后来被编辑时，旧任务播放器明确拒绝冻结版本，不使用最新内容代替；历史缺输出记录身份证明也不自动补造。实验成片入口在渲染面板，而不是资产中心的 visual-assets 列表。隔离后台签名与三秒测试画面不代表发行签名、公证、真实内容质量、人物／声音权利或费用通过。

NLE 清单的 owner 存档元数据、明确全字节核验与本地复制包见下方[NLE 交付与媒体核验](#nle-交付与媒体核验)。新混音／全帧门见根 PLAN 22.190–22.191，字幕字体／Host／Core／SDK见22.192–22.194，普通明确选择与真实后台Core→Host→Media字幕流程的有限验收见22.195：原键恢复、同策略重试、指定帧字幕像素、omit无字幕与坏字体重启拒绝均已验证。隔离本机测试字体与签名不是发行字体包或授权，不能据此推断普通安装已有烧录能力；必须核对本机实际 capability。完整当前版本 normal、发行字体授权、完整 Media Gate／格式规模及其余 A09 条件仍待，不把有限通过当作父项验收或发行就绪。旧静音版本证据保留在 22.44–22.47。

### 原素材交付证据

资产中心先明确“打开本地预览／重新核对本地记录”，成功读到指定素材的实际版本后，会显示“原素材交付证据”。成片渲染历史打开指定成功任务后，同样针对原冻结输出记录提供入口，不默认改用当前最新素材。点击“核对原素材交付证据”才读取一次指定项目／素材／版本的元数据；打开页面、刷新和重启都不自动核对，也不会加载文件、调用模型、确认费用或写权利声明。

结果分别显示原来源状态、单一有效存档的ID／大小／SHA、可编辑权利／费用／服务声明，以及该原版本最近已记录的一次完整读取凭证。存档SHA是元数据；历史凭证只证明记录时间的完整读取，即使与当前存档元数据相同，也不证明文件现在完好、能解码或已经审阅。没有存档、来源变化／未核验、已声明权利受限／撤回／过期或服务不可用会明确列出；没有负面标记也不表示通过。质量未核验、合法授权未核验、实际结算未知、当前文件未读取始终独立保留，不能靠填“已核验／已知／可用”解除。

重新核对先隐藏旧结果；“停止证据读取”停止等待并清除结果，迟到回复不恢复。离开对象、换版本、刷新或重启也不展示旧缓存。指定版本已经改变、历史凭证损坏或原归属不可核对时显示失败，不换最新版本或较旧的成功凭证。需要读取当前实际文件时，另行明确点击“加载实际媒体”；这也不等于审片、合法授权或正式发行。

本入口是单一素材元数据，不是整个时间线／NLE包的全部来源、字体、审片决定、授权或账单验收。实际后台原旅程的取消／重载、等长篡改后的历史保留与新读取失败、换版本拒绝已按根PLAN22.196有限验证；完整Media Gate、格式规模与整组normal继续。独立小说稿件和无媒体改编不要求完成可选媒体流程。

### 平台提交资料的原版本保护

“审核交付 → 导出与发布 → 平台交付”只归档提交资料元数据，不保存平台账号、登录或代投。它不生成、附加或读取成片／字幕文件，也不等于完整Media Gate；成片质量、合法授权、实际结算、当前文件和目标平台当前规格均未核验。通用交付档案是内部参考，不是平台最新要求。独立小说稿件和无媒体改编不必完成这条可选制作流程。

请明确选择交付档案和创意候选，不会默认选择第一项或最近采用项。手工保存为新候选只保存原标题、简介、标签与可选封面引用，不代表采用。点击“采用此候选”会按你读到的原候选版本／完整记录SHA、项目／改编版本及原采用头修订核对；竞争采用或内容变化会拒绝，不代选最新候选。旧记录的“已采用”文字没有新的有效采用头时仍未核验，须重新明确决定；旧正文和历史不改写。

核对人工字段后再运行预检。服务端检查分集实际父级、候选同项目／同改编和精确采用版本；引用封面时须有同项目的有效图片归档且无来源／负面声明阻断。人工勾选只是用户声明，不能解除质量、法律、结算或当前文件未知。预期MP4／SRT／JSON文件名只是清单，不表示文件已生成、附加或检查。

预检显示原候选标题、记录版本、采用修订和原SHA。创建归档使用这份预检的原输入与指纹，不临时重新取当前选择；项目、改编、分集、候选、采用头或所选封面证据变化时拒绝。换档案、换候选或离开对象会废弃旧预检／迟到结果并清空新勾选，归档历史冻结原资料而不是随当前内容改变。

采用／归档回复未知时保留原请求，只允许“只读核对原请求”或明确“用原键重发原请求”。刷新或重启只GET原键，不自动POST或改键。待核记录保存原身份、版本／指纹和原请求里的人工声明值，不保存文案、账号、凭据或文件路径，也不将原声明恢复成当前勾选。结果仍未知时保留；只有明确写入拒绝并只读确认原键404后，才可由你点击“保留原拒绝记录，重新核对来源”，原拒绝记录仍留在本机，不沿用旧预检。坏本机原请求记录不被静默丢弃，目录读取失败也不显示成空历史。

历史导出只读取原项目／归档。新归档携带原标题、简介、标签、档案和来源身份／版本／指纹的冻结预检；旧ID清单仍可读取／导出，但标明legacy-submission-metadata-unverified，不补造原标题、采用证明或新预检。导出两者都不代表当前文件完整或发行批准。真实Core／SQLite、普通后台资料旅程、原混音／字幕回归与末版工程门的限定证据见根PLAN22.197；完整Media Gate及其他A09条件继续。

### 整包审片的原版本保护

在“审核交付 → 预览与修订”中，“整包审片的原版本保护”提供新的明确入口。先点击“核对本轮整包来源”，核对原时间线ID／版本／指纹与轨道、镜头和素材范围，再勾选本轮声明并创建此版本审片包。读取不创建包、读取文件、调用模型或批准审片；没有原镜头不能创建。旧“创建离线审片包”保留兼容，但旧包没有完整NLE来源绑定，其历史批准不认证当前交付。

新包冻结完整NLE轨道、片段、原字面字幕、静音／solo／增益／淡入淡出／ducking、原素材和单一存档元数据，以及原改编／分集／剧本／场景／镜头和素材owner身份、版本与内容指纹。快照是编辑与来源元数据，不是读取过当前文件或已经审阅实际成片／字体。当前简化剪辑预览不代替完整原包；原来不支持的投影帧率明确拒绝，不改写成25fps。

新包创建前先保存原项目／分集／指纹和原请求key；丢失回复时重载只读核对原key，不自动重新创建。明确重发仍使用原body／key；新来源不替换旧输入。只有明确写入拒绝且原key不存在，才允许点击“保留原拒绝记录，重新核对审片来源”，保留旧记录后重查新来源。重载不恢复新勾选；损坏的待核记录保留并阻断新创建。

选定原包后，点击“核对当前包审片门”才读取当前owner决定与意见。包级最新非备注决定须为通过；逐镜头退回／需修改和任何未解决意见仍阻断，新的整体通过不能抹掉它们，备注也不替代明确决定。来源变化使原批准进入stale；旧包为unverified。这里的approved只表示原包有相应人工决定且本机械门无阻断，不证明文学／视听质量、审阅者身份、合法授权、账单、成片／字体审阅或发行；releaseReady始终false。

第22.210节另在同一次明确读取中接通“原包逐素材owner证据”。按原包全部素材ID、版本与完整记录指纹读取Media自己的权利／费用／服务声明、来源、存档和历史完整字节读取凭证；可展开各素材查看。人工审片状态与素材状态分别展示，人工approve不能擦除受限／撤回／过期、服务不可用或存档缺失标记。素材已改或缺失时不换最新证据；当前存档与原包存档比较，原包未绑定存档不能事后自动补成已绑定。能力缺失明确显示owner-unavailable，坏证据或读取中变动使本次读取失败，不显示旧成功。没有媒体的原包显示no-media，不强制补媒体。素材状态只可能blocked／unverified／no-media，仍不认证合法授权、实际结算、当前文件、成片／字体质量或发行。

“导出原整包审片资料JSON”仅导出原冻结包和完整原NLE快照，不包含动作key，也不改用最新来源、生成成片或复制媒体。普通入口与原归属／丢回复／SQLite重启、意见和源变保护的实际证据见根PLAN22.198；整个Media Gate及其余A09条件继续。

新增意见、审片决定、意见解决和离线反馈导入，会在写入事务内核对原包范围。指定镜头必须在该包原冻结范围中；同项目后来新增但未纳入原包的镜头也不能写入。离线文件先核对全部意见和决定，有一项范围错误就拒绝整批，不保留前面的有效项。旧包按其自己的冻结剪辑清单核对，不借当前镜头列表扩范围，也不升级为新来源绑定证据。原回执损坏时拒绝写入，不换旧清单；已存在的历史错误反馈保留并继续阻断，不能通过“解决意见”抹掉错误归属。来源后来变化不妨碍对原历史包写合法意见，但原批准仍失效，不批准当前交付。工程证据见根PLAN22.218。

第22.203节已补收当前有限业务组：上述原整包入口及资料、冻结音视频、字幕策略四条后台旅程同次4/4通过，M5离线工具47项另包含在同组。修正的是本机测试字体选择，不是为产品补系统字体回退；测试通过不替代真实模型、用户、授权、账单、成片审阅或发布验收。

### 媒体待确认与精确返回

全局“待确认”新增三类对象：素材来源复核、人工音轨修订／当前确认头的新草稿、人工时间线换源／移除。列表仅显示对象身份、版本、状态及计数，不复制台词、字幕、音频、素材内容、移除理由或审阅声明。来源失效的预览进入“需要处理”；已采用来源复核、已采用新轨、已确认换源及已放弃记录仍在原域历史，不反复列为待办。音轨修订确认只创建草稿，所以当前新草稿未采用时仍在待确认中。

“返回对应对象”打开指定的旧预览，并核对实际项目／素材／原轨／分集／时间线身份；不会跳最新候选、自动选其他分集或初始化时间线。对象缺失、错归属或读取失败时明确报错，不显示其他作品内容。页面只读打开不生成、确认、采用或调用模型；重新核对完整差异并勾选三项声明后才能提交。重启、预览切换和状态／来源变化清空声明。

音轨已确认后，精确页面显示实际新草稿的 ID／版本／状态，须再明确点击“另行采用此新草稿”。当前确认头或实际来源已变化时不能沿旧回执采用；采用不会改旧轨、素材或时间线。整个流程仍不证明实际声音质量、权利／费用或完整 Media Gate 通过。任何摘要能力缺失、后续分页失败或循环游标都显示“计数未核全”，不能当作零待办。限定工程及隐藏窗口证据见根 PLAN 第 22.41 节。

### 生成完成后的来源核对与人工复核

静帧、视频候选卡片会只读核对 Media 保存的来源绑定、实际镜头版本及素材内容哈希。结果生成之后再次改镜头，或修改实际素材内容，仍会显示待复核；修改可编辑 payload 的 sourceShotVersion 或清除 stale 不能恢复有效。历史记录没有不可编辑来源绑定时显示未核验，不在读取或升级时补造证明。机械一致不代表叙事、作者意图、权利、费用或制作质量通过。

打开“查看并复核来源”，检查实际素材及镜头，再“建立来源复核预览”。预览冻结素材版本／内容哈希、原绑定和当前镜头／正式来源；重启后可从复核历史继续。须分别确认已审阅实际素材、对应镜头和作者意图，才能“确认来源复核”。期间任何内容、镜头、正式依据或另一份绑定变化都会阻止旧预览确认；可明确放弃旧预览，再重建。没有安全内嵌预览时，元数据不能代替实际审阅；未审阅就保留或放弃，不据此声称完整归档视频审阅已完成。

确认只追加人工复核绑定，旧绑定／文件和回执保留，不自动采用、锁定、生成媒体或调用模型。重新核对当前来源后，静帧／视频仍须单独采用。音频工作区选中素材也提供这一入口，但整条音轨每个片段的完整冻结版本／采用复核不是此功能的完成声明。来源不在当前正式分镜、正式上游已失效或其他项目的镜头，不能用此入口替代正式修订。限定证据见 PLAN 第 22.37 节。

### 已有剧本与创意直写的独立正式单集链

选择“导入已有剧本”或“从创意开始 → 开发剧本 · 单季短剧”后，在“项目工具 → 单集开发”确认真实分集、正式作者意图及已批准 Story Bible。已有剧本必须选择实际原稿，创意项目必须先保存非空故事构思或简报，也可明确附带实际已有稿件；空目录和空稿不是故事来源。这条路径没有小说、改编诊断或季纲，不用占位对象补齐改编流程。

在“单集大纲”选择原稿或仅使用作者简报，确认 30–1800 秒的本集目标及当前版本，再生成、检查、审阅采用。场景显示真实 project／production 来源身份和版本，不显示虚构章节；大纲的结构映射不表示模型实际理解或文学质量通过。已有剧本的原始生产记录与实际 AST 文档分别绑定版本，历史确实没有 AST 时明确记录“未创建”，不在来源读取或预检时自动初始化。

通过 Production 导入协议明确提交、并归属当前真实分集的 Fountain／FDX 原稿，即使没有旧“剧本内容”字段，也能进入实际原稿来源目录。正式链只读其已保存稳定块、原稿记录／文档版本及格式损失信息；由块导出的 Fountain 是便于读取的 AST 表达，不是原文件逐字还原，也不表示专有排版没有损失。只有预览而未提交的文件、空块或只有注释／排版占位而无动作／对白的 AST 不成为故事来源。第 22.25 节为后端来源修复，项目内文件 UI 见第 22.26 节及下一节，创建前独立入口见第 22.27 节及“创建前原生剧本预览与初始化恢复”；全部格式验收仍待完成。

切换“标准剧本”与“分镜包”时，每轮重新确认实际采用头，但故事来源和目标时长精确继承已采用大纲，不能静默换原稿、改时长或重绑最新简报。明确采用标准剧本是在原真实分集下追加独立 `scripts`／稳定块文档；原稿及其稳定块保留不覆盖，分镜另经采用才建立实际场景与镜头，不生成媒体。简报、分集、正式意图、原稿正文／AST、批准设定或采用头变化阻止旧候选采用，并使原正式结果只代表历史。

确认只持久保存来源身份和版本；候选与正式结果按原冻结基准恢复。失败显式重试保留旧快照，改源后仍不能采用旧候选。隐私禁止、缺失实际来源或完整首轮提示超预算在分配上下文记录／任务／模型调用前拒绝，不静默裁剪、不换源。小说改编入口仍保留自己的季纲与章节规则，未因此迁移到直写或混合表达策略。

采用来源有效的正式分镜后，可使用同一内部试制包流程；清单和说明保留实际直写来源，没有诊断／季纲版本。直写首页继续卡与驾驶舱使用上述四个正式成果 Gate：有正式分镜不等于已保存，只有匹配当前正式链、实际场景／镜头版本、权利确认及 Host 摘要／字节数回执才标为内部包已保存。全部语义质量、授权范围、真实模型和发行验收仍未完成。限定工程证据见执行计划第 22.23–22.24 节。

预览绑定本项目、当前实际分集及各自版本。展开全部稳定块及源位置，核对完整格式损失报告；FDX 不支持的段落或排版可能转为可见注释，需要人工查看。分别勾选来源使用权声明和“核对完整剧本块及格式损失”，再点击“明确提交本集原稿”。声明不是授权证明，结构检查不证明文学质量；解析器也不是完整 Fountain／FDX 专有排版或标题页语义校验器。项目／分集版本变化、无有效动作／对白、损坏或重复块都不能按旧预览提交。预览期间原稿不写入，取消只撤销此预览，不删除任何已有稿件。

提交会追加独立原稿和原生稳定块文档，保存精确提交回执，不覆盖旧稿。导入本身不运行模型、自动生成或采用，也不自动选择故事来源。请手动选择实际原稿，再重新确认本轮单集基准；创意项目也可明确仅使用已保存简报。手动选源仅保存尚未确认的实际分集、原稿记录／AST 版本，跳转或重启后恢复同一选择；原稿版本变化须重新手动核对，不自动改为最新版本，不把该选择当作已确认基准或授权。

未提交预览可以后台重启后恢复，但两个勾选都需重新确认。回复中断或提交结果不明时，应用保留同一预览身份，只读查询回执和实际来源目录，不自动重试写入或换稿；“恢复同一导入预览”同样只读。已提交且原稿变化时回执仅作历史，历史导入缺回执时不按标题猜测或自动重导。关闭已提交／已取消的导入记录只清除当前本地恢复指针，不删除原稿。恢复指针不保存文件路径、grant、正文或勾选状态。全部入口／格式、真实模型质量与完整授权／发行验收仍按执行计划推进。

### 创建前原生剧本预览与初始化恢复

首页选择“导入已有剧本 → 开发剧本 · 单季短剧”，填写项目名称等简报，在“创建前导入剧本文件 · Fountain／FDX／结构化 JSON”点击“选择原生剧本文件”。先核对完整稳定块、源位置和格式损失，再分别确认原稿使用权声明及接受转换。预览和“取消创建前原生预览”都不创建项目、原稿或模型任务；取消后可明确清除本地预览指针再换文件。不能同时按另一入口创建项目或暗中更换目标；PDF／OCR 尚不支持。

“确认原生预览并创建剧本项目”才开始创建实际单季项目和真实分集目录。Fountain／FDX 初始化一个分集及独立原稿；结构化 JSON 按原文件顺序初始化全部分集、各集独立原稿／稳定块和文件实际提供的场景资料，不推演新场景或镜头，不把原场景视作正式分镜采用。两者均不补小说、诊断、季纲或媒体，不自动生成或采用正式内容。原稿导入后可另行审阅作者意图、采用 Story Bible，并在单集工作台明确确认本轮基准，沿正式大纲／剧本／分镜和内部 ZIP 链继续。声明不是授权证明；格式及非空故事结构检查不是文学质量保证。

结构化 JSON 格式为可选 `title` 与非空 `episodes`；每集须有唯一正整数 `episodeNumber`，可提供 `title`、`content` 与 `scenes`。先展开“全部结构化分集原稿”，逐集核对原文／读取表达、完整块及全部原场景属性。独立 `content` 逐字保留；没有独立正文时仅拼接实际场景正文作读取表达，标题／属性另存，不冒充原文件逐字正文。未知文档／分集字段列入损失报告、不转换；场景按公开格式校验，标题等元数据去除首尾空白，未知场景属性保留。任何一集只有标题、备注或排版而无动作／对白，整个初始化都不能通过，不会静默漏掉该集。重复集号或格式不符会拒绝整个文件。

JSON 回执包含全部分集、原稿、AST 和原场景的实际身份／版本，并精确对应文件顺序。正常打开使用文件中的首个实际分集，不按分集号重排。恢复会核对全部原对象；第二集或原场景变化同样使导入回执过期，但不自动改写已保存内容。后续正式单集开发只使用作者明确选择的实际原稿，其他分集和原场景保持独立。

重启恢复 pending 预览只读同一记录，两个勾选需重新确认。已开始初始化的异常状态保留同一预览／创建键、服务器冻结输入与实际回执；只读恢复不会重试写入。状态核验后可点击“明确继续同一次原生初始化”，继续原操作而不是另建项目，后改表单不替换已确认输入。如果提交已完成但回复丢失，先核对精确回执，再点击“打开实际导入原稿”。正常提交会打开实际原稿；创建前指针清除不删除原稿。已创建／已物化的对象被作者修改或删除后，不覆盖、不按标题找替代物或重建；状态不可核验时继续保留身份。

本地恢复只保存 previewId、ETag 和必要的同次创建键，不保存正文、路径、文件 grant 或勾选；服务器持久预览保存冻结 AST、JSON 全部分集来源、格式损失、明确创建请求和回执。文件流程不自动放弃正在初始化的记录；未知结果继续保留身份，不猜测另一个文件或项目。其他目标／素材格式、完整质量／授权与发行验证仍按 PLAN 推进；实际命令、数据库中断与后台桌面证据见第 22.27–22.29 节。

文件解析失败且尚无服务端预览时，本地仍先保留原 previewId，不自动换文件。只有“只读恢复同一创建前预览”取得本预览接口的明确 404，且本地尚无创建键，才显示“明确解除未开始创建的预览绑定”。点击时会再次只读核验同一身份：仍不存在才清除本地绑定，让作者另选文件；如果迟到的预览已保存，则保留原绑定与完整预览，两个声明仍需重新核对。解除不发送 DELETE／提交，不删除服务端预览、项目或原稿，也不等于已取消未知服务器操作。

网络超时、权限失败、普通路由 404、损坏／跨身份回复都不能解除绑定；已有持久创建键即使遇到明确 404 也保留，避免把可能已经开始的初始化当作未创建。解除前的读取失败会撤去旧的“可解除”判断，需重新只读核验，不复用旧错误。后台重启同样先读同一身份，不自动解除、重试写入或创建替代项目。该限定恢复增量见第 22.29 节，不扩张为所有导入协议／目标或发行验收。

### 预览并保存内部试制包

在“项目工具 → 单集开发”的当前、来源有效的正式分镜上，点击“预览内部试制包”，选择是否纳入实际已有的 NLE 导出，再点击“生成统一试制包预览”。预览冻结实际采用的大纲、剧本、分镜、意图及稳定块和实际场景/镜头版本：小说改编保留诊断/策略和季纲引用，独立直写保留实际项目、分集、原稿及文档版本，二者不混用、不补造来源。不会自动采用新候选、生成媒体或创建时间线。

结构化 ZIP 包含说明 Markdown、大纲/剧本/分镜 JSON、Fountain、分镜 CSV、视觉/声音需求、字幕 SRT、媒体缺失说明、章节到场景/块/镜头映射、生成记录与 `manifest.json`。已有时间线时纳入其实际版本的 manifest、FCPXML、OTIO、EDL、SRT、VTT、relink；没有时间线则显示缺失，不造空 NLE 文件。可以逐个查看实际文件、字节数、摘要、采用版本、预检和外部依赖。

新生成的包另含 `source-context.json`：分别记录正式大纲、剧本、分镜生成时的实际表达身份、版本、字段和哈希，本集章节映射与完整上下文范围分列；混合表达保留实际段落 ID、章节摘要记录和高层原冻结范围，不附带来源正文、摘要正文或提示词。历史原文路径与真实直写来源分别记录，没有原稿的创意项目不补造原稿或小说。它证明当时提供的输入身份，不证明模型理解、全文已读或段落到镜头语义映射；不能把所有输入自动归因到每个镜头。旧包不自动重生成新文件；限定实现与逐次验收见 PLAN 第 22.31–22.32 节。

新确认单集大纲采用逐场实际引文协议：候选展示真实引文、版本／字段及模型声明的关联理由；正式结果还可展开规则匹配的全部位置。重复引文不会猜选某一处，位置按 UTF-16 半开区间记录；实际已选段落可定位到原章节，原稿动作／对白块可保留其稳定 ID。摘要位置只在实际摘要内，不补原文锚点。每场来源必须有实际表达覆盖，引文须在完整冻结输入中逐字存在；结构匹配不证明改编语义或文学质量正确。旧确认／候选没有该协议时仍按历史规则处理，不自动补证据；新协议下的下游必须精确继承。

在正式分镜包的“核对变化影响”中，可只读比较原采用剧本与当前实际稳定块、场景／镜头版本。清单分列“关联受影响”“未观察到关联变化”和“范围未核全”，可重新核对；块正文不出现在报告中。动作／对白修改按镜头声明引用定位，场景上下文、增删和重排保守扩大到整场；换头、故事来源／意图／设定变化或映射缺失仍提示全包复核。未观察到关联变化不证明语义安全。读取不调用模型、不改稿、不自动重做；人工改稿仍需重新明确确认，旧分镜与试制包的来源失效门不会解除。该只读报告不是提交授权。固定结构的明确选中局部重做见上节及 PLAN 第 22.35 节；完整原故事表达／语义影响与结构性局部重做仍未完成，原只读工程证据见第 22.33 节。

内部 ZIP 的 `outline.json` 去掉上述引文和模型理由；`lineage.json` 只输出规则生成的来源身份／值哈希／引文哈希／全部位置以及既有场景、连续剧本块、镜头关系。镜头的 `sceneEvidenceIds` 表示经场景继承，`associationScope=scene`，不是逐镜头引文或语义归因证明；模型关联理由仍需作者审阅。历史包不补写新证据。正文隔离只针对证据字段，不意味着生成的大纲／剧本等作品正文被去除。

其中 `selection.chapters` 和高层摘要覆盖章节的 `contentHash` 绑定原章节版本；实际提供的段落／摘要等表达值哈希，以 `references` 中同一身份、版本、字段的 `contentHash` 为准。不能把原章节版本哈希或摘要覆盖解释成完整原文曾被读取。

当前用途仅为内部试制审阅。来源与结构检查不代表叙事质量通过；预检会核对正式大纲、剧本、分镜对应版本的全部有效已采用质量报告。任何未处理错误都会阻断保存，勾选三个确认也不能绕过；新干净报告不能消除旧报告的问题。可以打开实际报告核对证据、明确接受风险或依据真实复检记录解决，再重新生成包预览。人工决定或正式报告版本变化会使旧预览失效，不修改旧文件。

所需维度全部覆盖且无未处理错误时，只表示“评议证据已核对（不是质量保证）”；未覆盖项仍显示未核验。接受风险不等于修复，授权声明不等于完整证明/用途/地区/期限核验，费用未知而非零，媒体二进制与资产锁不包含。已记录撤回/过期/受限的权利或无有效授权标记的人物会阻断保存；未知项不能称为发行就绪。清单不导出质量原句、人工处理备注或冻结正文。

分别确认导出权利、内部用途和未核验事项后，才可打开本地 ZIP 保存窗口。Host 写入后读取核对，Delivery 只接受与预览 ZIP 的 SHA-256/字节数匹配的回执。取消、失败、缺/错回执或保存中不算交付；不自动再开窗口。保存前来源变化阻止旧包写入，窗口期间变化保留历史文件回执，但不证明当前版本已交付。

同一工作台的“试制交付历史”可重新打开真实记录，包括取消、失败和保存中状态；重新打开不恢复同意、不自动保存，也不换用最新分镜。可用“刷新同一交付记录”核对状态。中断后没有回执的 saving 记录仍为未核实，重复原请求不会重开窗口；再次尝试需回到当前正式分镜重新预览。回执仅证明当时写入，不监控外部文件之后的移动、修改或删除。工程验收记录见执行计划第 22.10、22.13 节，不据此声称真实模型质量或正式发布。

## 版本绑定的独立质量报告

普通保存剧本／独立场景的只读来源前置见 PLAN 第 22.76 节，明确报告／工作台限定入口的正常完整与后台工程验收见第 22.77 节，不是文学质量验收。只核实际记录、保存文档／块、真实父级、版本与原字节指纹及禁止依赖，不初始化或修复稿件。无父级的独立场景不被要求先写小说或建立剧本；有父级时须核实际同项目记录，父保存文档变化也改变该场景的来源指纹。来源 available 不代表已生成报告、完成文学检查或允许外发。

对应正式试制包的保存剧本／场景报告错误门已按 PLAN 第 22.78 节限定工程验收：包内实际保存表达必须与正式内容一致，有效已采用报告的未处理错误不能通过勾选内部用途绕过，新无问题报告也不会抹掉旧错误。预览分列保存稿件指纹及原报告链接，局部稿件报告不补大纲／剧本／分镜的整包未核验覆盖。人工风险只是作者明确承担，不是修复；确认后原包／回执保留，报告决定或来源变化使其退出当前状态，不自动重写。读取失败时上次包只能作历史查看，不能确认保存；明确刷新同一记录重新核对，不自动创建新包或重复弹出保存窗口。该轮正常完整、同构建后台 27 项与隔离 HMR 终态通过，但仍不是文学质量／真实模型／发行保证；该节当时尚待的独立单集重选后续按第 22.79 节限定验收。

单集开发新增“本集实际输入方式”：默认展示正式季纲表达，可以明确改为本集独立重选，再选择真实原文、已采用摘要或实际段落；完整高层摘要不能截掉范围外章节。必须覆盖季纲本集映射，未选来源不自动补入；确认后剧本和分镜只继承已采用单集大纲的该选择，不另选最新。切换或改选须重新确认，读取失败不能用旧控件启动。原整季来源隐私和正式季纲有效性仍是约束，不因为本集未选某章就绕过失效或禁止外发。本增量按 PLAN 22.79 已限定验收，普通完整、说明修正后十三项相关后台与隔离 HMR 分开通过；不证明文学质量、精确语义影响或发行通过。

系列长篇和单季项目可从“项目工具 → 质量报告”进入。选择实际当前非空章节、“小说跨章与全书”、来源有效的正式诊断／整季方案／单集大纲／标准剧本／分镜结果，或实际可核对的“保存剧本”和“独立／关联场景”；选择作者意图、人物认知／关系、时间线、因果、伏笔、重复、节奏、对白及可选制作风险等本轮维度，点击“确认本轮质量基准”。没有默认目标，确认后保存精确版本；普通保存稿还绑定实际来源 SHA-256，块内容或真实父文档变化时，即使记录版本未变也需重新明确确认，不替换原运行。空来源／缺文档不能生成，不自动初始化或补小说。小说可以独立检查并完成，不要求诊断、改编或媒体，也不强制爽点、反转或短剧化；上述范围不扩大为所有生产对象／媒体质量目标。

普通保存稿报告可展开“实际保存来源与原块身份”，只读原记录、保存文档／稳定块 ID、类型、顺序与 hash；场景另列真实父身份，不代表父正文已读。问题的逐字证据来自实际保存块 text，或场景动作／对白与备注／地点与时间，不从标题、ID、损失报告或来源标签补故事原文。模型声明覆盖和引用存在仍不证明阅读理解／文学质量；报告不会改稿。原报告／运行链接重启只读恢复指定对象，来源变更保留原历史，读取失败不显示旧缓存替代，不自动选最新或开启新模型任务。

跨章目标还需明确勾选实际非空章节，默认不选前三章或任何正文。“所选章节”是局部范围；要检查全书，选择“全书非空正文”并点击“选择全部非空章节”或逐一勾选，漏选时不能确认全书。空章禁选并显示未检查；完整目录、顺序和逐章版本被冻结，所选变化只在再次确认后生效。全书目录新增章节（包括空章）使旧全书报告失效；局部报告不自动读新增或未选正文。单次范围上限为 2000 章，还受实际冻结预算限制；超限不会自动裁成开头几章。明确混合表达已接入本质量评议，但不是任意长度或完整全书理解支持。

默认使用所选章节的完整原文。需要混合输入时，勾选“质量评议使用明确混合表达”，展开“质量评议实际表达”，另行选择完整原文、当前精确采用章节摘要、实际段落或来源仍有效的卷／故事弧／全书冻结范围摘要，再确认本轮基准。开启混合不会自动勾选原文；所有确认章节须被实际表达覆盖，高层摘要的全部原覆盖章节必须处于确认范围，不能截取其中几章使用。原冻结来源仍有效的旧完整范围可明确选择，但不会扩大到新章。选择只在本机保存安全 ID／版本，不保存摘要正文；来源变更不自动换头或换版本，必须重新选择确认。

点击“生成并检查版本绑定的质量报告”，审阅完成后的实际候选。每个问题显示类别、严重度、模型来源、建议、源 ID/版本、字段位置和逐字引文；可展开冻结来源与运行记录。引用存在不证明模型语义判断正确，可能有误报，没有总分或文学质量保证；未提供实际 usage 时 token/费用为未知，不是零。隐私/预算不能完整纳入本轮必需内容时，会在引擎调用前阻断。

跨章报告显示逐章实际表达、未选/空章、冻结目录计数与逐章版本，混合报告另列摘要身份及原冻结章节。模型必须列明全部所选章节版本和全部实际表达引用，漏报、伪造引用或拿摘要覆盖冒充原文纳入都会被拒绝；摘要引文只来自实际提供的摘要，不能声称引用了未提供的原文。“全书非空正文”在混合模式只是目标范围，不保证完整原文评议，摘要／片段会明确标注“不是全文评议”。其已知错误仍需处理，但干净混合报告不能补足全文维度证据。即使完整原文纳入，也不保证模型理解全部叙事或没有误报。冻结上下文 token 是估算，不是实际 usage 或费用；新全书报告不能自动清除旧有效局部报告的问题。

“采用此质量报告”须再次确认，只采用报告，不改正文、不自动接受风险。问题的人工处理说明不能为空；“接受此风险”也须明确确认，记录为接受风险而不是修复。“记录已解决（需复检）”须先生成并采用同目标／范围／精确表达的真实复检报告，再选中它；改用原文、其他摘要版本或不同段落不视为原混合报告的同一复检。系统核对其为当前有效正式报告且问题不再出现，不能仅靠勾选解决。新干净报告不会自动清除旧报告中的未处理问题。

报告历史和待确认链接打开指定报告，不跳到最新报告。报告、决定和冻结运行可重启恢复；旧有效报告也能依据当前复检记录处理，失效报告只保留历史，不能变成当前质量证据。来源核对不改旧内容、版本或时间；失败重试仍用原冻结基准，只有新的明确运行读取新来源。原章节、中间派生记录及其祖先的禁止外发限制继续生效，最上层摘要 always 不能绕过；完整首轮要求、格式及引用均计入硬预算。明确创建拒绝后，修正隐私或要求再点击可发起新请求；结果不确定的网络超时仍复用原幂等键。此入口是有证据的模型评议与人工决定，不代表完整全书语义检查、规则/人工独立评议创建或真实模型评测完成。

## 小说续写的明确上下文

正文页 AI 创作中的“本轮前文来源”可以按实际目录明确选择完整原文、某条当前已采用摘要，或逐一勾选当前版本的实际原文段落。未选前文不自动进入本章创作，旧 `summary` 字段和未经精确采用核验的记忆不作为事实引用；不再固定取最近两章及更早三十章的摘要。选段只代表这些片段，摘要是派生概括，不代表读过原文或完成全书连续性检查。

“续写下一章”另有“下一章来源范围”：默认清楚标明只承接当前章完整原文，不默认整书或全部历史记忆；可在点击续写之前改选当前已采用摘要、原文段落或其他前文。仅查看、读取来源和改变选择不会运行模型。所选 ID/版本保存在本机，重启后可以恢复；来源变化不自动换成新版本或最新摘要，须明确重新选择。本章来源和下一章来源分别记录，不把一个范围用于另一个操作。

续写会先用实际来源、隐私策略、模型选择和完整首轮生成提示（含补充要求与字数目标）做无写入预检。来源旧版本、所选摘要／段落缺失、必需作者意图被排除，或完整提示超过硬预算时，不新增空章节、上下文预览／快照、任务或运行，也不调用模型。预检通过后才创建下一章并正常冻结运行；此后引擎启动或模型运行失败，已创建的目标与运行会保留，可从运行历史明确重试原工作流，不自动删章或换源。

同一续写请求的并发提交或成功后的重启重放复用同一个目标和原响应；幂等标识绑定项目、来源与完整创作要求，不能用它提交不同内容。旧历史目标若缺少完整请求绑定会明确拒绝该标识，须从原运行历史继续，不用旧标识另建章节。失败后的显式工作流重试保留原冻结基准，修改来源或要求须发起新的明确请求。

摘要与段落继承原章节的外发限制。例如 `/chapters/某章节ID` 禁止发送时，不能把 `/knowledge/某摘要ID` 标为 always 来绕过；原章节上级路径的禁止同样生效。来源禁止或完整冻结提示超过硬预算时，创作在任务与引擎调用前阻断，不静默减选、补用旧摘要或塞进基础 Prompt。后续检查、局部修订、复检与失败重试沿用原快照，不自动换源。

也可以展开高层摘要来源，点击“读取卷／故事弧／全书采用头”，读取并明确勾选某条来源仍有效的已采用摘要，与逐章原文或实际段落混合。它不会自动替你勾选或撤销已有原文选择。只有全部原覆盖章节均为目标章之前的当前有效正文，才允许纳入；包含当前章、未来章节、旧来源或不是当前采用头时，不能截取部分摘要或换用最新记录。选择保存摘要 ID／版本，不复制摘要正文。

新增章节可能让旧摘要不再代表“当前完整全书”，但不改变它原来覆盖的正文。系统分别显示“当前完整范围是否失效”和“原冻结范围能否续写”：后者仍有效时，可由作者明确选择，只覆盖原来的章节，不扩展到新章。高层摘要的模型输入不夹带证据中的整章正文或中间章节记忆；所有原章节、中间派生记录及其祖先的禁止外发策略仍被继承，不能在最上层摘要标 always 绕过。

运行的“引用资料”显示实际前文表达、纳入／未选计数、安全来源 ID/版本/字段位置及冻结 token 估算和预算；实际 usage／费用未知，不填零。明确采用仍只写本章候选，核对所选源及目标版本；未选前文的独立修改不扩大原范围，所选原文或摘要失效则阻止旧候选采用。作者对目标正文的显式三方合并只重定位目标稿件，不把其他上游来源换成新源。

运行另列高层摘要的精确身份、原冻结章节版本及范围状态；高层和原文／段落重叠时，覆盖章节数去重，不将同一章算两遍。重启后待审候选与来源选择保留；立即采用候选所触发的事实记忆同步，会先恢复明确启用的模型配置，恢复失败则明确报错，不换引擎或模型。

这一前文能力用于独立小说本章创作与下一章续写；跨章质量和改编诊断分别有独立确认范围与混合表达选择，季纲只继承其已采用诊断的精确表达，不能借用本章或下一章选择。单集可明确完整继承混合季纲的实际表达，也可按第 22.79 节在原正式范围独立重选，本集映射与实际输入分别显示，不借用小说续写配置；历史原文基准不静默升级。完整人物认知与因果图、精确语义影响／结构性局部重做、通用 Agent 对话和其他兼容操作的统一迁移仍未完成。

## 本地长篇来源索引

在项目工具“质量报告”展开“本地长篇来源索引”，查看全书实际目录、章节真实卷归属、已明确绑定的规划故事弧及当前正文版本。空章、缺少有效摘要和摘要已过期分别显示；不默认取前三章，也不会把没有来源证明的章节摘要字段当成正文事实。它是可选的本地索引，创意或已有剧本项目不必创建小说才能继续工作。

明确选择一章后，可查看当前已采用派生摘要、人物状态、事件和伏笔，以及逐字引文匹配的全部原文位置。段落引用绑定此正文版本，位置使用 UTF-16 字符偏移，结束位置不含在内；重复引文不会猜成唯一位置。证据和采用来源只证明记录可追溯，不证明模型概括或文学判断正确。原文与摘要的 token 数是 UTF-8 字节/4 的预算估算，不是服务商实际 usage。

有效派生资料需匹配精确记录采用回执、实际完成的记忆工作流、原始采用输出和当前章节版本。历史资料、复制来源标记、采用后编辑的记录或不含实际原文依据的条目显示在未纳入资料中，不会自动升级。若要补充当前有效摘要，选择“审阅生成本章派生记忆”：独立生成经过正常生成/检查后等待作者审阅采用，不改正文。已有明确采用章节的自动事实同步仍保留；人工原稿无需先让 AI 改写。

故事弧的旧起止章号和自由文本上级不用于猜测范围。在索引下方明确选择实际故事弧与章节，确认后只记录有序章节 ID/当前版本，并保留原有规划字段；不改变正文，也不把计划当成已发生事实。章节版本或顺序变化使旧绑定失效，必须重新明确确认，不自动换源。

索引查看和刷新不会调用模型、改写正文或自动外发资料。小说续写、跨章质量与改编诊断可各自另行明确选择有效章节摘要、实际段落或已采用高层摘要，并继承完整来源隐私限制；季纲继承已采用诊断的精确表达。卷／全书摘要需要下方的独立生成和采用，不由目录自动产生。完整认知／因果图、其余操作迁移及跨版本段落到镜头谱系和精确局部重做仍未完成。查看目录、摘要覆盖或分集引用不代表模型已检查全书原文。

## 卷、故事弧与全书派生摘要

在“项目工具 → 质量报告”展开“卷／故事弧／全书派生摘要”，明确选择实际全书、真实卷或已绑定当前章节版本的规划故事弧。没有默认范围；数字章号或自由文本不推断故事弧绑定。范围内全部非空章节必须按实际目录纳入，空章显示未纳入、不算已读；单次最多 2000 个非空章节，仍受实际冻结预算限制，超限不自动取前几章。

逐章显示完整原文，也可点击“读取此章已采用摘要”选择某条当前有效的精确记录。派生摘要只发送摘要文字，不夹带其原文引文；原章节或祖先路径禁止外发时，不能用派生记录的 always 绕过。选择与查看不调用模型。点击“确认本轮摘要来源”保存安全 ID／版本和完整范围指纹；确认期间目录、卷归属、故事弧或采用头变化会要求重新选择，不自动换源。

点击“生成并检查卷／故事弧／全书摘要”，审阅完成后的实际候选、逐章版本及所选来源的逐字依据。每个非空章节必须被列明并带至少一项依据；这是结构与来源校验，不证明概括正确、人物弧已理解或模型不存在遗漏。摘要概括已有正文，不把未来规划当成已发生事实，不注入作者意图中的未来约束。预算为实际快照估算，真实 usage／费用未知，不填零。

明确采用只切换当前范围的派生摘要头，不改章节、规划或生产对象；竞争采用或来源变化会阻止旧候选覆盖，仍可明确放弃。历史保留精确候选、工作流与冻结快照，重启不会替换成最新摘要；修改所选源后只读显示失效，不重写历史内容和时间。未涉及的独立卷范围不因另一卷正文编辑自动扩大。待确认可返回原摘要工作流／候选；已采用摘要的失效提醒目前需在此工作台查看，尚未纳入全局失效摘要聚合。

已采用高层摘要可以在小说续写、跨章质量或改编诊断各自的实际表达中另行明确选择，不自动外发；范围增长后仅原冻结来源仍有效的快照可用，不代表新完整范围已被概括。质量的高层全部覆盖须处于确认范围，不能截取或用摘要冒充全文评议；诊断独立确认实际表达，季纲只继承已采用诊断的同一基准，不补整章正文；单集开发等其余操作仍有独立来源策略。当前是可审阅采用、有来源的分层概括，不是完整人物认知／关系／因果图、全书语义质量保证、任意长度支持或 GA；小说项目无需建立这些摘要才能继续写作或导出稿件。

## 小说稿件导出

小说页“输入输出 → 导出投稿包文档 / 导出投稿包数据”打开稿件交付预览。选择完整目录或部分章节后，系统按实际目录冻结已保存章节的版本与正文摘要；空章、未保存编辑和生成候选不会自动成为稿件。可以导出作者原稿，不要求先让 AI 改写或采用。新投稿 Markdown 只含题名、梗概和正文，新投稿 JSON 是带所选章节版本的纯稿件，不夹带通用资源附录。

预览显示实际章节版本、范围、格式、文件摘要和字节数。确认范围及原创、授权或公版的权利声明后，才会打开本地保存窗口。Host 核对实际写入文件的 SHA-256 与字节数，Delivery 保存成功回执；取消保存、保存失败或缺少匹配回执都不算成功。来源在保存前变化时会阻止旧稿件保存；在保存窗口开启后变化时，回执只代表历史版本，不证明新正文已交付。部分范围明确标为“所选范围”，不会冒充完整稿件。

从驾驶舱可以重新打开对应稿件清单；格式、章节范围、历史回执在重启后保留，待保存预览不自动恢复权利同意，也不会再次打开保存窗口。回执证明当时写入成功，不监控外部文件后续的移动、修改或删除。权利确认是作者声明，不是系统自动取得或核验授权，也不保证文学质量或投稿录用。导出不要求改编、分镜或媒体。

旧 Workspace 导出 API 和完整项目包保持兼容；旧 `submission-json` API 仍返回项目资料包，不是新纯稿件 JSON。普通“导出完整小说文档”保留资料附录，适合项目整理；这些兼容导出不制造 Delivery 正式交付回执。

## 原稿导入后的候选审阅

确认导入小说后，项目页会生成一个“导入候选审阅”变更集，其中包含从已确认版本整理的人物、场景、道具、章节摘要和短剧改编建议。每条候选都显示原稿章节、文本范围与置信度；这里的整理在本机确定性完成，不依赖模型服务商，因此服务商不可用不会影响已导入正文继续编辑。

候选在采用前不会写入 Story Bible、制作素材、章节摘要或改编资料。可以查看全部候选、逐项编辑、勾选采用、标记不采用，或只采用某一类别/某一项。采用在一个数据库事务内进行：发现同名人工资料或来源版本已变化时，会以冲突或“来源已更新”呈现，不会覆盖人工内容或留下部分写入。

采用后可点“撤销采用”。系统只撤销由该变更集创建且尚未被人工修改的内容；如果之后有人编辑过某项资料或摘要，撤销会保留该人工编辑并标记为待处理。重复提交同一候选不会创建重复实体。

## 待确认中心

“需要处理”还包括已经采用的高层摘要和当前正式单集的来源变化。摘要若只因目录增长不再代表完整范围、但原冻结来源仍有效，会显示“完整范围已变化，原冻结范围仍可使用”；真实原来源变化才显示冻结来源不可用。它不会把新章节加入旧摘要、撤销采用或自动生成新摘要。当前正式大纲／剧本／分镜来源变化也保留原正式内容；历史版本仍在各自页面，不重复冒充当前待办。

这些条目仅汇总真实身份／版本和计数，不显示摘要、正文、引文或 Prompt。返回摘要打开原 summaryId；返回正式单集打开原 resultId，只查看该快照，不换成最近候选、恢复生成基准或自动重做。需要重新开发时另行返回独立开发工作台并选择来源。错误项目或对象读取失败保留原链接并明确报错，不展示上一个项目的工具页或内容；全部分页未核全时仍如实提示。

全局“待确认”默认查看全部项目，也可选择单个项目。它统一列出已有的人物/大纲、章节、剧本等创作候选、旧章节修订、Story Bible 变更、正式作者意图候选、独立改编诊断、模型/人工整季方案、单集大纲/剧本/分镜方案、质量报告、导入资料候选、稿件范围与权利声明、素材来源复核、人工音轨修订及其当前未采用新草稿、人工时间线换源／移除，以及任务待确认结果和异常。分为“待确认 / 进行中 / 需要处理”；执行成功不等于正式采用，部分导入采用不等于全部完成。

点击“返回对应对象”打开该条记录的具体工作流、修订、变更或稿件清单，不用最新结果替代旧候选。全局任务不会误绑定当前项目。费用待确认项返回实际厂商预览核对费用和权利；稿件确认仍需核对范围及作者声明。浏览列表不会自动采用、导出文件或批准外部调用；各领域的差异、确认、版本冲突和权利/费用限制仍然有效。

任务中心的普通列表和精确链接会重读实际候选，而非拿任务内嵌的旧参数执行。链接同时指定任务与运行时，两者必须属于同一实际项目和原任务；错误、缺失、重复或空引用不会被忽略，也不会改开其他任务。助手中的厂商预览还需核对实际对话、运行及原任务。读取失败时旧参数与执行控件停止显示，恢复读取也不会自动执行。

厂商卡显示“记录中的预估费用”。金额或币种缺失时不会默认 USD 或零，远程创建按钮保持禁用；明确的零估值仍不是零账单或免费证明。查看实际参数后另点“确认并创建远程任务”，确认前后都会核对同一 pending 记录；记录变化或已离开原对象时，旧确认不执行，须重新读取并另行确认。已创建任务只表示受理，不表示生成完成、结算完成或合法授权；放弃未知费用预览不会启动新调用，也不能证明没有历史费用。此保护不能代替真实报价、费用回执或权利方授权材料。

章节修改后，尚未采用的 Story Bible 建议会进入“需要处理”，显示“来源版本已变化”。返回原变更仍能查看历史草案，但不能采用或恢复过期建议；可以明确“丢弃”，或核对当前章节后重新生成。即使只修改章节标题、正文未变，新版本也不会沿用旧草案。浏览检查不改写历史状态或正式记忆；已经采用的历史变更仍保留，若要移除其创建的记忆须使用“撤销采用”。全部项目范围下的“任务历史与配置”也查看全局任务，不会退回活动项目范围。

如果某个来源读取失败或分页未完成，会显示“未核全”，不是没有待办。已采用、已放弃和已取消的结果保留在原对象或任务历史中；失败任务可在任务中心标记已处理。旧章节修订的来源版本已变化时会显示冲突，但浏览列表不会修改该修订历史。冲突候选不能直接采用，仍可明确“放弃此预览”，确认后不改作者新稿；重复放弃不制造重复历史，其他未放弃候选仍保留。作者意图仅显示版本与来源摘要，不显示约束正文；诊断/季纲摘要不返回正文或原著片段，已采用/放弃的本域记录不会因工作流投影短暂滞后而反复制造待办。质量摘要不显示引文或人工备注：候选进入待确认，有效已采用报告的未处理问题和当前失效头进入需要处理；新干净头不会隐藏旧有效报告问题，返回指定 reportId/workflowId，不改报告。完整费用/权利链路与全书语义质量中心仍按执行计划建设。

## 项目驾驶舱与四区导航

打开项目后，项目驾驶舱按小说、小说改编或独立直写目标核对正式采用、当前来源与保存回执，不按章节、剧本、镜头或静帧计数判断完成。它只给出一个主要下一步，并明确列出当前阻断项；运行中、失败、未安装或等待人工确认都不会显示为完成。

驾驶舱下方的“创作 / 改编 / 制作 / 审核交付”会携带当前项目上下文。全局导航仍然保留，供查看或切换其他项目；从驾驶舱进入时无需重复选择已经确定的项目、改编方案或分集。

只写小说且未建立改编的项目显示“正文与章节采用 / 连续性事实记忆 / 稿件与投稿导出”三个结果状态，不显示必须完成的制作百分比；改编、制作和审片入口默认折叠。作者原稿显示已保存，不冒充 AI 正式采用，也不要求先让 AI 改写。采用记录只对对应章节版本有效；后续修改正文时，旧采用与旧记忆不再代表当前版本。

有候选、运行或失败时，推荐链接同时保留原项目、任务和运行编号，进入任务中心复核指定记录；不会把普通章节／资料编辑器中的最新运行当作旧候选，也不会因较新的已取消或已结束运行而隐藏原未决候选。失败可在任务中心明确标记已处理，之后不反复占据小说主操作；失败历史、作者正文与其他候选不变，已处理不表示生成成功或正式采用。

改编和直接开发剧本的驾驶舱会先核对当前正式来源与首集基准，再推荐尚待审阅的原候选或活动运行。你另行生成并放弃较新候选，不等于放弃较早候选；原候选仍可由下一步返回审阅。没有待审阅或活动运行时，较新结束记录不会让旧失败反复占据下一步；已有效正式采用的成果仍按当前版本继续。上游版本变化的候选不会按旧基准推荐，也不会自动改成新来源或采用。

首页“继续当前项目”读取必要进度或正式来源失败时，会提示“项目进度尚未核验”，暂不推荐生成或采用，并保留“打开已有项目”。这不表示原稿或成果不存在：可打开项目查看已有内容；读取恢复后再核对下一步，不自动执行。读取尚未取得必要数据时只显示整理中，直写与改编不要求先建立小说来源。

本章已明确采用且事实记忆对应当前正文时，推荐继续下一章。只有已采用、来源版本匹配且有正文证据的记忆才显示同步；缺失、删除或旧版本资料不算同步。返回驾驶舱会重新核验状态，不复用采用前的待确认缓存。

稿件 Gate 读取 Delivery 的实际清单和回执：预览显示“范围与权利待确认”，保存结果未知、取消或失败分别说明；只有当前范围/版本与匹配的 Host 回执才显示核验保存。来源修订后保留历史回执但标为过期，部分章节成功保存不代表全书交付；旧兼容导出没有正式回执时仍未核验。新小说改编六 Gate、实际旧兼容链五 Gate 与直写四 Gate 分路，不要求直写回到小说工作区；完整入口、语义质量与发行 Gate 仍按执行计划推进。

## 1–3 集试制向导

项目页的“1–3 集可恢复试制”用于先完成一段小范围生产链路。选择一至三个已有章节和相同或更少的试制集数后，先人工确认来源；确认才会建立可继续编辑的试制改编方案与分集。向导不会自动生成图片或视频，也不会把计划本身显示为完成。

确认来源后，向导根据真实的已采用剧本、场景、分镜和资产显示唯一待办，并跳转到对应现有工作区。来源章节更新会使试制标为待重新确认；“按当前来源重新开始”只刷新来源版本，不删除已经采用的内容。重复确认不会创建重复分集，取消试制也只关闭运行记录。

## 统一资产中心

“制作 → 资产中心”把角色、场景、道具和音色的候选版本放在同一处筛选和比较。每张卡片显示采用、锁定、权利、费用、服务和本地媒体状态；缺失文件、费用未知、权利受限与服务不可用会分别说明，系统不会伪造预览。

先采用一个候选版本，再锁定它，才能把该具体版本分配给镜头。锁定后，新候选不会自动替换它；请明确解除锁定或迁移镜头用途。被镜头使用的版本不能直接删除，必须先在资产中心移除或迁移用途。对于已归档且不超过本地预览上限的图片和音频，点击“打开本地预览”可在应用内查看或试听；预览只读取受控归档副本，不显示原始路径，也不会上传媒体。

## 本地系列资产库

在项目工作台的“系列资产库”可让多个本地项目选择性加入同一个系列。系列不代表账号、云同步或跨设备共享：旧项目可以完全不加入，离线照常打开；解除归属也不会删除或迁移任何项目资料。

系列故事圣经以项目采用的版本快照为准。系列里新增或升级设定后，不会静默改写已加入项目；项目需明确采用新版本，或建立自己的项目覆写。已有覆写会保留，系统不会用系列新版本覆盖它。

只有已采用、已锁定且权利已核验的视觉资产才能从同系列项目导入。`Link` 在目标项目建立不可修改的版本投影，后续源项目更新不会改变它；`Copy` 建立独立副本；`Fork` 建立可在目标项目内继续编辑的衍生版本。三者均保留来源与版本号，但不会重复复制本地媒体二进制。仍被 Link 引用的源/目标版本不能删除，须先明确迁移或移除链接。

项目包会同时保存项目内的系列来源、已采用设定和资产引用的说明快照。导入项目包不会自动加入原系列，也不会连接到外部库；因此即使原系列已不存在，导入后的项目仍可解释这些资料的来源和版本。

## 卡片式导演分镜看板

在“制作 → 分镜与资产 → 导演看板”中，先选择当前分集，再按场景扫视镜头卡片。每张卡片显示真实的静帧状态、画面、对白、景别 / 运镜 / 时长、镜头任务状态，以及角色、场景、道具、音色的资产引用、锁定、权利和成本风险。没有受控静帧文件时会明确显示状态，不会用占位图片伪造预览。

可使用卡片的“上移 / 下移”、聚焦卡片后按 `Alt + ↑/↓`，或把一张卡片拖到同场景的另一张卡片上重排。保存时会提交完整同级镜头列表和当前版本；发现其他窗口已经改动顺序时，请刷新后重试。一次成功重排可以立即撤销。长场景默认分段显示 50 张卡片，可继续加载，不会因为缺图或加载中让整个看板空白。

勾选一张镜头卡后可直接打开资产中心查看该镜头用途；点击卡片标题会把项目、分集、剧本、场景和镜头上下文同步给资产中心和智能助手。助手发起的新任务会附带这段镜头说明，但仍只产生预览或待确认任务，不会自动采用、锁定或调用付费媒体服务。

## 静帧优先的视频预检

在“制作 → 视频制作”中，先选择服务商、填写提示和时长，再点“检查静帧与视频预检”。系统会在本机服务端检查：当前镜头是否采用了未过期静帧、镜头引用的每个资产版本是否已采用和锁定、权利是否已核验、服务是否可用，以及服务商配置、时长、并发和费用状态。任一项不通过时，界面会逐条列出修复原因，且不会向视频服务商发送请求。

预检通过后会显示一次性快照，包含采用静帧、锁定资产数量、提交参数和费用状态。修改提示、时长、服务商或镜头后必须重新预检；若镜头设定、采用静帧或资产锁发生变化，则必须重新采用静帧确认视觉方向。费用未知时，必须勾选明确确认并重新检查，提交后应到“生成账本”补录实际费用。批量提交请先调用批量预检接口：它会逐镜头保留阻断项，并合并检查同一服务商的并发上限和已知 / 未知费用。

## 多轨时间线

在“制作 → 多轨时间线”中打开分集后，系统会首次从当前镜头和已采用的音轨建立一份版本化时间线：视频、对白、旁白、配乐、音效和字幕轨始终存在，初始片段使用稳定 ID 与受控媒体实体引用。首次装配之外，重新打开不会覆盖人工移动、裁切、分割、静音、独听或重链接。

按空格可播放 / 暂停，左右方向键每次定位一秒，拖动播放头和缩放尺可检查长时间线；`Ctrl/Cmd + Z` 可撤销，`Ctrl/Cmd + Shift + Z` 可重做。移动、裁切、在中点分割、静音 / 独听和重链接会立即保存到本地，并按 25 fps 的帧边界取整。预览只尝试播放受控归档的短媒体，并不代表最终渲染。

在时间线内点击“审查自动编排”，可把已采用的对白、旁白、配乐和音效版本映射到镜头范围，并预览音量、BGM ducking、淡入淡出、时长溢出和 SRT / WebVTT 字幕。选择要采用的音轨后才会写入可撤销的 change set；缺少媒体、权利受限或过期的候选会明确提示，系统不会自动取得未授权音乐，也不会静默裁断超长对白。

任何手工移动、裁切、音量调整或显式锁定的片段都会受到保护，后续自动编排不会覆盖或删除它。每个候选仍引用原始文本、音色 / 素材版本和可见的服务商、成本、权利状态；修改一条台词时，只应重新生成与该片段有关的音频和字幕。

“文件缺失”“编码不支持”和“未附加媒体”都显示在具体片段上，不会阻止其余轨道打开。选择片段后可以把它显式重链接到当前项目的归档媒体；这只改变时间线引用，绝不移动、复制或修改源文件。后续交付使用同一秒级 timebase、时长和片段顺序。

### NLE 交付与媒体核验

时间线中的“NLE 交付与媒体核验”提供同一份 canonical timeline 的 FCPXML、OTIO、CMX 3600 EDL、SRT、WebVTT、交付 manifest 和媒体重链接清单；导出使用稳定轨道／片段排序与 25 fps 时间换算。交付 manifest 为版本 3，逐项保留实际片段 ID、冻结素材版本和来源状态，再经 Media owner 核对同项目／精确版本的单一有效存档。有效存档提供 opaque artifactRef、MIME、扩展名、大小和 SHA-256，状态明确为“owner 元数据”；没有证明的历史引用、缺失／跨项目／旧来源和歧义存档不填成最新有效文件。

`media/<assetId>.<扩展名>` 是重链接目标，没有实际复制文件；缺存档时仍为无扩展名占位。存档 SHA-256 不是字节已核验回执。点击“核验清单媒体完整字节”后，系统在本次原清单范围内逐文件完整读取和计算 SHA-256，并在读取前后重新核对实际时间线、来源和存档。最多 50 个文件、合计 256 MiB、单文件 128 MiB；超过范围须另行逐文件审阅，不截取子集冒充全量。缺文件、同长篡改、版本变化、格式不符或读取失败明确显示未核验，不自动重试或换源。“停止核验”、切换对象和卸载取消在途媒体读取；已发出的只读清单查询若无法中止，其迟到结果也不更新新对象。核验不自动播放、上传、下载或保存审阅声明，结果只留在本次界面；刷新后须明确重新核验。

当前清单不把可编辑“已核验”权利字段转成授权通过，只记录 `user-reported-cleared`（人工报告已核验），权利状态仍未知；人工受限声明会保守保留为受限。全字节一致同样不代表可解码、NLE 可导入、文学／视听质量、合法授权或费用完成。导入 NLE 前仍须另行取得授权并在实际剪辑软件中导入／重链接和验片；本机原媒体包复制入口如下，其自己的整组验收以 PLAN 第22.178节为准，不能替代权利／费用或正式 Media Gate。

### 原媒体包本地复制与原请求恢复

“多轨时间线 → NLE 交付与媒体核验”下的“原媒体包本地复制”独立于只读核验和单文件凭证。小说与无媒体改编不必走此步骤。它只支持现有导出器的1080×1920／25fps／48k立体声配置，最多1000个原媒体、单文件2 GiB、合计8 GiB；有来源阻断、缺失／歧义存档或受限声明时不允许新复制，不截取子集冒充全包。

先明确勾选“我仅将原媒体包交给本地剪辑；质量、授权与费用仍未核验”，再点“明确选择本次写目录”。这取得绑定本次原清单的独立写授权；选择取消没有创建任务，也不复用上方只读权限。只有点击“复制本清单原媒体包”才提交，提交前必须成功保存并读回本机原请求键和完整原输入。Core会再次核对原时间线与Media owner存档，Host复制原存档媒体与七种固定NLE文档、完整重读目的字节，成功后保存原包凭证。原请求不会根据最新来源自动换键／重做。

页面重载／重启只恢复本机原身份，不自动复制、刷新或取消。提交或动作响应丢失时，先点“只读恢复原复制任务”；它只读原键和原输入，当前清单变化也不会改绑最新版本。原“刷新／取消”动作标识若保留，恢复不重发该动作，也不据此声称旧动作成功。“读取此时间线原复制历史”和“重读这条原历史任务”仅取原记录；失败清除本次显示的旧列表／游标，不拿缓存补成本次证据。

“停止界面等待（不取消复制）”只中止界面请求，不撤回Host已接受的复制或已发送动作。先只读恢复，再明确点击“明确刷新原任务结果”或“明确取消原复制任务”。取消与完成可能竞争：若原复制已经完成，实际回执仍显示完成，不伪造成已取消。切换原范围／卸载后迟到结果不能更新新面板；来源变化只标原历史，不发布为当前清单证明。

只有实际completed且带原artifactRef的回执才提供“展示这个已完成原包”；核对的仍是这个原输出，缺失／被替换／symlink拒绝，不回落其他路径。展示不重新核验当前全部字节或授权。核到对应原请求的终态后，可明确点“准备新的复制（保留原任务历史）”，仅清本机绑定，重新声明用途、选目录和提交，不删除Core历史或自动复制。损坏本机记录须先显式读取历史，再单独确认仅清本机记录；清除不证明旧请求从未提交。

原完成回执只证明记录时间的完整复制与目的字节重读，仍显示“质量未核验／授权未核验／费用未知”。它不证明现在的文件持续完整、媒体解码、实际NLE导入、成片混音／字幕烧录、文学／视听质量或发行就绪。

FCPXML 和 EDL 当前仅导出视频编辑，不包含音轨／字幕；OTIO 保留各轨的基本片段和间隙，但没有完整翻译静音、独听、音量、淡入淡出或 ducking。SRT／WebVTT 是独立字幕文件，不是烧录结果。兼容性报告明确列出当前缺口，不宣称覆盖所有格式损失或外部 NLE 导入；旧装配来源的导出门仍拒绝失效音轨，不替代上述文件和授权核验。单独读取／导出清单不创建时间线，请先在“多轨时间线”明确建立和保存。

NLE 交付不包含 MP4 成片。独立实验本地混音渲染已在“制作 → 成片渲染”接通明确发起、原请求恢复、取消／原来源同策略重试和冻结结果播放；字幕烧录可在签名工具与原字体实际能力通过后明确选择，完整 Media Gate 尚未完成，并非只有 Provider 声明 `timeline_render` 才能本地编码。实验使用的本地隔离编码工具／字体不等于发行包已配置可用工具或字体授权。正式交付仍请人工验片，实验入口的实际边界见[实验混音渲染的当前边界](#实验混音渲染的当前边界)。

## 可选云审片

在“审核交付 → 审片”中，先创建一个本地审片包，再填写已授权的平台地址和 workspace。短期访问令牌只会在点击“保存安全连接”时写入本机加密凭据库；项目数据库只保存不含秘密的凭据引用，界面不会回显令牌。

点击“选择要上传的媒体”后，逐项确认文件名、相对发布路径、类型和关联分镜。点击“计算 SHA-256 发布预览”会在本机读取这份清单，显示每个文件的 checksum、总存储量和不含秘密的 review manifest；此时尚未创建云端 package 或上传文件。平台会在创建 package 后按 workspace 策略返回到期时间；若平台未提供费用预估，界面会明确显示“未知”，不会显示为 0。只有这份已计算的清单才能点击“确认发布选定媒体”上传到平台返回的私有对象存储目标；不会上传完整 SQLite 数据库、Provider key、授权证明正文、绝对路径或未选择的媒体。发布失败会保留本地审片包，远端 package 会尝试撤销，用户可修正后重试。

发布成功后只显示一次受控分享链接；请按项目规则向审片人分享。审片人的带时间码意见和通过 / 退回 / 修改决定可用“按游标同步意见”回流到本地同一审片包。同步用远端 client ID 去重，重复同步会更新原记录而非创建重复意见；离线、未配置账户或云端不可用时，本地项目、时间线和 NLE 交付不受影响。

已发布的审片包会在本地保留远端状态、到期时间和分享链接。需要收回时，使用“撤销并删除云审片”：应用会先请求平台删除远端审片包及其上传对象，成功后仅移除本地的云端绑定与同步游标；已经回流的本地意见和决定会保留。删除失败时，本地绑定和反馈也会保留，方便恢复连接后重试。

同步到未解决意见或返修决定后，选择本集剧本并提出修改要求，点击 AI 修订。系统读取该审片包的意见、时间码及当前剧本，生成、检查并在必要时局部修订一次。采用后会针对原问题再做一次检查，结果保留来源版本；不会自动替审片人关闭问题。已有完整修改稿可以在“导入已有修改稿”中建立兼容预览。

## 本地创作结果台账

打开“数据洞察”，选择“所属项目”，查看“本地创作结果台账”。小说组分别显示正式章节采用版本、人物／大纲／故事弧采用版本和已保存的稿件版本集合；剧本／改编组分别显示诊断、季纲、标准剧本采用版本与已保存的内部试制包版本集合。两路可以独立使用，不要求小说一定改编，也不要求剧本先有小说或生成视频。

“正式采用”只在对应 owner 已提交正式内容时记录；“已保存”只在 Host 的文件 SHA-256、字节数与 opaque artifactRef 回执匹配并已持久保存成功时记录。候选、预览、放弃、取消、失败、仅下载／返回导出内容或页面点击都不是上述成功事实。普通编辑保存正文也不制造新的“章节采用”；实际人工剧本经独立正式确认才计为新正式剧本。

累计与“最近 7 天”按去重结果单位计量：正式章节／规划／诊断／季纲／剧本使用对象与正式版本，稿件使用所选章节正式版本集合，内部包使用实际正式大纲／剧本／分镜／所绑定剧本文档与制作记录版本集合。相同集合再次预览、换格式或保存新文件，不增加成果数；实际新正式版本才产生新单位。最近七天为以该单位首次权威事实时间为准的滚动窗，不是自然周，也不因重复导出被重新计到本周。采用与保存不能相加成质量或爆款评分。

展开“查看不含正文的权威回执”，可分页查看实际事件、对象、正式版本和去重标识；点击“刷新结果台账”只读重新核对，不生成、采用或保存内容。项目切换按作用域重读；重启从持久 owner 事件回放，不依赖页面缓存或重复生成。投影尚未追平／重试／异常时明确提示数字可能不完整；读取失败不会当成零成果。统计失败不改写已经正式采用或成功保存的内容。

这是开始记录后的本地历史事实，不是当前来源仍有效、合法授权或独立语义质量证书。旧项目此前的生成／采用／保存不会由历史状态或猜测补算，因此“尚无已记录回执”不表示旧项目从未有成果。台账不包含正文、标题、prompt、API key 或绝对路径，不向外部分析服务发送；当前没有外部遥测或同意开关。

“本地首候选与采用耗时”分别显示小说章节、改编诊断、整季方案和标准分集剧本四类记录。分母只纳入开始记录后、同一目标第一个实际请求进入审阅的原候选；没有候选或最初请求未记录时不补为 0%。小说按章节、剧本按正式单集的稳定身份区分目标，诊断与整季方案按项目区分；来源变化、重试、重新生成、复检或人工合并不重置首轮。页面单独列出待决定、已结束未直接采用、改写后采用、后续候选和采用被拒，失败或取消不会变成成功。

只有正式内容 owner 的采用事实与原候选 ID、内容指纹和工作流全部一致，才算“原首候选直接采用”。人工编辑正文或重排季纲后采用仍是有效正式成果，但不冒充原首稿直接采用。当前占比包含尚待决定的分母，是截至当前的本地记录，不是公开产品采用率、文学质量或受控／真实模型的比较；运行分类目前明确未知。

首个有完整对应证据的正式采用显示“请求至候选”“审阅至采用”“请求至采用”三段实际耗时，并区分原候选／改写候选。审阅时间包含人工操作，不能当作模型纯生成速度；重启不会重置起点。时间倒退标为异常／未知，不裁成零；历史缺少真实请求或候选事件时不补造耗时。刷新和切换项目仍只读，不派发、采用、保存或向外部发送数据。

“本地七天续写观察”将当前项目与全本地有记录项目分开呈现。小说从首个有完整 owner 采用记录的正式章节建立窗口，只有准确上一正式版本被明确纳入实际上下文、目标在实际目录中紧邻且引擎接受了真实 run／session，才记录下一章启动。剧本从实际第一集正式标准剧本建立窗口，只有同一明确季纲或当前直写分集目录的实际第二集启动才计入。空目标、预分配运行标识和会话接受前失败不是启动；已经接受会话后失败仍保留实际启动，下一目标正式采用另计。

每项目、每路各固定一个七天 UTC 观察窗。重复采用、修订、重试或保存不重置起点；准确后续来源版本须有自己的正式 owner 事实。当前项目展示开始／满窗时间、实际请求／本窗启动／后续正式目标与未关联本窗记录。未满七天一律“待观察”，即使已经续接，也只显示提前续接，不进入正式分母。满窗继续率只按已满七天的 eligible 项目计算，不按章节／工作流次数计算；没有满窗分母是“未建立”，不是 0%。历史缺少完整锚点保持未知，时钟倒退／未来证据排除，晚启动不能补成七天内成功，不把“未记录窗内启动”声称为文学创作失败。

全本地汇总不包含其他项目的 ID／正文／提示词；两路独立，不要求小说一定改编。刷新仍是只读，投影滞后与读取错误明确提示，不产生新计数。七天窗不是上方“最近 7 天”的滚动成果窗，也不是公开留存率、叙事质量或真实模型对比。真实模型对比／费用汇总、叙事质量率与其余指标仍未完成；不由引擎名推断受控或真实模型。七天观察的原实施见根 PLAN 第22.50节，原请求与逐阶段报告的只读关联见第22.185节；MET-01和整体计划仍在推进。

### 正式采用版本的交付覆盖

在“数据洞察”选择项目，点击“读取采用版本交付覆盖”。系统明确只读全部已记录成果页，小说按“章节正式版本 → 已保存稿件”，改编按“剧本正式版本 → 已保存内部试制包”分别关联，不将两个独立计数相除。

只有保存事件之前已记录采用、对象与正式版本完全相同，才计入已交付分子；顺序来自原owner事件游标，不用墙钟推算耗时。重复保存／换格式不多计，旧版保存不替代新版；未找到匹配保存的采用版本仍在分母。没有已记录采用版本时覆盖率未建立，不补0%；已保存但没有此前采用关联的版本另列，不补造采用。展开可看原版本、首次采用／匹配保存事件和保存版本集合数。

读取前后核原投影检查点、全部去重单位总数和原首页，未追平／失败／分页不完整或变动拒绝本次结果，需明确重读。单次最多10万事件，超限不返回部分分母；停止、重读或切项目清旧结果，迟到回复不恢复。不启动模型、采用、导出或外发；这是已记录历史版本的保存关联，不是当前有效性、质量、授权、实际投稿或发行完成，也不是每周留存／模型质量对比。小说不要求改编／媒体，无媒体改编仍可保存内部包。限定工程证据见根PLAN22.215。

### 七天首次交付与采用后保存耗时

同一卡片点击“读取七天交付与保存耗时”，按本次读取前Core summary的原asOf冻结UTC七天滚动窗（含首尾，不是自然周）。小说章节版本和改编剧本版本分别显示本窗新增采用、本窗首次匹配Host保存；旧采用本周首次保存可以计入交付，重复保存／换格式不刷新首次时间。两项是跨期计数，不能相除为本周转化率。

耗时按原首次已记录采用事件到首次匹配Host回执的savedAt计算，须采用时钟≤Host保存时钟≤owner保存事件时钟≤原asOf。真实零保留；未来、倒退、回执先于采用／晚于owner，以及不能精确表达成毫秒的非零亚毫秒时间分别保留异常／未知，不裁零或挑后一次“好”保存。待保存与异常分别列出，可核历史版本才参加范围和BigInt精确分数均值；均值不是仅本周样本，也不包含没有此前采用的保存版本。

此操作复用上一节的完整只读分页和前后检查点／原首页／累计单位核对，不额外调用模型、采用、导出或外发。失败、停止、重读与切项目清掉两种旧读数，迟到回复不恢复。时间包含人工操作／等待，不是模型速度、从任务开始到交付的全程效率、每周留存、文学质量、授权或实际投稿／发行证明。原覆盖入口及旧结果格式保留，工程证据见根PLAN22.216。

### 原请求与逐阶段运行关联

在“数据洞察”选择项目后，点击“读取原请求台账”，再选择明确的原工作流。此入口包括开始记录后的小说／改编和独立人物、大纲、故事弧、知识规划请求，也保留失败和重试；没有原请求的旧资料不会被补造。请求和工作流历史各有自己的“读取更早”分页；候选指纹、正式版本或完整规划采用批次保留原身份，不增加既有成果数或改写正文。

生成、检查、修订和复检分别显示各自原run／会话／上下文、发生时保存的请求模型配置、状态及实际起止耗时。请求模型不证明服务实际使用的模型版本，人工采用不等于文学质量通过。缺记录、读取能力不可用、原读取失败以及原时钟异常分别提示，不切最新运行、不补成功或零耗时。重新进入原工作流会重新只读核对，读取等待或失败不把旧缓存当作当前结果；切换项目后旧返回不进入新项目。

每阶段先显示最近25条原用量观测，可展开“单独读取原阶段全部用量分页”明确重读和翻页。引擎报告的0、未报告和无效值分开；会话累计不是本次运行用量，USD／EUR等原币种估值也不合计成账单。整个入口没有自动生成、采用、重试或外发遥测；模型来源仍未知、质量未核验、费用结算未知。当前本地定向／构建／后台证据见根PLAN第22.185节，不代表完整指标、真实质量或发行验收。

“原尝试配置分组与运行统计”只统计当前选择的原工作流尝试，按回执中的引擎、请求模型ID、服务ID和配置档ID归组；字段未记录与原配置无效分开，不使用当前设置补齐。这不是完整超参数指纹、实际模型版本或全项目模型成功率。同键重试的新工作流另计，不把原失败阶段搬到新尝试中。每组列原阶段、状态、run ID及可核耗时分母；耗时范围只比较有原起止时间的阶段，缺失、异常或未结束不补零，也不相加为工作流总耗时。“已记录修订阶段”不等于达到采用所需的局部修订次数。没有回执时统计分母未建立；回执记录了缺失run时仍保留该身份，不猜阶段或配置。统计不增加请求、不读取额外模型或汇总用量／费用；本组证据见根PLAN第22.186节，完整MET-01仍在推进。

### 候选正文实际修订次数

单章创作工作流或写作对话的候选卡片提供“查看候选正文实际修订次数”。它按明确原预览读取已保存正文修改、显式合并以及其中实际改变正文的合并次数；相同内容重复保存不计数，回改原文仍计一次。完整原候选链才显示局部修订总数，已正式采用与尚未采用分别标注；旧记录缺历史则显示未知，不补造零。坏台账、来源缺失或读取失败不显示旧成功，也不切换最近候选。

这不是模型“局部修订”阶段次数、未保存的编辑动作、人工工作量或全部生成重试的总量，不证明文学质量。这个入口仅支持单章候选原链；章节跨尝试统计见下一节，改编／独立规划仍在推进。此只读操作不会启动模型、采用候选或外发台账，证据见根PLAN第22.211节。

### 首次章节采用前实际修订

在Insights的“本地创作结果台账”点击“读取首次章节采用前修订”，本机明确只读当前项目全部已记录章节目标分页。每个目标保留放弃、失败及重试候选的已保存正文变化，只统计首次已记录正式采用事件之前；采用后的新编辑不并入。相同保存不多计，显式合并次数与其中正文变化次数分别展示。完整历史才显示修订总数；没有正式采用为总数未建立，已采用但历史／原关联不完整则总数未知，不能当零。

原采用事件、章节版本和全部原请求身份可查看。较早的旧采用不会被跳过以改用后来一次成功；缺关联仍显示原事实与未知总数。读取失败、取消或项目切换不展示部分分页或旧成功，需明确重新读取。它不会调用模型、修改或采用正文、外发台账；模型修订阶段、未保存操作及人工工作量均不包含，不证明文学质量。目前为小说章节，候选正文实际合并已计，改编／规划另行推进，限定证据见根PLAN第22.212节。

### 按原配置分组的章节修订

同一卡片点击“读取按原配置分组的章节修订”，本机明确只读完整修订页、原请求和工作流回执，可能需要等待。按每章节目标最初生成阶段保存的引擎／请求模型／服务／配置档字段分组，换模型重试仍留原目标组，不表示全部尝试使用同一模型。原配置无效、未记录或回执缺失分别保留，不用当前设置补齐。

每组列完整可核采用目标数、已采用但历史未知、尚未采用，以及可核修订范围和精确分数均值。只有完整已采用目标参加均值，真实零保留，未知／未采用不补零；“3/1次”表示可核修订总数3、完整已采用目标1，不是采用率。展开可看原目标、全部尝试及原采用事件。读取失败、停止或切换项目不显示部分／旧结果，迟到回复也不恢复统计。不调用模型、自动采用或外发，不认证实际远端模型版本、完整超参数、人工工作量、文学质量或账单；改编／规划另行推进，证据见根PLAN第22.213节。

### 全项目原请求配置漏斗

点击“读取全项目原配置漏斗”后，本机按顺序只读全部已记录原请求页及各工作流事实页，可能需要等待；可点击“停止本次读取”，或切换项目取消。它不启动模型、不自动重试，也不发送台账到外部。结果按每个目标最初请求的**生成阶段**引擎、请求模型／服务／配置档字段归组，后续重试即使改模型也仍归该最初目标组；这不表示组内所有运行均使用同一模型。其他阶段的原配置仍在单工作流界面独立列出，不补作完整超参数或实际模型版本证据。

当前模型选择仅支持 `providerId`、`modelId`、`profileId`，各字段去掉首尾空白后最多200字符。模型设置、会话、创作预检／启动和三引擎盲测会拒绝额外参数，不会静默忽略 `temperature`、`maxTokens`、`reasoningEffort` 或 `seed` 后继续运行。拒绝不等于这些参数已实现；旧记录也不会补出参数或远端实际模型版本。M5真实评测协议须只写实际支持／记录的参数，未知的引擎内部默认值仍标未知。

小说章节／改编与独立小说规划分别保留自己的漏斗单位，规划按完整采用批次而非单条资料计量。每组展示原请求与目标、首候选、原候选直接采用、待决定、已关闭未直接采用、修改后采用、重试候选及首次正式采用的原事件／工作流／耗时。首候选比例仍包含待决定，不是公开模型质量或采用率；缺少最初请求时不借重试候选重建首候选分母。原回执缺失、不可用、读取失败和生成阶段未记录各列未知组；已发生的人工采用事实不会因此变成模型成功证明。时钟异常的耗时保持未知，不推算首目标到重试的总历时。

所有页必须核对原项目、唯一工作流、完整分页链、原请求、原事件游标和相同投影检查点，结束再核原请求头；任一读取失败、取消或检查点变化都不显示部分结果或旧分母，需明确重读。投影未追平会提示：读完全部已记录页不等于历史事实全部存在。这里不是跨所有owner的事务快照、全项目实际模型比较、Token／费用汇总或文学质量验收；MET-01其他指标和可信来源仍继续。本组定向／后台与正在执行的完整回归分别记录在根PLAN第22.187节。

## 原运行用量报告

AI 工作台和普通对话可点击“查看原运行用量报告”，只读核对指定 run 的已保存引擎观测。零是引擎明确报告的数值；“未报告”和“报告值无效”不换算为零。每条注明单响应增量／运行累计／会话累计／未指定口径及输入是否包含缓存；会话累计不是本次运行用量，页面不将这些报告相加为总量。无历史报告是未知，不表示从未调用。报告发生时的全局／项目范围保持，对话后来绑定项目不会回写旧报告归属。

报告覆盖可能不完整、引擎自行报告也不证明实际付费；运行来源分类、费用与结算明确未知，没有默认币种或虚构价格。控制接口提供的测试报告不是实测 token／账单，真实文学质量仍需独立判定。明确重读／翻页不生成、采用、保存内容或启动模型；读失败时旧报告只作历史查看，不自动切换运行，后台重启后仍需明确读取。候选正文与原项目不会由用量操作改写。该普通原运行观测按 PLAN 22.91 限定工程范围完成，完整工程、同构建后台 40 项和随后隔离恢复通过；旧盲测／灵感整理的用量消费另行接续，不视为已经迁移，MET-01 与完整 PLAN 仍继续。

盲测与灵感整理的接续见 PLAN 22.92：盲测先明确评议、再明确揭盲，只有揭盲后才能查看该候选自己的原运行报告；不会在揭盲前显示有识别性的引擎计量。灵感记忆中心不再把预算／字符长度或历史整数相加为实际 token，逐次整理或重试有独立原运行记录。失败也可保留已经收到的报告，缺报告仍未知；点击查看只读历史，不触发“重新整理”，重启后不自动读报告或调用模型。此独立观测按限定工程范围完成，当前完整工程、同构建后台 41 项及随后隔离恢复终态通过。插件停止时的在途任务释放继续单独验证；不表示真实付费、完整覆盖、文学质量或整个任务完成。

## 集级节奏看板

在“改编”页面选择分集后，可同时查看节拍密度、爽点、反转和结尾悬念四条轨道。看板会从当前分集、剧本、节拍、场景和镜头建立同一条可追溯时间轴；没有来源时会显示空态，而不是生成无依据的分数。每个点都能返回关联剧本，并标明规则派生或人工确认、来源版本和 stale 状态。

可为任一轨道新增人工标记，也可调整或否决已有标记；记录会保留在审查历史中，来源改变后会显示“来源已变化”。对已关联剧本的规则诊断点，可创建“上下文 AI 修订预览”：智能任务只会在任务中心产出待确认的变更预览，采用前不会改写权威剧本。采用涉及剧本文本的建议会自动留下“节奏修订预览采用前检查点”；可在看板中恢复该检查点，恢复前也会先保存当前版本。

## 编辑器旁的 Story Bible 侧栏

在项目章节编辑器和已选剧本的审阅区，Story Bible 会按当前内容关联人物、关系与设定、时间线、伏笔、已锁定的视觉资产和章节记忆。它只读取已保存资料；搜索、固定、折叠和宽度偏好都会按项目保存。没有关联资料时会显示空态，本地服务暂不可读时也不会阻止继续编辑或保存正文。

每条内容都会标明权威事实、人工确认、AI 建议或来源已变化，并可跳转到完整的 Story Bible 页面。章节侧栏可生成待确认变更草案，展开“查看字段差异并选择采用”后，勾选章节摘要、重要事件、人物变化与秘密或伏笔字段；采用仍经同一个本地变更包事务写入章节记忆，不会改写正文。正文版本变化会阻止采用并标记 stale；“撤销采用”也只删除该变更集创建的资料。

## 模型服务商

“设置”页面最上方是“模型服务商”。选择 OpenAI、Anthropic、Google Gemini、DeepSeek、Kimi、MiniMax、Mistral AI、xAI Grok 或 OpenRouter 后，再从联动列表选择模型并填写接口密钥即可；接口地址和协议由应用随版本内置。

需要连接兼容接口、私有网关或目录外模型时，选择“其他（全部手动填写）”，手动填写服务商名称、服务类型、模型名称、接口地址、协议和接口密钥。常用服务商连接成功后，应用会把账号实际可用的模型合并到模型列表中。

接口密钥通过桌面安全凭据接口保存，业务数据库只记录凭据引用。编辑已有配置时可以不填写密钥，以继续使用原密钥；若本机凭据存储不可用，应用不会退回明文保存。

模型目录随桌面版本发布并显示最近核对日期。每次提升应用版本都必须重新核对官方目录、模型标识和下线公告，否则发布检查不会通过。

## 智能引擎

在“设置 → 智能引擎”中查看 Pi、Codex、LangGraph.js 的状态、版本与认证方式，并设置全局和项目默认引擎、模型。Pi 是默认内嵌 Agent Harness；Codex 可使用安全保存的 OpenAI API Key、ChatGPT 浏览器登录或设备码登录，也可以绑定“模型服务商”中已经保存的 OpenAI 兼容文本服务商，因此不要求用户拥有 ChatGPT 账号。LangGraph.js 复用当前已保存的 Provider 凭据，并支持 OpenAI、OpenAI-compatible、Anthropic 和 Google。

Codex 0.164.0 的自定义服务商通道支持两种模式：Responses API 直连，或在本机把 Chat Completions 转换为 Responses。设置中心会列出已保存的 OpenAI 兼容文本服务商；仅支持 `/v1/chat/completions` 的厂商选择“Chat Completions：本地转换”即可。转换模式兼容范围更广，但 Codex 的部分 Responses 专属高级能力可能受限。

智能助手默认使用“简洁模式”：它只显示当前页面最相关的 1–3 个动作、所需项目/章节输入、引擎能力和费用状态，不要求选择引擎、模型、任务或盲测参数。每个推荐动作仍使用同一份受控任务目录和不可变上下文快照；生成结果只会进入任务中心的预览或变更包，绝不会自动采用。

需要精确控制时，选择侧栏中的“高级模式”。高级模式保留完整任务目录、显式引擎和模型选择、任务要求，以及 Pi、Codex、LangGraph.js 三引擎盲测；该模式偏好按项目保存，可随时切回简洁模式。失败只会显示所选引擎的中文错误，不会自动改用其他引擎。任务详情可查看实际输出、工具调用、中断和恢复；Token 与费用只在对应权威运行记录实际提供时展示，未知不补为 0，预算或 estimatedCost 不冒充实际消耗。当前小说／改编创作主链的持久用量与实际费用计量仍未接通。

三引擎盲测必须由用户主动发起。开始前会显示三次调用的预估 Token 和费用说明，可选择“各引擎推荐配置”或“三个引擎使用同一模型”。创建实验前会并发预检 Pi、Codex、LangGraph.js；任一未配置、未认证或不健康时不会写入实验或调用模型。新实验随机映射为 A/B/C；评价前只显示候选编号，用户提交评分、偏好和接受结果后才可单独执行揭晓。媒体厂商调用始终先生成预览；预估金额或币种未核全时，确认创建远程任务保持禁用，直到重新获得明确记录。即使记录齐全，它也不是实际报价或账单的真实性证明。

## 内容修改与远程生成

写作、角色、大纲、剧本、场景、镜头和 Story Bible 的智能修改只生成“内容变更预览”。核对差异后点击“确认应用”才会写入正式资料；目标版本变化时会要求重新生成或人工合并。

小说、图片、音频和视频的模型推理通过已配置的远端模型／厂商 API 或远程部署的服务执行，不在本机运行生成模型。智能引擎对媒体任务只能提出厂商、模型、参数、提示词和费用建议；用户完成所需确认后 Runtime 才创建远程任务，估算不能代替可核对的实际报价。

当前另有明确标注的实验性混音 MP4 编码路径，要求本机已有通过签名与实际混音能力校验的工具、完整冻结来源与显式操作；它只是把已有素材编码为文件，不是本地视频生成模型。字幕须明确不烧录，或在原签名字体实际能力通过后明确选原字体烧录；这些能力不代表完整 Media Gate 或发行支持。工具／字体不可用或来源校验失败时明确阻止，不自动下载安装、降级为静音／无字幕或改用其他来源。限定实现与后台验证见根 PLAN 22.190–22.195；旧静音版本历史见 22.44–22.48。

# 专业创作工作台

首次打开时，可提供创意、导入已有来源或打开示例。建立项目、保存创作要求和浏览资料不需要先配置 AI；生成内容前连接所选引擎与模型。连接后回到原对象，再由你明确发起生成。再次打开应用时，项目库首先显示上次工作对象、待确认结果和最近项目；点击继续即可恢复该项目保存的章节或制作位置。

左侧栏分为全局入口和当前项目入口。全局入口包含项目库、灵感、待确认、搜索、任务和设置；项目入口包含概览、故事、改编、制作、审核交付及已启用插件贡献的其他功能。顶部项目选择器会为每个项目单独保存位置。常规工作对象已删除或不属于当前项目时，应用会回到最近有效父级并显示原因；指定待确认对象的精确链接则显示读取失败、删除或错归属原因，不用其他候选代替。

章节默认进入 AI 创作工作台：左侧章节目录，中间阅读方案、候选或定稿，右侧点选创作操作、补充要求、查看实际引用和检查结果。目录、正文与右栏独立滚动，右栏输入和主操作固定在底部。窄窗口通过“智能写作”打开临时抽屉。选中正文后，可以向 AI 提出局部修改要求；正文微调与导入修改稿收在“更多操作”，阅读参数在“阅读设置”中。

任务中心将内容分为“待确认、进行中、需要处理、历史”。主动取消会进入历史；失败可标记为已处理。可恢复操作通过“返回原操作”交给所属业务执行器；视频重试会恢复原服务商和输入，并要求重新完成静帧、资产、权利与费用预检。

项目模式代表持久的创作意图，不能原地改写。在“故事 → 项目设定”中可先预览，再建立带来源关系的派生项目。系列长篇派生单季短剧时，需要先选择一季。

## AI 创作的执行、采用与恢复

每次内容操作会冻结项目、目标对象、来源版本、要求、引擎和模型。Runtime 自动完成生成与检查，必要时只做一轮局部修订及复检，随后等待审阅。结构无效不会显示“待审阅”；仍有内容争议时保留候选与问题，由你决定下一步。关闭页面不取消运行，任务中心、对象页和助手指向同一个持久候选。

执行时，右栏顶部显示实际步骤、已用时间、资料读取状态和逐步返回的内容；检查与修订阶段同步更新。首段内容返回前会显示等待模型响应，不显示推测的完成百分比。重新打开页面可以继续查看已返回内容；失败或停止后，已有片段保留供查看，正式正文只在采用后更新。持续有进展的生成不再被固定的两分钟时限截断；连续五分钟没有进展或单次运行超过三十分钟时会请求停止并说明原因。

“采用”只应用当前单位。“采用并生成下一章”才会承接已采用内容创建下一章。首集试制保留 1–3 集范围，默认 1 集；确认来源后会启动第一集的真实 AI 工作流。后续集数需要在试制分集选择器中选择并明确生成。

人物、大纲、设定、博主选题与脚本作为完整方案包审阅。小剧场需要先完成人物授权，再进入故事、剧本和分镜生成。素材权利、付费媒体提交及对外发布仍需独立确认。

采用章节后，系统根据该版本正文提取有原文证据的摘要、事件、状态和伏笔。界面显示资料更新中、已同步、待审阅或失败。未采用候选不进入正式记忆，来源版本变化的派生事实不会被当作有效上下文使用。

独立小说可按“人物 → 全书大纲 → 正文候选 → 明确采用 → 记忆同步 → 续写下一章”持续创作，再从“输入输出 → 导出投稿包文档”确认稿件范围与权利声明，核验保存。原稿/候选稿切换只改变阅读预览，不自动保存或采用候选；第二章候选在重启后仍可回到该章审阅。没有候选时，打开“微调正文”可以编辑作者稿，后续修订会使旧采用、记忆及稿件清单不再代表当前版本。该路径不要求创建改编、分镜或媒体对象。当前本地受控模型接口已验证这条桌面工程闭环，不代表真实模型的文学质量。

候选与当前版本冲突时，正文采用保守的文本三方比较；剧本按稳定块标识比较。独立新增内容予以保留，冲突需要明确选择。剧本合并后重新检查，再产生新的待审阅候选。关闭比较窗口保留原候选，放弃候选不改变定稿。

保存剧本修订的块顺序接续已按 PLAN 22.83 的限定范围验收完成，末版正常完整与同构建后台 30 项均通过，无视觉基线更新。比较窗口把“正文冲突块选择”和“完整块顺序核对”分开：单方或一致的顺序可保留，两个新增块争用同一位置或双方重排不一致时，不会猜相对位置。可以分别以当前稿或候选顺序为排序起点，再上下移动；另一侧仅有的保留块放在草稿列表末尾供你安排，并不表示系统已经批准它的位置。明确核对全部保留块的增删与顺序后才可提交，改变正文选择或排序会清除本轮确认。合并只产生复检候选，仍须另外点击“采用”。

比较与采用都核对同一实际文档／记录及准备上下文，变化会拒绝，不自动改读最新。发送后若回复不确定，页面显示“原剧本合并请求恢复”；重启不会自动 POST，须明确“重发原合并请求并核对回执”。它重发原正文选择、顺序、比较哈希和同一幂等键：已成功只返回同一候选，尚未成功仍可能启动原请求，不是只读按钮。记录不保存剧本正文、凭据或批准，不能恢复其他项目／剧本／原候选。仅删除本地重发记录不会撤销服务端候选；须从实际运行另行查看、采用或放弃。缺失或格式不明的原记录不自动替换；历史比较无顺序协议也不补造确认。当前机制不是叙事语义安全、任意场景／镜头拓扑或发行质量证明。

图片和视频提示可直接从已采用镜头读取，配音可从结构化剧本选择台词并匹配已有角色音色。AI 本地化输出在没有可靠时间信息时标为待对齐草稿，可导出 TXT。SRT/VTT 必须包含有效字幕时间段；系统不会伪造固定 5 秒字幕。MP4 仍取决于实际媒体与渲染服务商能力。

影响清单的读取边界按 PLAN 第 22.80 节已限定验收：点击“核对变化影响”或“重新核对变化影响”会明确重读该原正式分镜成果，不取最新成果替代。读取等待、失败或返回身份不符时不显示上次清单；恢复网络后仍须明确点击重读。离开／返回工作台后的迟到回复不自动打开清单。原 stale 历史与全包需复核原因仍保留，未观察到关联变化不证明语义安全，不解除失效包门或自动重做；本增量实际三文件十三项后台及隔离恢复检查通过；完整语义影响／结构性重做仍另行推进。

本轮还新增“上游正式约束版本核对”（PLAN 22.81，限定只读验收完成）：明细按本包实际绑定显示原冻结与当前正式身份、版本和已知指纹，区分换头、版本／顺序变化、批准设定新增／移除与读取未核全。直写仅显示实际项目／分集／原稿等独立约束，不补季纲或诊断；没有保存文档明确显示未记录，不为核对初始化。旧清单未提供明细时明确缺失，不代表空集合或已核全。身份版本未观察变化不证明正文或语义不变，当前来源失效和全包复核仍有效，不自动换源、采用、改稿或重做。

PLAN 22.84 的“实际场景与镜头字段基准”已按限定范围通过普通完整与同构建后台 30 项验收，无视觉基线更新：点击“核对变化影响”并取得本次真实清单后，可展开查看原采用结果、冻结／当前记录版本、父级／顺序和字段组指纹。该指纹明细不显示作者正文或自定义字段原值，不执行合并，也不确认语义安全。旧结果未存基准会明确说明，不能从模型方案补造旧人工内容；基准损坏、实际缺失、版本或同版本字段变化都会保留原记录并要求复核，不自动改成最新。下述第 22.85–22.86 节字段比较／明确选择是另一个受限流程，不能仅凭指纹明细覆盖人工新稿或判断发布就绪。

作者场景镜头计划（PLAN 22.88，限定工程验收完成）是独立的新模式：勾选“按作者场景镜头计划重做”，逐场纳入全部原镜头。复用者显示实际记录和版本；“新增镜头”产生新身份，初始 1 秒须自行调整。可以上移／下移／移除计划镜头，逐镜明确整数秒数及既有资产勾选，各场总秒数必须仍匹配正式大纲，不能增删场景、跨场移镜或补造资产。这里的资产是原分镜方案的定义，不代表已经生成、锁定或获得授权的媒体文件。确认基准只保存元数据，不调用模型；模型只能生成这份计划的表达、字幕与局部风险。修正后完整工程、固定后台 38 项、隔离恢复检查与截图核对已通过，首次失败分开留证，没有更新视觉基线。

生成后审阅“冻结作者镜头计划”，逐一核对新／复用身份、顺序、时长和资产，再另行明确采用。作者标题与私有自定义字段保留，未选场景不改；移除的原镜头采用后退役，实际记录和旧正式快照仍可按原 ID 读取，关联旧素材须复核而不是删除。退役不能普通编辑、删除或作为新媒体来源，也不会自动取消正在执行的付费任务。人工实际字段／正式来源再变化会拒绝整个采用，不能借原固定块／确认块字段合并处理这个新范围。后台重启保留已确认计划和同一候选，不自动生成或采用；此流程不证明语义安全、费用、权利或发行质量。

保持块结构或明确已确认场内块结构模式的“选中镜头局部候选”仍待审阅时，可点击“比较实际字段”，只读查看标题、场景动作及七项镜头创作文本的“原实际字段／当前人工记录／冻结候选”。原字段来自正式采用时保存的真实行，不是模型重建；自定义字段不显示，归属、顺序、时长、资产和来源不可在这里修改。先展开对应字段详情，再明确选择两侧之一；真正冲突没有默认，非冲突默认也可调整。标题和场景动作独立于镜头文字，须核对彼此一致性；机械规则不能证明语义安全。

作者镜头计划模式的字段合并（PLAN 22.89，限定工程验收完成）使用专用新协议，不借旧固定块／确认块协议。候选中点击“比较实际字段”，会只读显示原计划中的新增／复用／待退役身份、实际版本、顺序、秒数和资产方案引用。只有原场景及复用的实际镜头有三方文字选择；新增没有旧记录，待退役者保留当前历史标题／私有原值，不补造原字段或提供删除正文的选择。结构仍以先前明确冻结的计划为准，不能在合并时顺带修改。逐项选择与披露后仅复检新合并候选，再另行采用；重启或响应丢失只保存无正文的原选择、哈希和同一幂等键，明确重发恢复原运行。正常完整工程、同构建十一文件后台 38 项及随后隔离恢复终态通过，最终截图核对无私有旁注或基线更新；不是公开质量、真实费用或发行保证，完整父范围仍继续。

已确认块结构模式使用单独协议，比较中会只读显示原／新场内块映射、正式剧本及实际文档版本和结构指纹。这里只采用原局部候选已经冻结并核全的映射，不能通过字段选择改变来源，也不会自动把旧固定块候选升级为新协议。场景／镜头身份、数量、顺序、时长和资产仍不变；当前人工记录的保护结构、未选范围或确认链改变则拒绝，不能用此入口处理更大拓扑变更。

逐项审阅后，勾选所选文字将按原配置送模型复检的明确披露，再点击“冻结字段选择并复检”和确认。完整原来源、所选新文字的隐私／预算以及所有实际字段指纹重新核对；任一遗漏或变化则拒绝，不自动换版本、裁剪文字或重生成。成功生成单独合并候选，仅复检冻结选择，正式记录仍不改；通过“打开字段合并候选”核对全部冻结字段，再另行采用。采用时再变仍拒绝，作者自定义数据保留，未选记录不写入；这不是自动内容优化或文学质量保证。

响应丢失时保留“字段合并原请求恢复”。本地只保存原身份／选择／哈希和同一幂等键，不存正文；已确认块结构原请求额外绑定结构指纹，不存可编辑映射。重启不自动 POST，须明确“重发字段合并原请求”。它恢复同一真实运行；未受理的原请求仍可能启动复检，不是只读按钮。放弃本地原请求仅移除该本地重发记录，不删除服务器候选／正式稿，可从任务查看实际运行。读取失败不拿旧缓存代替；历史缺原基准、保护结构变化、未选镜头新稿与来源变化不能自动升级。当前受控工程终态与失败记录见 PLAN 22.85–22.87，不代表文学质量、真实模型费用或发行就绪。
