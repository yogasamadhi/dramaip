# Desktop 专业创作工作台实现基线

> 历史说明：本文保留 2026-09-05 的实现记录，其中“先手动写正文、再按需 AI 修订”及默认专注写作不再作为后续设计目标。当前产品定位、核心层级与主路径以 [产品定位](../../../docs/product/POSITIONING.md) 为准；阶段实现及验证见 [2026-09-06 AI 核心流程执行记录](./AI_CREATION_IMPLEMENTATION_2026-09-06.md)。

本文记录 2026-09-05 整体体验重设计的实现约束、入口映射和验收数据。它与 `DESKTOP_UX_REVIEW_2026-09-05.md` 配套使用；架构决策仍以仓库根目录的 Desktop Runtime 架构文档为准。

当前口径中，小说作者能独立完成章节、续写与稿件/投稿，改编团队完成剧本与试制交付；下文单条历史“产品验收主线”不能覆盖这两类目标。2026-09-30 校准只明确阅读边界，不重算历史测试或宣告 [新执行计划](../../../docs/PLAN.md) 已完成。

## 产品主线

第一条产品验收主线固定为：

1. 新建、示例或导入内容；
2. 写作并安全保存正文；
3. 生成和人工确认 AI 修订候选；
4. 明确建立 1 集试制范围；
5. 完成结构化剧本、场景、分镜与素材预检；
6. 定位审核问题并回到来源修订；
7. 预览和导出字幕、剪辑交换文件、媒体清单及可用交付物。

MP4 仅在真实服务商明确提供渲染能力并完成文件校验时显示。没有该能力时，产品应列出可导出的项目文件和仍需在外部剪辑软件完成的步骤。

## 应用框架与视觉变量

- 桌面宽屏使用 224 px 项目导航、紧凑上下文栏、内容工作区和 360 px 可停靠助手；导航可折叠为 64 px。
- 1280 px 以下助手进入临时抽屉；1080 px 以下项目导航进入抽屉。
- 视觉使用石墨中性色和低饱和铜橙强调色；浅色、深色和跟随系统均使用同一语义变量。
- 页面内容默认 14 px，正文编辑默认 18 px。状态信息必须同时提供文字，不单独依赖颜色。
- 阴影用于菜单、抽屉和需要从画布上浮起的区域；普通工作区使用边框和背景层级。

控件和异常状态的可运行样例位于 `/ui-showcase`，覆盖导航、编辑器、任务、候选差异、空态、加载、失败、警告、成功和冲突。

## 旧功能到新入口的映射

| 原有能力                             | 新入口                     | 上下文规则                                                   |
| ------------------------------------ | -------------------------- | ------------------------------------------------------------ |
| 项目列表、示例、导入、创建恢复       | 项目库                     | 首访显示三个开始动作；回访显示继续、待确认和最近项目         |
| 小说首页、章节、大纲、人物、设定     | 项目 → 故事                | 专注写作默认收起内容目录和助手；项目保存独立布局             |
| 创作分析与项目工具                   | 项目 → 创作工具 / 创作分析 | 保留插件贡献和原深链接                                       |
| 改编方案、分集、剧本、场景、分镜     | 项目 → 改编                | 继续使用结构化 `ScreenplayDocument`                          |
| 资产、静帧、音频、视频、时间线       | 项目 → 制作                | 导演看板为默认入口，完整依赖图按需展开                       |
| 质量、合规、本地化、审片、交付       | 项目 → 审核交付            | 依次组织为问题与阻塞、合规复检、预览与修订、字幕、导出与发布 |
| Agent 任务与内容候选                 | 全局 → 任务                | 待确认、进行中、需要处理、历史分开统计和分页                 |
| 服务商、引擎、主题、备份、扩展、账本 | 全局 → 设置                | AI 连接、外观与编辑、数据与备份、扩展、高级诊断              |

应用菜单仍由已启用插件的贡献清单生成。原 URL 和深链接在解析后进入新框架；项目切换会恢复该项目自己的最后位置，并清除不属于新项目的下级对象。

## 状态与数据安全基线

- 项目进度来自 `/api/v2/projects/{id}/progress`，按明确试制分集和真实父子关系聚合。项目、分集、场景和镜头范围不能互相替代。
- 任务执行状态与提醒状态分开。主动取消进入历史；已处理失败不再占用提醒；结果状态读取权威预览记录。
- 通用任务表不能伪装取消或重试。支持恢复的业务执行器保存原服务商、模型和输入快照；付费视频重新提交必须重新通过静帧、资产、权利和费用预检。
- 正文草稿、已保存版本、生成快照和 AI 候选分别保存。每个文档串行提交；旧响应不得清除新草稿或把新输入标记为已保存。
- AI 生成期间正文保持可编辑。失败、取消、延迟事件和页面切换均不得恢复旧正文。
- 采用候选前先保存当前草稿；版本变化时创建新的 rebase 候选并保留来源，冲突内容必须人工选择。

## 固定验收数据与测量

功能验收至少覆盖 100 个项目、单项目 1000 章、单集 500 镜头和 10000 条历史任务。章节目录每次最多增加渲染 100 项，任务工作列表使用 25 项游标分页；其他大列表应沿用所属接口的分页或局部渲染。

性能结果必须记录参考机器、提交号、数据生成方式、冷启动、典型章节打开、列表切换和持续输入。目标是典型章节打开 P95 小于 1 秒；在没有固定机器实测数据前不得标记为已达成。

视觉基线由 `tests/electron/lm7-ui-visual.spec.ts` 生成，覆盖 12 个主要界面的浅色和深色截图、1440×920、1280×800、1080×700 及 200% 缩放。更新截图前必须使用隔离的 `DRAMAIP_E2E_USER_DATA`，不得使用个人项目数据库。

## 发布证据边界

本地自动化可以证明界面旅程、Runtime 合约、生成客户端和结构化导出。macOS、Windows、Linux 的签名安装、升级恢复，真实 NLE 导入、真实服务商和 MP4 仍需受管发布环境的外部证据；缺少这些证据时保持 RC 状态。
