# Desktop 全产品 AI 核心定位审计

历史审计日期：2026-09-05。下文保留整改前证据；2026-09-06 的阶段实现与验证范围见 [执行与验收记录](./AI_CREATION_IMPLEMENTATION_2026-09-06.md)。当前产品定位与优先级以 [产品定位](../../../docs/product/POSITIONING.md) 为准。

本次历史审计采用的交互原则是：AI 是产品的主创作界面。该原则适用于系列长篇、单季短剧、小剧场和博主工作室，以及灵感、规划、正文、改编、制作、审核修订与交付准备。用户提供目标、参考、约束、反馈和关键决定，内容生产与重复整理默认由 AI 和系统完成。2026-09-30 校准的当前口径是：小说为重要上游核心之一、可独立完成章节/稿件/投稿的一等能力，IP 改编与剧本为转化核心，作者意图、叙事质量、连续性、版本和来源贯穿两路，媒体为可选生产出口。历史模式覆盖不代表所有模式仍占据同等市场优先级，也不将整改前缺口视为今日仍未完成。

## 1. 核查范围与归因

本轮核查 `desktop/` 的首页、项目概览、小说、人物与大纲、创作分析、改编、首集试制、媒体、审片、交付、数据洞察、灵感和模式专用工具的主要入口；对审片修订和反馈修订进一步跟踪了客户端调用与 Runtime 路由。未修改 `platform/`，未进行真实模型调用或全产品运行验收。

归因以当前工作区相对 HEAD 的差异为依据：可以确认前一轮重设计新加入的默认行为和文案，也可以确认哪些问题在 HEAD 中已经存在；不能仅凭某文件处于修改状态，就将其中全部旧流程归为本轮新引入。

示例、导入、建项目无需调用模型仍然合理。问题是把 AI 描述为内容已经由用户写好之后的可选工具。无需模型的准备动作与模型生成必须准确区分。

## 3. 三类优先处理的问题

1. **方向错误。** 首页、默认布局、空态和推荐下一步将内容生产交给用户。不能仅把“新建”改名“AI 生成”，必须接入真实生成与结果处理。
2. **输入重复。** 已有剧本和分镜，仍让用户重新写提示词、粘贴对白、填写译文。需要继承当前对象、内容版本和结构化资料，把专业参数按需展开。
3. **执行与结果不相符。** “创建任务”“完成”“候选”不保证发生过模型执行。数据洞察的固定说明任务、审片的人工内容预览已是具体实例，应优先明确能力和完成真实执行链路。

小说生成的章节绑定、字数约束、上下文与候选事件链路另见 [小说工作台方案](./AI_NOVEL_WORKSPACE_REDESIGN.md)。这些是静态核查发现，影响范围仍需 Runtime 验证。

## 4. 全产品统一的职责和交互规则

- 用户输入作品目标、偏好、参考和修改要求，选择方案并对关键取舍作决定。
- AI 与系统承担规划、正文与剧本生成、分镜设计、上下文整理、媒体提示准备、检查、修订及衍生资料生成。
- 默认主操作随对象状态变化：规划、生成、检查、修订、审阅采用、继续下一阶段。技术任务目录和原始表单不承担普通用户的主流程。
- 每个产物关联真实输入、来源版本、执行记录、候选与采用记录。规则分析、模板初始化和模型生成分别标明，状态不能互相替代。
- 上游改变后展示实际受影响对象；只重做相关产物。自动连续执行必须有范围、成本边界、暂停与恢复点。
- 将灵感空间已有的“给出意图、AI 对话探索、生成项目预览”的交互作为可复用起点；保留人物与大纲生成器、媒体生成、自动编排、版本和候选基础。

AI 核心定位不改变用户对作品和账号的控制。采用候选、保护已选内容、选择创作方向、授权人物与素材、支付确认和显式发布仍是用户决策。字号、时间线微调、元数据更正以及保存恢复也继续有价值，但不应成为用户必须完成的主要内容生产工作。

## 5. 纠偏执行顺序与验收

| 顺序 | 工作                                                                       | 验收                                                                               |
| ---- | -------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| P0   | 修正全局默认定位与目录缺陷；核对小说目标上下文、审片修订、反馈修订执行链路 | 用户不会被要求先写出成品；标为 AI 执行的动作有真实运行记录和对应结果               |
| P1   | 统一四种项目模式的 AI 主入口；打通意图、方案、生成、检查、修订和采用       | 从创意或导入来源得到第一份可采用内容；首次连接不会丢失用户要求                     |
| P2   | 改编到媒体、字幕、交付及反馈的上下文衔接                                   | 用户不需复制正文、台词和镜头提示跨页面搬运；失败可在原对象恢复                     |
| P3   | 有边界的连续生成和全产品质量评估                                           | 衡量可采用产物、修订轮数、人工补录量、连续性、耗时与成本，避免只统计按钮与页面存在 |

实施保持在 `desktop/`，保留插件贡献、typed service、Runtime 编排、Host 能力与凭据边界；既有数据、预览、对话和版本记录不因定位纠正被清除。
