# 尽意 DramaIP 新定位优化执行计划

> 文档状态：Proposed / Execution Plan
>
> 制定日期：2026-09-21
>
> 定位依据：[产品定位](./product/POSITIONING.md)
>
> 适用范围：`desktop/` 为主要实施范围；`platform/` 只承担官网、账户、商业化、可选协作与审片等独立云能力

## 1. 计划目标

本计划用于把当前项目从“能力丰富但入口和流程分散的 AI IP 创作平台”收敛为：

> 面向 AI 短剧与漫剧的本地优先 AI 编剧与 IP 改编工作台。

首要产品结果是让原创作者和 1–10 人内容团队能够从创意、小说、大纲或已有剧本出发，稳定得到可采用、可追溯、可继续制作的整季方案、首集剧本和首集分镜试制包。

默认英雄流程为：

```text
导入小说或大纲
        ↓
改编诊断
        ↓
整季分集方案
        ↓
首集标准剧本
        ↓
首集分镜试制包
        ↓
审核、导出或进入可选媒体制作
```

计划不以增加模型、Provider、页面或按钮数量为目标。完成标准是用户能够更快得到正式采用的创作结果，并能理解结果来自哪里、为什么可信、修改上游后会影响什么。

## 2. 当前基线判断

### 2.1 可直接复用的基础

以下能力已经存在，应优先复用和串联，不应重写：

- 本地项目、导入预览、权利确认和 Preview / Commit；
- AI Workflow、冻结上下文、来源版本、持久任务、候选、检查、人工采用和冲突处理；
- 小说章节、人物、大纲、故事弧、故事圣经、章节记忆、事件、伏笔和连续性资料；
- 结构化剧本、Fountain 导入导出、稳定剧本块和三方合并；
- 改编、分集、场景、分镜、生产影响图和 1–3 集试制计划；
- 视觉资产锁、权利检查、费用预检、Provider-neutral 媒体提交；
- 离线审片、可选云审片、时间线、字幕、媒体清单和 NLE 交换文件；
- Desktop Runtime、插件所有权、Domain Event、幂等、ETag、SSE 和恢复机制。

### 2.2 当前关键缺口

1. 官网、应用元数据和演示案例仍偏“AI IP 创作/导演生产”，没有突出“小说/IP 改编为短剧”的核心结果。
2. 首次使用先要求选择内部项目模式，没有优先询问用户手中已有的素材。
3. 小说、改编、制作、审核仍表现为多个并列工作区，用户需要反复选择项目、改编方案、分集、剧本和场景。
4. 缺少独立、可采用的改编诊断和整季分集方案；当前 `episode` 操作承担的职责过多。
5. 未显式选择来源时，改编生成可能只使用前几章，不能代表长篇 IP 的完整结构。
6. 作者意图已有界面表达，但尚未成为独立、版本化、可引用的权威资产。
7. `adaptations / episodes / scripts / scenes / shots` 的通用 payload 难以支撑稳定的专业改编契约。
8. 规则检查较丰富，但缺少真实模型采用率、连续性错误、成本和目标用户任务测试证据。
9. 当前 fresh-profile 主流程验收到试制剧本，完整制作交付主要由内置样片提供证据。

## 3. 执行原则

1. **先打通纵向结果，再增加横向能力。** 每个里程碑都必须形成从用户输入到可采用结果的闭环。
2. **小说是上游核心之一，不是强制入口。** 创意、已有小说和已有剧本三条路径必须同时成立。
3. **改编与剧本是当前转化核心。** 新增资源优先投入改编诊断、整季方案、首集剧本和叙事质量。
4. **作者拥有权威内容。** AI 只产生候选；高影响写入必须 Preview / Diff / Confirm / Version。
5. **来源优先于生成。** 每个正式产物必须关联实际采用的来源版本和覆盖范围。
6. **媒体是生产出口。** 图片、TTS 和视频继续 Provider-neutral、BYOK、显式授权和成本预检。
7. **不把计划写成事实。** UI、官网和发布材料只描述已经实现并经过验证的能力。
8. **保持 Desktop 与 Platform 独立。** 不增加跨目录构建或运行时依赖，不把 Desktop 权威正文迁移为云端权威数据。

## 4. 目标产品结构

### 4.1 全局层

```text
项目
灵感
待确认
设置
```

全局层负责选择作品、恢复工作、处理待确认结果和系统配置。现有深链接路由可以保留，但不再要求用户把小说、改编、制作和审核理解为互相独立的产品。

### 4.2 项目内部层

```text
故事母本
改编方案
分集剧本
分镜试制
审核交付
```

项目首页展示当前采用版本、阶段 Gate、阻断项、最近结果和唯一推荐动作。高级资料编辑、历史任务、通用资源表单和诊断详情放入二级入口。

### 4.3 三种开始路径

| 开始路径 | 默认结果 | 是否经过小说写作 |
| --- | --- | --- |
| 从创意开始 | 故事母本、人物和改编方向 | 可选，系列项目通常需要 |
| 导入小说或大纲 | 改编诊断和整季方案 | 使用已有母本，不强制重写 |
| 导入已有剧本 | 连续性/制作检查和分镜试制 | 跳过小说阶段 |

项目模式继续作为持久业务意图存在，但由系统根据用户输入推荐；“我的 AI 小剧场”和“博主内容工作室”移至其他模板或独立 Profile，不占据核心首屏。

## 5. 工作流与领域归属

| 能力 | 唯一业务所有者 | 主要职责 |
| --- | --- | --- |
| 项目入口、项目模式、作者意图 | `workspace` | 项目身份、用户目标、创作约束和派生关系 |
| 小说、人物、大纲、故事弧 | `writing` | 故事母本创作和正式文本 |
| 故事圣经和派生事实 | `knowledge` | 从已采用内容提取、审阅和维护可信知识 |
| 改编诊断、季纲、分集、剧本、场景、分镜 | `production` | IP 改编和结构化剧本生产 |
| 叙事与连续性报告 | `creative-quality` | 有证据的规则/模型检查和修订建议 |
| 跨阶段运行、重试、候选和采用 | `automation` | 持久工作流、状态机、Preview / Commit 和恢复 |
| 图片、音频、视频和资产锁 | `media` | Provider、费用、权利、媒体候选和采用 |
| 审片意见与决定 | `review` | 审片包、评论、决定和返修关联 |
| 标准交付包 | `delivery` | 投稿、提案、分集、分镜、字幕和 NLE 交付 |
| 本地结果指标 | `insights` | 不含正文的结果事件、漏斗和质量指标 |

插件不得直接写入其他插件拥有的表，也不得导入同级插件实现。跨领域协作通过服务契约、路由、Domain Event、只读引用和投影完成。

## 6. 核心领域对象

### 6.1 `AuthorIntent`

建议由 `workspace` 所有，至少包含：

- `themeStatement`：作品真正想表达的主题；
- `emotionalPromise`：面向观众的主要情绪承诺；
- `targetAudience`：目标受众；
- `mustKeep`：改编必须保留的人物、关系、事件和表达；
- `mayChange`：允许合并、删减、重排或替换的内容；
- `mustAvoid`：禁止改变、禁用表达和敏感边界；
- `endingContract`：结局和人物归宿约束；
- `toneAndVoice`：叙事声音与风格；
- `version / source / adoptedAt`：版本、来源和采用信息。

作者意图不能继续只从自由文本标题中解析。旧项目可以在迁移后显示“待确认”，由用户采用后成为正式版本。

### 6.2 `AdaptationDiagnosis`

建议由 `production` 所有，至少包含：

- 原著核心卖点、主题和情绪承诺；
- 主线、人物弧和关键关系；
- 高价值钩子、冲突、反转和悬念；
- 需要保留、合并、删减、前置或重构的内容；
- 目标形式、集数、单集时长和建议节奏；
- 视觉化、角色一致性、场景复杂度和制作成本风险；
- 来源章节/片段、覆盖比例和未覆盖区域；
- 2–3 个可比较的改编策略候选；
- 采用状态、版本和失效原因。

### 6.3 `SeasonPlan`

建议由 `production` 所有，至少包含：

- 整季主题和主冲突；
- 分集列表及稳定顺序；
- 每集 logline、来源范围、目标、主要冲突、转折和集尾悬念；
- 人物状态、关系推进、伏笔埋设/回收；
- 每集预计场景数、角色数、制作复杂度和成本等级；
- 原著覆盖矩阵和重复/遗漏检查；
- 采用状态、版本和影响摘要。

### 6.4 `NarrativeQualityReport`

建议由 `creative-quality` 所有，按项目、季、分集、剧本或场景建立，包含：

- 问题类别、严重度、证据、来源位置和建议；
- 人物认知、关系、时间线、因果、伏笔、重复、节奏、对白和制作风险；
- `rule`、`model`、`human` 三种来源；
- 目标对象和来源版本；
- 已解决、接受风险、失效或待处理状态；
- 复检结果。

### 6.5 `PilotPackageManifest`

建议由 `delivery` 所有，描述首集试制的可交换结果：

- 已采用的作者意图、改编诊断和整季方案版本；
- 首集剧本、场景、分镜和来源映射；
- 角色、场景、道具、声音和视觉设定；
- Prompt、负面 Prompt、字幕、媒体清单和成本说明；
- 质量、权利、连续性和交付预检；
- Markdown / JSON / CSV / Fountain / 支持的 NLE 文件引用；
- 未完成项和外部依赖。

## 7. AI 创作操作拆分

新增或调整以下 `CreationOperation`：

| 操作 | 输出 | 采用单位 |
| --- | --- | --- |
| `author-intent` | 作者意图候选 | 项目意图版本 |
| `adaptation-diagnosis` | 改编诊断候选 | 单份诊断 |
| `adaptation-strategy` | 2–3 个改编策略 | 选定策略 |
| `season-plan` | 整季分集方案 | 整季方案版本 |
| `episode-outline` | 单集节拍与场景目标 | 单集大纲 |
| `episode-script` | Fountain 剧本和稳定剧本块 | 单集剧本 |
| `script-revision` | 保留块标识的完整修订稿 | 单次剧本修订 |
| `storyboard-package` | 场景、分镜和生产说明 | 单集分镜包 |
| `quality-review` | 有证据的问题和建议 | 质量报告，不直接改正文 |

当前宽泛的 `episode` 操作进入兼容期：旧记录继续可读，新主流程不再依赖它同时创建改编、分集、剧本、场景和分镜。迁移不得删除既有候选或采用记录。

每个操作必须具备：

1. 强类型输入和输出 schema；
2. 冻结的实际引用和来源版本；
3. 确定性结构校验；
4. 模型质量检查与一轮受控局部修订；
5. 候选比较、明确采用和放弃；
6. 来源变化后的 stale/冲突处理；
7. 幂等、取消、重试和恢复；
8. token、费用、模型和耗时记录。

## 8. 长篇上下文与来源覆盖

### 8.1 禁止默认以前几章代表全书

未显式选择来源时，不得再静默截取固定数量的开头章节用于整季改编。系统应要求用户确认范围，或使用明确的分层索引生成全书诊断。

### 8.2 分层上下文

```text
原著全文
├── 章节摘要、事实和状态变化
├── 卷/故事弧摘要
├── 人物关系、认知和人物弧
├── 事件、因果、时间线和伏笔
├── 当前改编策略对应的章节范围
└── 本轮实际送入模型的原文片段
```

上下文预览必须显示：

- 纳入和排除的章节；
- 使用原文还是摘要；
- 选择原因；
- 估算 token 和裁剪情况；
- 原著覆盖率和未覆盖关键内容；
- 来源版本发生变化后的影响对象。

### 8.3 细粒度来源映射

目标映射链路：

```text
原著章节/段落
→ 故事节点
→ 季与分集
→ 剧本块
→ 场景
→ 分镜
→ 媒体和交付项
```

第一阶段可以使用章节级范围；第二阶段升级到稳定段落/文本锚点。映射必须使用不泄露正文的内部引用，项目包只携带允许导出的快照和脱敏谱系。

## 9. UX 改造任务

### UX-01：素材优先的新建入口

- 首屏主按钮改为“导入小说或大纲”；
- 同级提供“从创意开始”和“导入已有剧本”；
- 系统根据素材和目标推荐项目模式；
- 其他模式进入二级模板区；
- 草稿恢复、原文件预览和权利确认保持不变。

验收：用户无需理解项目模式，即可从三种素材状态创建正确项目。

### UX-02：项目阶段驾驶舱

项目首页显示五个核心 Gate：

1. 来源与作者意图；
2. 改编诊断；
3. 整季分集方案；
4. 首集剧本；
5. 首集分镜试制包。

每个 Gate 显示正式版本、来源覆盖、主要问题、阻断项和下一步。计数可以作为详情，但不能继续作为完成状态的主要依据。

验收：任意项目状态下只突出一个主动作，并可回到上一步修订。

### UX-03：项目上下文自动继承

- 从项目进入改编、制作和审核时自动带入当前项目和当前采用版本；
- 常规流程不再展示五级选择器；
- 对象切换使用面包屑、分集目录或上下文抽屉；
- 高级用户仍可通过搜索和深链接直接打开对象。

验收：从项目首页到首集剧本，不需要重复选择项目、改编方案和分集。

### UX-04：待确认中心

统一展示：

- 作者意图候选；
- 改编诊断和策略；
- 整季方案；
- 剧本与分镜候选；
- Story Bible 变更；
- 质量问题和返修候选；
- 费用或权利确认。

验收：任务、对话、候选和正式采用状态名称保持一致，用户能从待确认项返回原对象。

## 10. 叙事质量 Gate

| Gate | 自动检查 | 阻断条件 |
| --- | --- | --- |
| 改编诊断采用前 | 来源范围、主题、人物弧、关键情节和权利 | 来源未确认、覆盖严重不足 |
| 整季方案采用前 | 集间重复、遗漏、人物推进、伏笔、钩子与结尾悬念 | 主线缺失、关键人物弧断裂 |
| 剧本采用前 | 人物认知、因果、对白、场景推进、时长和集尾 | 严重连续性或结构错误 |
| 分镜采用前 | 镜头覆盖、角色/场景引用、动作可视化和成本风险 | 剧本覆盖不足、权利阻断 |
| 媒体提交前 | 资产锁、Provider 能力、费用、权利和 stale 状态 | 未采用静帧、费用未确认、来源失效 |
| 交付前 | 质量、合规、审片决定、文件和谱系 | 未解决阻断项 |

分数只能作为摘要。每个问题必须有证据、位置、来源类型和可执行建议；模型推断不能冒充正式事实。

## 11. 媒体与交付边界

1. 默认英雄流程结束于首集分镜试制包，不要求生成完整视频。
2. 静帧用于验证角色、场景、构图和视觉方向，优先于高成本视频。
3. 视频生成只从已采用分镜和已锁定资产发起。
4. Provider 数量不作为阶段目标；优先保证现有 Provider 的能力声明、费用、失败和取消语义真实。
5. 上游变化只使受影响镜头和媒体失效，不全量重做。
6. 交付包必须在没有媒体二进制时仍可完整表达剧本、分镜、Prompt、字幕、资产清单和缺失项。

## 12. 官网、演示和商业化

### WEB-01：官网首屏

首屏统一使用：

- 品牌主张：尽作者之意，成万象之作；
- 结果标题：把小说打磨成真正能拍的短剧；
- 产品定位：面向 AI 短剧与漫剧的本地优先 AI 编剧与 IP 改编工作台。

主视觉从单个导演镜头切换为“原著 → 诊断 → 整季方案 → 首集剧本 → 分镜”的结果链路。

### WEB-02：案例替换

新增一套完整、虚构、可再分发的改编案例，至少展示：

1. 原著节选和作者意图；
2. 三项改编问题及证据；
3. 两个可比较的改编策略；
4. 已采用整季方案；
5. 首集剧本与原著来源对应；
6. 首集分镜试制包；
7. 上游修改后的局部影响和恢复。

现有十镜头样片保留为生产能力案例，但不再承担首页唯一核心案例。

### WEB-03：套餐表达

套餐优先表达用户结果：

- 长篇上下文与改编规模；
- 改编诊断和整季方案；
- 叙事质量与连续性检查；
- 专业剧本、分镜和交付；
- 团队席位、云审片和私有网关。

本地项目和用户正文不得因订阅到期被锁定。媒体 BYOK、云审片容量和高级导出继续作为差异化权益。

## 13. 指标与数据边界

### 13.1 北极星指标

> 每周被用户正式采用并导出的分集剧本或首集试制包数量。

### 13.2 核心漏斗

```text
项目创建
→ 来源确认
→ 诊断采用
→ 整季方案采用
→ 首集剧本采用
→ 首集分镜包导出
```

### 13.3 辅助指标

- 首次可采用诊断所需时间；
- 改编诊断、季纲和首集剧本的首次候选采用率；
- 达到采用所需的局部修订次数；
- 每十集连续性和人物认知错误数；
- 原著关键情节覆盖率；
- 人工补录量；
- 每分钟可采用剧本的 token 与费用；
- 上游修改后实际重做的对象比例；
- 首集分镜试制包导出率；
- 第二集继续率。

### 13.4 数据原则

- 本地首先计算完整指标；
- 对外分析默认关闭并需明确同意；
- 只上传白名单事件、状态、耗时区间和匿名安装标识；
- 不上传小说正文、Prompt、候选全文、API Key、绝对路径或母版；
- 模拟、规则、真实模型和人工评价必须分开标记。

## 14. 测试与评估计划

### 14.1 自动化场景

1. 从创意创建项目并采用作者意图；
2. 导入小说/大纲，确认权利并采用改编诊断；
3. 从已有剧本跳过小说阶段，进入连续性检查和分镜；
4. 采用整季方案后生成首集剧本；
5. 采用首集剧本后生成首集分镜试制包；
6. 修改来源章节，只标记受影响的诊断、分集、剧本和分镜；
7. 来源在候选生成后变化，采用必须冲突而不是覆盖；
8. 无 AI 配置时保留项目、来源、要求和恢复位置；
9. 模型失败、取消、应用重启后任务和候选可恢复；
10. 无媒体 Provider 时仍能导出完整结构化试制包。

### 14.2 固定内容评测集

至少覆盖：

- 悬疑、情感、轻喜剧、成长和奇幻五种类型；
- 短篇、中篇、长篇三种规模；
- 创意、已有小说、已有剧本三种入口；
- 人物认知、时间线、关系、伏笔、因果、重复和制作风险。

真实模型评测固定模型版本、输入版本和预算，记录采用、修订、错误、耗时和费用。采用匿名双盲或至少隐藏 Provider/模型名称后再评分。

### 14.3 目标用户验证

首轮邀请 6–8 位目标用户：

- 2–3 位有长篇小说的原创作者；
- 2–3 位短剧编剧或导演；
- 2 位 1–10 人内容工作室成员。

统一任务：导入一份真实或授权样稿，完成诊断、整季方案、首集剧本和首集分镜包。观察任务完成路径，再访谈结果可信度和采用意愿。

## 15. 实施里程碑

时间为相对迭代顺序，实际排期由团队容量决定。每个里程碑必须满足退出 Gate 后才能进入下一阶段的范围扩张。

### M0：定位表面与基线

目标：所有真实产品表面与文档定位一致，并建立实施前数据基线。

- [ ] 更新官网首页、SEO metadata、下载页、套餐和案例文案；
- [ ] 更新 Desktop package description、窗口/安装包展示文案；
- [ ] 搜索并清理非历史目录中的旧定位；
- [ ] 记录当前三条入口的任务步骤、完成时间和阻断点；
- [ ] 建立北极星指标和漏斗事件字典；
- [ ] 冻结“继续增加 Provider、模式和泛化工具”的非核心需求。

退出 Gate：没有未标注旧定位；现有能力与未实现能力在官网、应用和发布材料中区分明确。

### M1：素材优先入口与项目驾驶舱

目标：用户不理解内部项目模式也能开始，并始终看到唯一下一步。

- [ ] 新建入口调整为创意、小说/大纲、已有剧本三条路径；
- [ ] 系统推荐项目模式，其他模式降为二级模板；
- [ ] 驾驶舱改为五个结果 Gate；
- [ ] 常规流程自动继承项目上下文；
- [ ] 待确认中心统一候选、任务、费用和权利确认；
- [ ] 保留旧路由和深链接兼容。

退出 Gate：三条入口在 fresh profile 中都能恢复；从项目首页到下一正式结果无需重复选择父级对象。

### M2：改编诊断与整季方案

目标：形成新定位最关键的可采用中间产物。

- [ ] 增加 `AuthorIntent` 正式契约、迁移、路由和采用流程；
- [ ] 增加 `AdaptationDiagnosis` 契约、存储、工作流和 UI；
- [ ] 增加多策略比较和单一采用；
- [ ] 增加 `SeasonPlan`、分集覆盖矩阵和顺序编辑；
- [ ] 拆分 `CreationOperation`；
- [ ] 旧 `episode` 工作流进入兼容路径；
- [ ] 新增来源变化和并发冲突测试。

退出 Gate：导入小说后可以采用一份有来源证据的诊断和一份完整整季方案；正式内容不会被静默覆盖。

### M3：首集剧本与分镜试制包

目标：从已采用整季方案生成可交付的首集结果。

- [ ] `episode-outline` 和 `episode-script` 使用已采用诊断、季纲、作者意图和 Story Bible；
- [ ] 稳定剧本块、三方合并和现有导入导出继续工作；
- [ ] `storyboard-package` 生成场景、分镜、视觉需求和成本风险；
- [ ] 媒体生成保持可选，不作为完成 Gate；
- [ ] `PilotPackageManifest` 支持 Markdown / JSON / CSV / Fountain 和已有 NLE 能力；
- [ ] 建立从真实导入到试制包的完整 Electron E2E。

退出 Gate：三种入口都能在不依赖预置样片的情况下完成首集剧本；小说入口可进一步导出首集分镜试制包。

### M4：长篇上下文、谱系与质量门

目标：形成区别于通用 AI 写作和视频工具的核心壁垒。

- [ ] 建立章节、故事弧和全书分层索引；
- [ ] 移除默认固定前三章的隐式行为；
- [ ] 显示本轮上下文和原著覆盖；
- [ ] 建立章节/段落到分集、剧本块、场景和分镜的映射；
- [ ] 建立叙事质量 Gate 和问题复检；
- [ ] 上游变化只失效受影响下游对象；
- [ ] 项目包携带允许导出的脱敏谱系。

退出 Gate：固定长篇样例可以解释每集来源；修改一个章节不会导致无关分集和镜头全量失效。

### M5：真实质量和商业验证

目标：证明产品结果而不是页面存在。

- [ ] 跑固定真实模型评测集；
- [ ] 完成 6–8 位目标用户任务测试；
- [ ] 根据采用率、修订次数、连续性和成本调优；
- [ ] 官网案例替换为完整改编案例；
- [ ] 套餐按改编、质量、交付和协作价值重组；
- [ ] 完成目标平台安装、升级、恢复和发布 Gate。

退出 Gate：至少一条真实模型、真实用户的英雄流程达到内部发布阈值；模拟结果不得替代发布证据。

## 17. 暂缓范围

在 M3 退出 Gate 前，以下方向仅维护现状和安全修复，不主动扩张：

- 新增视频、图片或音频 Provider；
- 扩大 Marketplace 和第三方扩展能力面；
- 完整 Web 创作编辑器和默认云同步；
- 博主内容工作室的新功能；
- 我的 AI 小剧场的新功能；
- 更多泛化 Agent 或独立分析页面；
- 全自动整季剧本、整季视频或自动发布；
- 爆款预测、投流和发行平台；
- 与核心流程无关的富文本编辑器增强。

## 18. 技术实施约束

### Desktop

- Renderer 业务代码只使用生成的 `@dramaip/client`，不得直接 `fetch`、业务 IPC 或导入 Runtime/Host 实现。
- 新业务路由由对应插件声明并保持 `/api/v2`、RFC 7807、operation ID、ETag、Idempotency-Key、游标分页和可重放 SSE。
- 新表、路由、事件、服务和 UI contribution 必须有唯一所有者。
- 正式写入与 Domain Event 在同一事务内完成；迁移只允许前向追加。
- 长期任务、处理器、监听器和进程必须通过 `ctx.effect()` 或 supervisor 跟踪。
- 不手工修改 OpenAPI、架构 catalog、generated manifest 或迁移矩阵。
- Contract 变化后执行 `bun run --filter @dramaip/client generate` 和 `bun run check:generated`。
- 所有权、事件、服务或内置 UI contribution 变化后执行 `bun run architecture:generate` 和 `bun run check:architecture`。
- 功能迁移完成后执行 `bun run migration:generate` 和 `bun run check:migration:complete`。

### Platform

- Gateway 仍是唯一公开入口，业务服务保持单一表写入者和服务边界。
- Platform 不保存或接管 Desktop 私人正文的权威版本。
- Web、Mobile、Admin 只通过 Platform SDK 和 `/api/v1/**` 契约访问云服务。
- Desktop 与 Platform 不增加跨目录构建、数据库或运行时依赖。

## 19. 验证命令

按改动范围执行，不能用文档或 UI 截图替代真实测试。

cd desktop

bun run test
bun run check:generated
bun run check:architecture
bun run check:migration:complete
bun run build
bun run check:renderer-chunks
```

```

### Platform 客户端和服务

```bash

```

涉及 Web 对外页面时，从 `platform/clients/` 运行 lint、typecheck、test 和 `build:web`；涉及契约时同时执行 contract check 和 Web route smoke。

## 20. 发布 Gate

满足以下条件前，不把新定位描述为已经完整实现：

1. 创意、小说/大纲、已有剧本三条入口均通过 fresh-profile E2E；
2. 小说入口实际完成诊断、整季方案、首集剧本和首集分镜包；
3. 每个正式结果都有来源、版本、模型、费用和采用记录；
4. 来源变化能阻止过期候选采用，并只标记受影响结果；
5. 无 Provider 或无媒体生成时仍可得到可用试制包；
6. 固定真实模型评测记录采用率、修订、连续性、耗时和成本；
7. 完成目标用户任务测试；
8. 官网、应用、下载页、套餐和发布说明使用相同定位；
9. Windows、macOS 和 Linux 的发布状态按真实证据标注；
10. 不存在“一键爆款”“全自动成片”或未经验证的质量承诺。

## 21. 计划维护方式

- 状态只使用 `planned`、`in-progress`、`blocked`、`done`；
- 每个任务必须关联负责人、目标里程碑、代码/设计证据和验收结果；
- 完成任务时更新对应复选框和退出 Gate，不以“页面已出现”代替业务完成；
- 范围变化先检查是否强化英雄流程和北极星指标；不能强化时默认延后；
- 当前实现事实继续记录在工程和架构文档中，本计划不替代实现说明；
- 本计划不启用 Loop 模式，也不创建 Loop 记录。
