# LM3-16 订阅生命周期验证与回滚

## 状态与边界

- 取消默认只设置 `cancel_at_period_end`；billing-job 到期后结束当前订阅和周期记录。
- 恢复只能发生在仍为 `active` 的已取消续订周期内，且以订阅和周期为幂等边界。
- 模拟支付订阅可以升级：billing 先持久化 `quota_pending` 的变更意图，quota-service 以
  `adjustment_id` 写入一次 `quota_adjustments`，最后 billing 才切换当前套餐快照。
- 降级只写入不可变的计划快照和生效时间；job 创建下一周期时才应用，当前周期的
  `subscription_periods` 快照和额度不被覆盖。
- 退款不等于取消。只要额度已结算或存在未结算预留，quota-service 返回 `manual_review`；
  只有模拟支付且当期零用量、无进行中预留时，才会将账户置为 `refund_hold` 并完成模拟退款。
  真实支付渠道继续等待 LM3-17/LM3-18 的服务端验签与确认。

## 数据与补偿

`billing.subscription_periods` 保留每个周期的套餐快照；`billing.subscription_changes`
记录升级、降级、取消和恢复的意图、生效时间、状态与失败原因；`billing.refunds` 保存退款
与人工复核状态。`quota.quota_adjustments` 是额度变化的只追加审计账本，
`quota.refund_holds` 是退款冻结的跨服务幂等记录。

billing-job 每轮先处理到期取消、待完成升级、待完成退款，再为到期的模拟订阅创建下一
`quota_pending` 周期。quota RPC 在 billing 本地事务之后调用；失败会保留 `quota_pending`
和失败原因，后续轮次使用相同 change/refund ID 重试。不会跨服务事务，也不会覆盖历史周期。

业务/数据测试覆盖升级幂等、额度 RPC 故障重试、降级延迟、取消恢复、退款冻结与人工复核、
周期快照不覆盖、到期取消和新周期创建。恢复健康的 Compose 栈后，还应运行
`make platform-e2e` 并增加真实支付沙箱回调验证；当前本地栈不健康时不将其记为通过。

## 回滚

024/025 仅新增表、索引和列，不删除订单、订阅、周期、额度或调整记录。回滚应用版本时
保留已写入的生命周期和额度账本；不得删除 `subscription_periods`、`subscription_changes`、
`refunds`、`quota_adjustments` 或 `refund_holds` 来伪造旧状态。若外部支付退款无法确认，
保持 `manual_review` 并由后续渠道/后台流程处理。
