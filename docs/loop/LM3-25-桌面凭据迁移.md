# LM3-25 桌面本地凭据迁移与恢复

## 存储边界

模型与视频 Provider 的用户自填 API Key 使用 `keytar` 保存到系统凭据库：macOS
Keychain、Windows Credential Manager 或 Linux Secret Service/libsecret。SQLite 的
`model_configs.api_key` 与 `video_provider_configs.api_key` 仅保存
`keychain:v1:<reference>`；renderer 只接收 `masked:v1:*`，不会接收明文或引用可解析出的
凭据。

Key 仅在 Electron 主进程内存缓存中提供给本地 AI/视频 Provider。日志、诊断包和迁移审计
禁止记录 Key；`credential_migration_audit` 只记录区域、配置 id、旧格式类别、结果、次数和
引用。

## 迁移与失败语义

启动时会识别旧版 `enc:v1:`、`plain:v1:` 和裸明文值，并按每条记录执行：

1. 在系统凭据库创建一条新的、版本化引用；
2. 确认写入成功后，再将 SQLite 值替换为引用；
3. 写入不含凭据内容的迁移审计记录。

任何写入或更新失败都会保留 SQLite 中的原值，供下一次启动重试；不会删除或覆盖用户已有
配置。应用打开旧库前会创建自动 SQLite 备份，恢复该备份即可回到迁移前数据库状态。正常
删除或更换配置时，数据库不再引用旧凭据后才尝试清理该凭据；清理失败不会让凭据重新进入
SQLite，可在后续保存/删除操作中再次清理。

## 恢复检查

- macOS：确认当前用户的 Keychain 未锁定，并允许“短剧IP小说工作室”访问钥匙串。
- Windows：确认 Credential Manager 服务可用，当前登录用户可创建通用凭据。
- Linux：安装并启动 Secret Service/libsecret 兼容服务（例如 GNOME Keyring 或 KWallet
  Secret Service）；无桌面会话的环境不会降级为明文保存。

设置页会显示“系统凭据”“旧版待迁移”“不可读”和迁移失败的聚合数量。若提示失败，先恢复
系统凭据服务，再重启应用；不要从日志、诊断包或 SQLite 中寻找 API Key。

## 验证边界

本 loop 的本地验证包含类型检查、secret 单元测试、SQLite migration replay/DB smoke、
Electron E2E、敏感字段扫描和当前平台的打包 smoke。Windows/Linux 安装包需要在各自原生
环境执行相同的 Keytar/Secret Service smoke；macOS 打包验证不能替代其它操作系统的凭据库
可用性证据。
