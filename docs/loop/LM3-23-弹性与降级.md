# LM3-23：弹性、降级与舱壁运行手册

本记录实现 `LOOPMAP3` 的 LM3-23。目标是将下游短暂故障限制在可预测的时间、并发和重试范围内；它不改变账本权威性，也不把支付、额度或认证失败“降级为成功”。

## 策略与配置

| 区域 | 策略 | 默认值 |
| --- | --- | --- |
| 所有内部 gRPC | client/server deadline | `GRPC_REQUEST_TIMEOUT=10s` |
| AI Chat gRPC | 独立 deadline | `AI_RPC_TIMEOUT=95s` |
| 可重试 RPC | 仅 `Get*` / `List*` / `Validate*`；仅瞬态 `Unavailable`/`DeadlineExceeded`；指数退避+抖动 | 最多 3 次 |
| 下游熔断 | 连续瞬态失败打开，单个半开探测 | 3 次 / 15 秒（`AI_PROVIDER_CIRCUIT_FAILURES`、`AI_PROVIDER_CIRCUIT_RESET` 可覆盖 Provider） |
| Provider | 每个 `Provider + model` 独立超时、熔断、并发舱壁 | 90 秒 / 8 并发（`AI_PROVIDER_TIMEOUT[_SECONDS]`、`AI_PROVIDER_MAX_CONCURRENCY`） |
| billing outbox | 持久化重试，保留 event ID，失败释放租约 | `OUTBOX_RETRY_DELAY=5s`，指数退避上限 5 分钟 |
| billing job | 单个 job 操作 deadline | `BILLING_JOB_OPERATION_TIMEOUT=30s` |

客户端已有较短 deadline 时共享组件不会延长它。写 RPC（包括 `ReserveTokens`、`SettleTokens`、订单创建、支付确认）不会因网络错误被 client interceptor 自动重放；它们只能由既有幂等键、Saga、outbox 或补偿任务安全处理。

## 失败行为

- quota 不可达：AI 在调用 Provider 前失败，绝不跳过预扣；如果 Provider 已失败/超时，则取消 quota reservation、释放 cost guard，并保留失败审计。
- auth 不可达：BFF 返回 `503` 和 `Retry-After: 2`，不会信任客户端提供的身份。
- billing 不可达：仅 `/v1/plans` 可回退到本进程 5 分钟内的成功只读快照；不会缓存或伪造订单、订阅、支付状态。
- MQ 不可达：outbox 记录不删除，lease 释放后按持久化指数退避继续尝试；不得通过标记 `published_at` 来消除积压。
- Provider 超时/熔断/舱壁饱和：返回短暂不可用（熔断或饱和为 `503 + Retry-After: 2`，deadline 为 `504 + Retry-After: 1`）；其它 `Provider + model` lane 继续可用。

## 故障注入与通过标准

自动化测试覆盖以下情形：

- 查询 RPC 第一次 `Unavailable` 后成功重试；`ReserveTokens` 在相同错误下只调用一次。
- 熔断器在连续瞬态失败后打开，reset 后仅用半开探测恢复。
- 慢 Provider 受 deadline 终止；一个已饱和的模型 lane 不阻塞同 Provider 的另一模型。
- BFF 对 `Unavailable`/`DeadlineExceeded` 分别返回 `Retry-After: 2`/`1`，billing 套餐页在已有快照时可读。
- outbox 失败等待时间按 5 秒、10 秒、20 秒…增长，至多 5 分钟，且零延迟测试配置仍可显式使用即时重试。

健康 Compose 栈恢复后，再执行以下人工 chaos smoke：停止 quota 或让其 gRPC 端口不可达，调用 `/v1/ai/chat` 并确认 Provider 没有被调用；让一个 test Provider 延迟到超时并并发调用另一个模型，确认后者完成；关闭 RabbitMQ 后检查 outbox 行仍为未发布且 `next_attempt_at` 后移；恢复依赖后检查半开探测、relay 和 Prometheus 指标恢复。不得停止、删除或重建用户已有容器来制造这些证据。
