# LM4-01：核心编辑内容持久化与离开保护

状态：已通过本地验收，待按 Loop 流程合并、推送并登记完成记录。

## 已交付

- 章节、剧本和镜头 Prompt 共享 `clean / dirty / saving / saved / error / recovered` 保存状态。
- 用户每次输入先写入本机恢复缓冲，再以 600ms 节流写入 SQLite；保存失败时保留恢复缓冲并显示可重试状态。
- `Cmd/Ctrl+S` 可立即 flush；路由/对象切换的卸载阶段会 flush；窗口关闭前主进程等待 renderer 的已注册草稿 flush 完成后再关闭。
- 若上次异常退出留下的恢复记录与当前内容不同，编辑器显示“已恢复草稿”，用户可继续保存或明确放弃。
- 镜头 Prompt 的参考图、首帧、封面、旁白和字幕输入同样被纳入一个恢复草稿和一次保存事务，避免只保存正文而丢失关联资产输入。

## 回归证据

cd dramaip-desktop

`pnpm test:e2e` 新增 `draft-autosave-on-immediate-route-leave`：在剧本和镜头编辑器输入后立刻离开路由，随后通过受限 IPC 读取数据库确认内容已写入。单测还验证恢复缓冲按编辑对象隔离。

## 边界

- 恢复缓冲只保留在本机 renderer 的 localStorage；不会上云、不会写入日志，也不会替代 SQLite 的正式保存。
- AI 结果采用前仍按既有预览/采用流程处理；本 Loop 只保护用户编辑中的本地草稿，后续 LM4-02 负责内容新鲜度与工作流真值。
