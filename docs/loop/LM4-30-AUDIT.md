# LM4-30 加密快照审计

状态：`partial`

客户端快照信封使用 AES-256-GCM、32 字节恢复密钥、96 位随机 nonce、固定版本 AAD 与内容摘要。恢复密钥仅在 Electron 主进程生成并存入 OS Keychain；renderer、Desktop BFF、Snapshot 服务与遥测均不会收到密钥或项目明文。错误密钥与篡改密文使用相同失败语义，避免认证 oracle。

Desktop 将不带二进制素材的项目包在本机加密。8 MiB 以下使用有界单请求；8～64 MiB 使用 1 MiB 密文分片。上传前仅把密文、摘要、项目本地标识和幂等键暂存于 `userData`（文件权限 0600），密钥仍只在 Keychain。上传失败后，再次选择同一项目会复用幂等键和密钥，仅补传服务端缺失分片；24 小时后客户端暂存和服务端未完成分片会清理。

Snapshot 领域服务只接受不透明密文：mTLS 调用方限制为 Desktop BFF，用户身份由内部元数据绑定；每用户最多两个未完成上传、十个有效快照，单包最多 64 MiB。完成操作会逐片校验长度/哈希、验证总摘要并原子写入正式快照，再删除暂存分片。删除或 30 天到期都会先清除唯一密文字节；服务端无项目包解析、恢复密钥、全文索引或内容日志路径。恢复会先本地验证/解密，再导入为新项目。

本地验证覆盖 crypto 向量、错误密钥/篡改、服务端上传边界、Desktop BFF 不返回分片密文、全仓 Go/桌面回归、Compose/Helm 渲染以及 UI/a11y 基线。生产准入仍缺：获批的迁移和 mTLS 证据、真实云账号上传/列表/下载/删除恢复演练、存储/KMS/备份保留决策及 LM3-34 灾备证据。不得以本地 fixture 替代这些生产证明，也不得把加密前项目包、恢复密钥或静态存储凭据塞入 Desktop BFF。
