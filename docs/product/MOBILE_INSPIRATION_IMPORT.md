# 移动灵感记录与桌面导入设计

本文用于约束移动轻量入口和桌面灵感台导入能力。

## 1. 产品边界

移动端只承担灵感记录，不承担完整小说写作、AI 工作流执行、项目同步冲突解决、视频资产生产或资源市场能力。

当前阶段的移动记录可以来自手机备忘录、快捷指令、第三方笔记或后续轻量 Web/PWA。它只需要沉淀短剧 IP 创作卡片：

- 爆款开局
- 人物关系
- 冲突机制
- 反转
- 集尾悬念
- 视频画面卖点

桌面端仍是项目数据、AI 生成、章节采用、导出交付和版本回滚的唯一可信写入端。移动记录导入桌面后，会进入灵感台收藏快照，由用户手动采用到项目设定或章节要求。

## 2. 数据模型

移动灵感导入复用现有 `inspiration_favorites` 收藏表，不新增移动专用表。

移动导入卡片使用：

- `sourceKind`: `mobile_import`
- `sourceId`: `mobile:<fileName>`，用于展示来源文件
- `cardKey`: 根据来源、类型、标题、内容和用途生成稳定键，同一项目重复导入相同记录会更新收藏快照
- `kind`: `opening`、`relationship`、`conflict`、`reversal`、`cliffhanger`、`visual`
- `title`、`pattern`、`applyTo`、`risk`: 进入灵感台的轻量字段

导入不会创建章节、修改正文、触发 AI 任务或写入视频资产。

## 3. JSON 格式

桌面端支持数组根节点，也支持包含 `items`、`cards`、`inspirations` 或 `records` 数组的对象。

```json
{
  "items": [
    {
      "title": "婚礼现场反杀",
      "kind": "opening",
      "pattern": "女主在被退婚时公开关键证据，第一屏先给全场静默。",
      "applyTo": "第一章钩子 / 第一集开场",
      "risk": "证据链不要堆太满"
    }
  ]
}
```

字段别名支持中文标题、类型、模式、内容、灵感、可用于、用途、风险提示等常见写法。

## 4. Markdown 格式

Markdown 可以用标题分隔卡片，也可以用 `---` 分隔多条记录。

```markdown
## 婚礼现场反杀
类型：爆款开局
模式：女主在被退婚时公开关键证据，第一屏先给全场静默。
可用于：第一章钩子 / 第一集开场
风险提示：证据链不要堆太满

---

## 雨夜车窗倒影
类型：视频画面卖点
模式：男主只在车窗倒影中露出半张脸，观众先看到戒指再看到人。
可用于：封面首帧 / 分镜 Prompt
```

导入器会按类型别名归类；无法判断类型时默认进入“冲突机制”。缺少 `applyTo` 时按类型补默认用途。

## 5. 云端后续设计

云同步不进入 LM2-21 实现范围。后续若实现移动端账号、云端草稿箱或跨设备同步，必须先完成：

- 项目数据和移动草稿的边界：移动端默认只同步灵感卡片，不同步正文和本地资产。
- 隐私与加密：用户正文、样本、诊断包和密钥不得进入未声明的云端流程。
- 冲突策略：桌面端项目数据为权威源，移动草稿按导入快照或待处理队列进入。
- 审核与版权：资源市场、公开模板或共享灵感必须有来源声明、侵权投诉和下架流程。
- 失败恢复：断网、重复导入、半成功导入必须可解释、可重试、可回滚。

这些议题由 LM2-22 继续展开。
