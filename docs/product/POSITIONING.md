# 尽意 DramaIP 产品定位

> 状态：当前统一口径
>
> 生效日期：2026-09-21
>
> 最近校准：2026-09-30；补全独立小说成果、分路径指标与实现边界
>
> 品牌主张：**尽作者之意，成万象之作**

本文是尽意 DramaIP 面向产品、设计、研发、文档、官网和发布材料的定位来源。历史路线、发布记录和实现审计可以保留当时事实，但必须注明历史语境，不得继续把旧口径作为当前市场定位。

## 定位层级

### 长期愿景

> 成为创作者拥有的本地优先 IP 操作系统。

尽意长期保存和发展作品的作者意图、权威正文、人物、世界、事件、因果、版本、来源、权利与生产资产，使同一个故事可以延展为小说、短剧、漫剧、分镜、声音和影像，而不被单一模型或平台锁定。

### 当前市场定位

> 面向 AI 短剧与漫剧的本地优先 AI 编剧与 IP 改编工作台。

### 一句话说明

> 尽意 DramaIP 面向原创作者和小型内容团队，帮助持续创作小说与故事母本，或把创意、已有小说、大纲和剧本推进为分集剧本、分镜与交付包；以作者意图、叙事质量和连续性为主线，作者始终掌握原稿、版本、来源和最终采用权。

### 用户价值表达

首页和市场材料优先表达结果，而不是技术范围。改编场景使用：

> **从小说到分集剧本，让故事走向短剧。**

小说创作场景使用：

> **把故事写下去，让人物与世界前后一致。**

补充说明：

> 从故事开发、长篇一致性、分集改编到分镜交付，AI 负责生产和检查，用户决定方向与最终采用；作品和创作记录默认保存在本地。小说可以独立完成与投稿，不必改编或生成视频。

本地优先描述数据与权威内容的归属，不等于模型推理离线运行。对外描述制作可行性时必须说明检查和验证范围，不承诺“必然能拍”或自动达到发行标准。

## 首要用户

当前首要用户是：

- 希望持续创作原创小说、维护长篇设定，或将故事、小说、大纲、剧本改编为 AI 短剧或漫剧的个人作者；
- 需要稳定生产分集剧本、角色设定和分镜交付物的 1–10 人内容工作室。

编剧、导演或制片人是重要的专业使用者，重点在媒体投入前验证故事、改编与首集试制；首轮产品验证仍优先原创作者和小型内容工作室。

当前不以通用网文社区、大众视频剪辑、单镜头视频生成、真人剧组统筹、内容发行或投流平台为首要市场。

## 产品核心

产品围绕“故事/IP 的持续开发与权威内容资产”组织，小说写作不是唯一中心，而是不可弱化的上游核心之一：

```text
总核心：故事/IP 的持续开发与权威内容资产
        │
        ├── 上游核心：小说与故事母本创作
        ├── 转化核心：短剧/漫剧分集改编与剧本开发
        ├── 贯穿核心：作者意图、叙事质量、连续性、版本与来源
        └── 生产出口：分镜、角色/场景资产、Prompt、媒体试制与交付
```

对应原则：

- 小说写作是完整的一等能力，负责建立和发展故事母本，也能独立形成章节、完整稿件和投稿成果；不把它降为改编输入，也不把整个产品收窄为通用 AI 小说软件；
- 小说按作者选择的类型、文风、视角和表达目标检查，不默认强制短剧化、爽点或集尾反转；只有用户选择改编目标时才引入相应制作约束；
- 剧本改编负责把故事重构为可观看、可制作的分集叙事，是当前商业转化核心；
- 连续性、作者控制、版本和来源贯穿所有阶段，是长期产品壁垒；
- 分镜和媒体能力用于验证、试制和交付，不与基础视频模型厂商竞争模型数量、单镜头速度或算力价格。

## 三种进入路径

用户不必先写小说，主流程必须支持从不同成熟度开始：

1. **从创意开始**：创意 → 作者意图与人物/世界 → 小说创作，或直接进入剧本开发；
2. **从已有小说或大纲开始**：导入与来源确认 → 继续写作与整理，或选择改编诊断 → 改编策略 → 分集剧本；
3. **从已有剧本开始**：导入 → 连续性与制作检查 → 分镜与交付。

首页可以展示这三个入口。面向改编市场的英雄流程与演示目标为：

> 导入小说或大纲 → 改编诊断 → 整季分集方案 → 首集剧本 → 首集分镜试制包。

小说作者的独立闭环为“创意或已有稿件 → 人物/大纲与上下文 → 本章生成/修订 → 审阅采用 → 连续性记忆 → 下一章或稿件导出”。下一步按用户目标推荐，不能以未进入改编、分镜或媒体阶段判定小说项目未完成。

## 产品边界

| 领域 | 当前策略 |
| --- | --- |
| 故事、小说与 IP 研发 | 深度自建，维护作者意图与权威内容 |
| 分集改编、剧本与叙事质量 | 深度自建，是当前主战场 |
| 连续性、版本、来源、权利与影响 | 深度自建，形成可信创作资产 |
| 分镜、角色/场景资产与专业交付 | 自建结构和工作流，形成可交换的生产包 |
| 图片、TTS 与视频生成 | Provider-neutral、BYOK、显式授权和成本预检 |
| 云端能力 | 可选灵感、协作、审片、账号与运营，不接管本地权威正文 |
| IP 市场、发行与投流 | 不是当前核心，优先通过标准交付和合作连接 |

因此，视频模型是可替换的生产供应商；尽意保存的是不可替换的故事、决定和生产谱系。

## 交互与信任原则

- AI 与系统负责规划、生成、检查、修订和重复整理；用户负责目标、约束、反馈、关键取舍和最终采用。
- 已有正式内容不得被模型静默覆盖。高影响变更必须经过预览、差异、确认、版本或快照。
- 已采用事实、规则分析、模型推断和生成候选必须明确区分。
- 上游内容变化后只重做受影响的下游产物，并保留原因、范围、模型、成本和采用记录。
- 私人正文、语料、创意指纹、凭据和母版不因使用可选云能力而自动同步或用于平台训练。
- 不使用“一键爆款”“爆款预测”“全自动成片”等不可验证承诺。

## 对外交付物

产品价值通过可采用、可制作、可交换的结果体现，重点包括：

- 故事或小说母本、人物与世界设定；
- 原著改编诊断、整季改编策略和分集大纲；
- 单集标准剧本、场景、对白和叙事检查报告；
- 角色、场景、道具、声音和视觉设定；
- 分镜表、镜头 Prompt、字幕、媒体清单和试制素材；
- 小说投稿包、短剧提案包、分集交付包、项目包和受支持的 NLE 交换文件；
- 来源、权利、模型、版本、成本、采用与审片记录。

## 竞争口径

尽意不以“接入模型最多”“生成镜头最快”“算力最便宜”作为核心承诺。差异化集中在：

1. 从创意或长篇作品开始，而不是只接收完成剧本；
2. 长期维护人物认知、关系、事件、伏笔、因果和作者意图；
3. 所有 AI 结果可比较、可拒绝、可采用、可恢复、可追溯；
4. 在消耗媒体生成费用前完成改编、质量和制作风险验证；
5. 以本地权威项目和开放交付包连接不同模型、团队和下游工具。

## 成功指标

北极星方向是“用户正式采用并交付的有效创作成果”，按工作流分别衡量，不把不同单位强行相加：

- 小说创作：每周正式采用的章节、稿件导出/投稿包完成数，以及下一章继续率；
- 改编剧本：每周正式采用并导出的分集剧本或首集试制包数量，以及第二集继续率。

采用、导出、投稿包完成是不同事件，分别记录；重复导出同一正式版本不重复计为新成果。辅助指标包括首次可采用结果时间、首稿采用率、局部修订次数、章节/分集连续性错误、人工补录量、可采用内容成本和交付包导出率。生成次数、按钮点击和总 token 消耗不能单独代表产品价值。

## 文档使用规则

- 品牌主张统一使用“尽作者之意，成万象之作”。
- 当前产品定位统一使用“面向 AI 短剧与漫剧的本地优先 AI 编剧与 IP 改编工作台”。
- 长期愿景可以使用“创作者拥有的本地优先 IP 操作系统”，但不得将未实现路线描述为当前能力。
- 小说创作写作“重要的上游核心之一、可独立完成的一等能力”，不得描述为全部产品，也不得降为可有可无的输入工具。
- 历史文档保留历史事实时，应在开头链接本文并说明旧定位不再作为当前口径。
- 技术规范保留契约、所有权和版本语义；法律/第三方声明、生成文件、供应商代码和测试素材不做营销化改写。
