# 新旧功能迁移矩阵

本文件以 `legacy/` 中恢复的 Git 基线 `34f4bea` 为唯一功能基线。迁移允许调整实现和界面位置，但每一个旧能力必须具备新的：

1. 中文用户入口；
2. `packages/schema` 中的权威契约；
3. 仅由 DramaIP HTTP Client 调用的 `/api/v1` 接口；
4. Server/数据库实现；
5. 自动化测试或端到端验收场景。

状态含义：`未开始` 表示只有通用资源占位或完全没有实现；`部分完成` 表示已有可用入口但尚未覆盖旧版语义；`完成` 必须同时满足上述五项并有验证证据。

## 页面与工作区验收

legacy 的 26 个页面及 22 个专业创作区块均需有新版中文入口。新版不复用旧 IPC 或旧 Zustand 数据获取逻辑；功能复刻后，在对应行补充 HTTP 路由、界面路由、测试位置和验收日期。

当前新版中 `DomainWorkspace` 只用于内部开发诊断，不可作为上表任意一项的“完成”证据。

## 已知基线计数

- 旧版 IPC 调用：400 个唯一调用点。
- 旧版顶层页面：26 个。
- 旧版创作专业区块：22 个。
- 旧版数据库实体：80 余个，定义见 `legacy/packages/db/src/schema.ts`。

## 迁移顺序

1. 项目/创作资料及搜索；
2. 改编、剧本、场景、分镜；
3. 素材、图片、视频、音频、动态分镜、渲染；
4. 质量、合规、本地化、审片、交付、反馈；
5. 服务商、模板、创意工作流、备份、云端；
6. OpenCode、Codex、LangGraph.js 三引擎任务目录与用户主动盲测；
7. 全量契约、端到端和中文文案审计。
